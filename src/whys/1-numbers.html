Numbers inside C++

Why is the biggest int 2 147 483 647?

An int has 32 bits. A bit is one small box that holds 0 or 1.

One bit keeps the sign (plus or minus), so 31 bits are left for the size. The biggest size they can hold is \( 2^{31} - 1 = 2\,147\,483\,647 \).

The negative side reaches one number further, \( -2\,147\,483\,648 \), because zero takes one place on the other side. 32 bits give \( 2^{32} \) patterns: half for the negatives, half for zero and the positives.

Past the end, C++ calls it "undefined behaviour": anything may happen.

What this means for you: if a value can pass about \( 2 \cdot 10^9 \), store it in long long.

Why does long long stop near \( 9 \cdot 10^{18} \)?

A long long has 64 bits. One is the sign, so 63 are left for the size.

The biggest value is \( 2^{63} - 1 = 9\,223\,372\,036\,854\,775\,807 \), about \( 9.2 \cdot 10^{18} \).

A quick way to guess it: \( 2^{10} = 1024 \), about \( 10^3 \). So \( 2^{63} = 2^3 \cdot (2^{10})^6 \approx 8 \cdot 10^{18} \). The true value is a bit bigger, because 1024 is a bit bigger than 1000.

The product of two numbers up to \( 10^9 \) fits. Two numbers up to \( 10^{10} \) do not.

What this means for you: \( 10^{18} \) fits, \( 10^{19} \) does not. Above that, you need a remainder (modulo) or another idea.

Why write long long and not plain long?

C++ promises only that a long has at least 32 bits.

On 64-bit Linux, a long has 64 bits. On Windows, it has 32 bits, the same as an int.

Codeforces runs your code on Windows. So there a long stops at 2 147 483 647. Your code can pass on your Linux computer and fail on the judge.

A long long has 64 bits on both systems.

What this means for you: always write long long, never long.

Why does v.size() - 1 explode?

An unsigned number has no sign bit, so a 32-bit one goes from 0 to 4 294 967 295.

It exists for things that are never negative, like sizes. v.size() returns one.

An unsigned number cannot go below zero. It wraps around to its biggest value. For an empty vector, v.size() - 1 is 18 446 744 073 709 551 615 on a 64-bit compiler.

So a loop i < v.size() - 1 on an empty vector runs almost forever. It reads outside the array.

What this means for you: turn the size into an int first: (int)v.size() - 1 is \( -1 \) for an empty vector.

Why does \( n! \) overflow so fast?

\( n! \) ("n factorial") is \( 1 \cdot 2 \cdot 3 \cdot \dots \cdot n \). Each step multiplies by a bigger number than the step before.

Why does 7 / 2 give 3?

An int holds only whole numbers. The true answer 3.5 has no place to go.

So C++ drops the fraction. It moves toward zero. 7 / 2 is 3, and -7 / 2 is \( -3 \), not \( -4 \).

If one side is a double, you get the fraction: 7.0 / 2 is 3.5.

To round up with positive numbers, write (a + b - 1) / b. For \( a = 7, b = 2 \): \( 8 / 2 = 4 \).

What this means for you: integer division is exact and fast. Use it, but remember that it rounds toward zero.

Why is -7 % 3 equal to \( -1 \)?

C++ keeps one rule for every a and b: (a / b) * b + a % b == a.

Integer division moves toward zero, so -7 / 3 is \( -2 \), not \( -3 \). Then the rule forces the rest: \( -7 - (-2) \cdot 3 = -1 \).

On a clock with 3 hours, \( -7 \) lands on 2, not on \( -1 \). Math wants 2.

The fix: add m, then take the remainder again.

\[ ((-7 \bmod 3) + 3) \bmod 3 = (-1 + 3) \bmod 3 = 2 \]

What this means for you: when a can be negative, write ((a % m) + m) % m.

Why is 0.1 + 0.2 not 0.3?

A double stores a number in binary: only 0s and 1s.

In binary, 0.1 never ends: 0.000110011001100… It is like 1/3 = 0.333… in decimal. So the computer cuts it and stores a number very close to 0.1.

With 17 digits, 0.1 + 0.2 prints 0.30000000000000004. Plain cout prints only 6 digits, so you see 0.3.

But 0.1 + 0.2 == 0.3 is false. This is why contests prefer whole numbers: they are exact.

What this means for you: use integers when you can. Never compare two double values with ==.

Why is 1e9 exact, but 1e18 + 1 is not?

In C++, 1e9 means \( 1 \cdot 10^9 \), and it is a double.

A double keeps 53 bits of digits. So every whole number up to \( 2^{53} = 9\,007\,199\,254\,740\,992 \) is stored exactly.

\( 10^9 \) is far below that, so int x = 1e9; is safe.

Near \( 10^{18} \), a double can only hold numbers that are 128 apart. So 1e18 + 1 rounds back to \( 10^{18} \). The 1 is lost.

What this means for you: long long big = 1e18; is fine, but never do math with big whole numbers in double.

Why not use pow for whole numbers?

pow works with double, not with whole numbers.

A double keeps only about 15–16 correct digits. A big power has more.

Example: \( 3^{39} = 4\,052\,555\,153\,018\,976\,267 \). But (long long)pow(3, 39) gives 4 052 555 153 018 976 256. The last digits are wrong.

A loop that multiplies long long values gives the exact answer.

What this means for you: for whole-number powers, multiply in a loop. Keep pow for real numbers.

Why is a char a number?

Memory can hold only numbers. So a letter is stored as a number too.

The ASCII table, a US standard from the 1960s, says which number is which letter: 'A' = 65, 'a' = 97, '0' = 48.

The letters come in order, and the digits too. That gives handy tricks:

  • 'c' - 'a' is 2: the place of the letter in the alphabet.
  • '7' - '0' is 7: the digit as a number.
  • 'a' - 'A' is 32: the gap between small and capital letters.

You do not need to remember the numbers. Write the letter itself in quotes.

What this means for you: s[i] - 'a' turns a small letter into 0 … 25, a perfect array index.

Why do computers use binary?

A computer is made of tiny electric switches. A switch is on or off.

Two states are easy to tell apart, even with noise. Ten levels would be much harder. So every number is written with only 0 and 1.

This is why powers of two are everywhere: \( 2^{31} \), 1024, 256 MB.

What this means for you: when a limit looks strange, check if it is near a power of two.

Why XOR?

XOR means "exclusive or": one or the other, but not both.

For each bit, the result is 1 if the two bits differ, and 0 if they are equal. 5 ^ 3 is 6: 101 and 011 give 110.

In C++, ^ is XOR. It is not a power: 5 ^ 3 is not 125.

Two facts make XOR useful: \( x \) XOR \( x = 0 \), and \( x \) XOR \( 0 = x \). So a value that appears twice cancels itself.

What this means for you: XOR all numbers of a list where each value appears twice except one: what stays is that one.

\( 2^{10} = 1024 \). That is almost 1000.

Why does memset work only with 0 and \( -1 \)?

memset fills memory byte by byte. It does not know about int.

An int is 4 bytes. So memset(a, 1, sizeof a) puts the byte 1 four times into each int.

The result is not 1. It is 16 843 009.

With 0, all bits are 0, which is the int 0. With \( -1 \), all bits are 1, which is the int \( -1 \).

What this means for you: use memset only with 0 or \( -1 \). For any other value, use a loop or fill.

Why do indexes start at 0?

In C and C++, a[i] means: start at the beginning of the array and move i places. The first element is 0 places away, so it is a[0].

In 1982, Edsger Dijkstra wrote a short note called "Why numbering should start at zero". One of his reasons: with \( 0 \le i < n \), the number of elements is exactly \( n \).

What this means for you: loop with i = 0 while i < n. The last element is a[n - 1].

Why is a global array zero, and a local one garbage?

Global variables live in a memory area that C++ fills with zeros before main starts. The language promises this.

Local variables live on the "stack". Other functions used that memory a moment ago.

C++ does not clean it, because cleaning takes time. So a local variable without a start value holds whatever was there.

Reading it is undefined behaviour. It may look like 0 on your computer and be different on the judge.

What this means for you: give every local variable a start value: int sum = 0;, int a[100] = {};.
