Add the numbers once and save every running sum. After that, the sum of any part of the array is one subtraction.

Before this lesson

  • You can fill and read an array in a loop → Arrays and strings
  • You know when sums need long long → int or long long?
  • You can count the steps of a loop → Limits → speed

Spot it

  • Many queries: "what is the sum from position \( l \) to position \( r \)?"
  • "How many good positions are between \( l \) and \( r \)?" Put 1 on good positions and 0 on the others. Now it is a sum.
  • The array does not change between the queries.
  • \( n \) and the number of queries are both up to \( 2 \cdot 10^5 \). A loop for every query is too slow.

Three ways to understand it

1 · Story — the bank balance

On days 1 to 5 you get 3, 1, 4, 1 and 5 dollars. The bank writes your balance after each day: 3, 4, 8, 9, 14. This is a running sum.

How much did you get on days 2 to 4? Do not add the three days again. Take the balance after day 4, 9, minus the balance after day 1, 3. That is 6.

2 · Picture — one row more: pre

On this page, positions count from 1, as in the story. The box pre[i] is the sum a[1] + … + a[i]. And pre[0] = 0: the sum of nothing is 0.

One query. The sum of a[2..4] is \( 1 + 4 + 1 = 6 \). Take everything up to r, then remove everything before l.

\[ \text{sum of } a_l \dots a_r = pre_r - pre_{l-1} \]

A chart of pre shows the same thing. The sum of a[2..4] is how much the line climbs from \( i = 1 \) to \( i = 4 \).

3 · Code — build once, answer each query in one step


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, q;
    cin >> n >> q;
    vector<long long> a(n + 1), pre(n + 1, 0);   // positions 1..n, sums can be big
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
        pre[i] = pre[i - 1] + a[i];              // pre[i] = a[1] + ... + a[i]
    }
    while (q--) {
        int l, r;
        cin >> l >> r;                           // positions from 1, as in the input
        cout << pre[r] - pre[l - 1] << "\n";     // sum of a[l..r]
    }
}

One rule for every problem. Positions from 1, pre[0] = 0, answer pre[r] - pre[l - 1]. Most inputs count from 1 too, so you never convert.

Change it to fit

The problem changes: "add \( v \) to every element from \( l \) to \( r \)", many times. Then print the array. You change: the direction of the idea. Do not touch every element of the range. Write only two marks: "the change starts here" at l, and "the change stops here" at r + 1. The marks live in a difference array d. At the end, one running sum of d gives the array.


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, q;
    cin >> n >> q;                               // the array starts with n zeros
    vector<long long> d(n + 2, 0);               // positions 1..n, plus d[n + 1]
    while (q--) {
        int l, r;
        long long v;
        cin >> l >> r >> v;                      // add v to a[l..r], positions from 1
        d[l] += v;                               // the change starts at l
        d[r + 1] -= v;                           // the change stops after r
    }
    long long cur = 0;
    for (int i = 1; i <= n; i++) {
        cur += d[i];                             // running sum of d
        cout << cur << " ";                      // this is a[i]
    }
    cout << "\n";
}

Three smaller changes. Each changes one line of the build loop.

  • Count, not sum: for example, the even numbers. cnt[i] = cnt[i - 1] + (a[i] % 2 == 0 ? 1 : 0). The count in [l, r] is cnt[r] - cnt[l - 1].
  • Biggest so far: mx[i] = max(mx[i - 1], a[i]). This gives the max of a[1..i] only. A max cannot be subtracted, so it does not work for any [l, r].
  • A grid: the sum of the rectangle from \( (1, 1) \) to \( (i, j) \) is \( P_{i,j} = a_{i,j} + P_{i-1,j} + P_{i,j-1} - P_{i-1,j-1} \).

Solve one together

Problem. A string \( s \) of '.' and '#' has length \( n \). There are \( m \) queries. Each gives \( l < r \), positions from 1. Count the positions \( i \) with \( l \le i < r \) where \( s_i = s_{i+1} \). Limits: \( 2 \le n \le 10^5 \) and \( 1 \le m \le 10^5 \).

  1. What is asked? For each query: how many neighbours inside \( [l, r] \) are equal.
  2. A small example by hand. Take s = #..###. Mark position \( i \) with 1 when \( s_i = s_{i+1} \).
    i0123456
    s[i]#..###
    good[i]01011
    pre[i]001123

    Query \( l = 2, r = 5 \): positions 2, 3, 4 have good 1, 0, 1. The answer is 2.

  3. The idea. A count is a sum of 1s and 0s. So build pre on the row good. The positions go from \( l \) to \( r - 1 \). So the answer is pre[r - 1] - pre[l - 1]. Check: pre[4] - pre[1] = 2 - 0 = 2.
  4. Why is it fast enough? Building costs \( n \) steps. Each query costs 1 step. Total \( 10^5 + 10^5 \) steps. A loop per query would cost up to \( 10^5 \cdot 10^5 = 10^{10} \).

#include <bits/stdc++.h>
using namespace std;

int main() {
    string s;
    cin >> s;
    int n = s.size();
    vector<int> pre(n + 1, 0);                   // pre[i] = good[1] + ... + good[i]
    for (int i = 1; i < n; i++) {
        int good = (s[i - 1] == s[i]) ? 1 : 0;   // position i matches position i + 1
        pre[i] = pre[i - 1] + good;              // (the string itself counts from 0)
    }
    int m;
    cin >> m;
    while (m--) {
        int l, r;
        cin >> l >> r;
        cout << pre[r - 1] - pre[l - 1] << "\n";
    }
}

Speed: \( O(n) \) to build, then \( O(1) \) per query. Difference array: \( O(1) \) per change, \( O(n) \) once at the end.

Wrong ideas people get

  • You may think: One loop from l to r per query is not slow.

    The truth: There are many queries. \( 2 \cdot 10^5 \) queries of \( 2 \cdot 10^5 \) steps make \( 4 \cdot 10^{10} \) steps.

  • You may think: The sum of a[l..r] is pre[r] - pre[l].

    The truth: That drops a[l]. The right one is pre[r] - pre[l - 1]. Check with the picture: pre[4] - pre[2] is 5, not 6.

  • You may think: After one element changes, pre is still right.

    The truth: Every box after that element is now wrong. Building again costs \( n \) steps each time.

Common mistakes

  • The sums in an int. \( 2 \cdot 10^5 \) numbers of \( 10^9 \) give \( 2 \cdot 10^{14} \). Use long long.
  • Mixing positions from 0 and from 1. Keep this page's rule: positions from 1, pre[0] = 0.
  • The difference array with only \( n + 1 \) boxes. A change that ends at \( r = n \) writes d[n + 1]. Make \( n + 2 \) boxes.

Not now

  • The array changes between queries. That needs a Fenwick tree or a segment tree. Not needed below 1600: After 1600.
  • The max or min of any range \( [l, r] \) without a loop (a "sparse table"): After 1600.
  • Prefix XOR. The same trick with XOR instead of plus: Bits.

Check yourself

  1. The array is a = 2 7 1 8, positions from 1. What are pre[0] to pre[4]?
    Answer

    0, 2, 9, 10, 18. Each box is the box before it plus one element.

  2. With the same pre, what is the sum of a[2..3]?
    Answer

    pre[3] - pre[1] \( = 10 - 2 = 8 \). Check: \( 7 + 1 = 8 \).

  3. You have 4 zeros and add 5 to positions 2 to 3. Which two boxes of d change?
    Answer

    d[2] += 5 and d[4] -= 5. The running sum then gives 0 5 5 0.
