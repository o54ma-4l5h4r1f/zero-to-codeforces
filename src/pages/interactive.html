Your program talks with the judge. You print a question, the judge answers, and you use the answer to choose the next question.

Optional at this level. Interactive problems are not needed below 1600. Read this when you meet one. Skipping it now will not block the lessons after it.

Before this lesson

  • You can write the binary search loop with lo and hi → Binary search

Spot it

  • The statement says "This is an interactive problem".
  • Something is hidden: a number, an array, a position. You do not get it in the input.
  • You ask questions in a fixed format, like ? x, and print the answer like ! x.
  • There is a limit: "at most 30 queries".

Three ways to understand it

1 · Story — the guessing game with a real person

Remember the guessing game from Binary search. Now your friend really sits in front of you. You say a number. You wait. Your friend answers. Only then you say the next number.

One danger: you write your question on paper but keep the paper in your pocket. Your friend waits for you, and you wait for your friend, for ever. In C++ the pocket is the output buffer. To flush means to give the paper to your friend now.

2 · Picture — one dialogue

The judge hides a number from 1 to 16 (here: 11). You print ? q. The judge answers 1 if the hidden number is at least q, and 0 if it is smaller.

Count the questions before you code, and compare with the limit. For a range of size n you need \( \lceil \log_2 n \rceil \) questions. Here \( \lceil x \rceil \) means "round up". For 100 numbers: \( 2^6 = 64 \) is too small and \( 2^7 = 128 \) is enough, so 7 questions.

3 · Code — one function that asks

Put the dialogue in one function. Then the rest is the binary search you know.


int ask(int q) {
    cout << "? " << q << endl;     // endl = new line + flush
    int reply;
    cin >> reply;                    // wait for the judge
    if (reply == -1) exit(0);        // we broke a rule: stop at once
    return reply;
}

Flush. Write endl after every line you print here. This is the one place where endl is better than "\n". Keep the two fast-input lines of your template. The endl still flushes with them.

Test it at home: you are the judge. Write a hidden number on paper. Run the program. When it prints ? 9, type the true reply and press Enter. Count the questions, and check that the final answer is your number. Try the smallest and the biggest number too.

Change it to fit

The DEFAULT is the program in "Solve one together". Most problems change only ask or one line.

  • Another reply format. The judge answers with text, like < or >=. Change only the reading inside ask: 
    
string s;
cin >> s;
return s == ">=" ? 1 : 0;           // was: cin >> reply; ... return reply;
  • Find a position, not a value. A hidden row of 0s and then 1s, positions 1 to n, with at least one 1. ? i gives the value at position i. Find the first 1. It is the first "yes", as in the binary search lesson. 
    
int lo = 0, hi = n;                  // position 0: a "no"; position n: a "yes"
while (hi - lo > 1) {
    int mid = lo + (hi - lo) / 2;
    if (ask(mid) == 1) hi = mid; else lo = mid;
}
cout << "! " << hi << endl;
  • A limit on the questions. First compute \( \lceil \log_2 n \rceil \). If the limit is smaller, binary search alone is not enough. You need another idea. For \( n = 10^9 \): \( 2^{30} \approx 1.07 \cdot 10^9 \), so 30 questions.

Solve one together

Problem. The judge hides a number x from 1 to n. First you read n. You may print ? q. The judge answers 1 if \( x \ge q \), else 0. Print ! x at the end. You may ask at most 30 questions. Limits: \( 1 \le n \le 10^9 \).

  1. What is asked? Find x with few questions. The answers are 1 1 1 … for small q, then 0 0 0 …. That is a binary search.
  2. A small example by hand. Take \( n = 8 \) and \( x = 3 \).
    you printjudge answersstill possible
    ? 501 … 4

    ! 3–finished
  3. The idea. lo = 1 is surely a "1", because \( x \ge 1 \). hi = n + 1 is surely a "0". Ask about the middle and move lo or hi until they are neighbours. The answer is lo.
  4. Count the questions. \( 2^{30} \approx 1.07 \cdot 10^9 \), which is at least \( 10^9 \). So \( \lceil \log_2 10^9 \rceil = 30 \) questions are enough. The time is tiny.

#include <bits/stdc++.h>
using namespace std;

int ask(int q) {
    cout << "? " << q << endl;            // endl = new line + flush
    int reply;
    cin >> reply;                           // wait for the judge
    if (reply == -1) exit(0);               // we broke a rule: stop at once
    return reply;
}

int main() {
    int n;
    cin >> n;
    int lo = 1;                             // x >= 1 is true for sure
    int hi = n + 1;                         // x >= n + 1 is false for sure
    while (hi - lo > 1) {
        int mid = lo + (hi - lo) / 2;
        if (ask(mid) == 1) lo = mid;        // x >= mid
        else               hi = mid;        // x < mid
    }
    cout << "! " << lo << endl;             // the final answer, also with flush
}

Speed: the time is almost never the problem. The real limit is the number of questions: \( \lceil \log_2 n \rceil \) for a range of size n.

Wrong ideas people get

  • You may think: The samples in the statement are a normal input file.

    The truth: They show one dialogue only. Your program must work for any hidden value.

  • You may think: Writing "\n" is enough. The flush does not matter.

    The truth: Without a flush the question stays in your pocket. The verdict is "Idleness limit exceeded". Use endl.

  • You may think: One extra question is fine if the final answer is right.

    The truth: One question over the limit gives "Wrong answer", even with the right final answer. Count them before you code.

Common mistakes

  • Wrong format: ?9 without the space, or no ! before the answer. Copy the format from the statement.
  • Many test cases: after ! x some problems send one more reply to read. Check the statement.
  • Printing the next question before you read the reply to the last one.

Not now

  • Interactive problems that are not a binary search (clever questions, a judge that changes x while you ask). These are mostly above 1600: After 1600.

Check yourself

  1. The hidden number is from 1 to 1000. The limit is 10 questions. Is binary search enough?
    Answer

    Yes. \( 2^{10} = 1024 \), which is at least 1000. So \( \lceil \log_2 1000 \rceil = 10 \).

  2. Your program is correct, but the verdict is "Idleness limit exceeded". What is the likely reason?
    Answer

    No flush. The question stayed in the buffer, so the judge never saw it. Use endl.

  3. How do you test an interactive program at home, with no judge?
    Answer

    Be the judge. Pick a hidden number, run the program, and type the true reply to each question.
