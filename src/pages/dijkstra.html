The shortest path when every edge has a length. Again and again, fix the closest vertex that is not fixed yet.

Before this lesson

  • You can store a graph and run BFS → Graphs: BFS and DFS
  • You know queue and pair → map, set, stack, queue. priority_queue is new here.
  • You know when a sum needs long long → int or long long?

Spot it

  • Roads have a length, a time or a price: each edge has a weight.
  • The statement asks for the minimum total cost or the shortest path from one vertex.
  • All weights are 0 or more. No edge has a negative number.
  • \( n \) and \( m \) are up to about \( 2 \cdot 10^5 \).

Three ways to understand it

1 · Story — the GPS

A GPS knows the time of every road. At the start it is sure of one thing: your own city is at distance 0.

Then it repeats one step. Take the closest city that is not fixed yet. Its distance is now final: every other way to it passes a city that is farther, and roads are never negative. Then look at its roads. Maybe they give a shorter way to a neighbour.

2 · Picture — from vertex 1

The priority queue holds pairs (distance, vertex). It always gives the pair with the smallest distance.

3 · Code — the distances from one vertex

First, the new tool. A priority_queue is a box of values. Its top() always gives the biggest value inside. With greater it gives the smallest. push(x) adds a value, pop() removes the top. Both cost \( O(\log n) \); top() costs \( O(1) \).


priority_queue<int> big;                                // biggest on top
priority_queue<int, vector<int>, greater<int>> small;  // smallest on top
small.push(5); small.push(2); small.push(8);
cout << small.top();                                     // 2
small.pop();                                             // removes 2; top() is now 5

Dijkstra uses the "smallest on top" form, with pairs {distance, vertex}. Read the long type from the inside out. g is a vector: for every vertex, a list of pairs {neighbour, weight}. When a distance gets better, push a new pair. The old pair stays in the queue, so skip it when it comes out.


const long long INF = 1e18;                      // 10^18: "not reached yet"
vector<vector<pair<int, long long>>> g;          // g[v] = {neighbour, weight}

vector<long long> dijkstra(int start, int n) {
    vector<long long> dist(n + 1, INF);
    // pairs {distance, vertex}; "greater" puts the SMALLEST distance on top
    priority_queue<pair<long long, int>, vector<pair<long long, int>>,
                   greater<pair<long long, int>>> pq;
    dist[start] = 0;
    pq.push({0, start});
    while (!pq.empty()) {
        long long d = pq.top().first;
        int v = pq.top().second;
        pq.pop();
        if (d > dist[v]) continue;               // old pair: v has a better distance now
        for (auto edge : g[v]) {
            int to = edge.first;
            long long w = edge.second;
            if (dist[v] + w < dist[to]) {        // a shorter way to "to", through v
                dist[to] = dist[v] + w;
                pq.push({dist[to], to});
            }
        }
    }
    return dist;
}

Put the distance first in the pair. Pairs are compared by the first number. 1e18 means \( 10^{18} \); it is exact in a long long. In for (auto edge : g[v]), auto lets C++ write the type for you: here edge is a pair<int, long long> (C++ reference, "Variables and types").

Change it to fit

Which tool? Every edge costs the same → BFS: simpler and faster. Weights 0 or more → Dijkstra. Negative weights → Dijkstra is not safe. You need another tool, which you learn later.

Why a negative weight breaks Dijkstra. The roads here are one-way:

Default: the code above, with the edges read in both directions. Then change one thing:

  • One-way roads (directed). Add each edge once, from a to b: 
    
g[a].push_back({b, w});            // and NOT g[b].push_back({a, w})
  • Print the path, not only its length. Remember where each better distance came from. "Solve one together" below does this. 
    
dist[to] = dist[v] + w;
parent[to] = v;                    // the best way to "to" comes from v
  • The distance from every vertex TO a target t, on one-way roads. Turn every road around, then run Dijkstra from t: 
    
g[b].push_back({a, w});            // the road a -> b, stored backwards
vector<long long> distTo = dijkstra(t, n);
  • Several start vertices (for example, many hospitals). Put all of them in the queue at distance 0 before the loop: 
    
for (int s : starts) { dist[s] = 0; pq.push({0, s}); }

Solve one together

Problem. A graph has \( n \) vertices and \( m \) two-way edges with weights. Print a shortest path from vertex 1 to vertex \( n \), as a list of vertices. If there is no path, print -1. Limits: \( 2 \le n \le 10^5 \), \( 0 \le m \le 10^5 \), \( 1 \le w \le 10^6 \). (This is Codeforces 20C "Dijkstra?".)

  1. What is asked? The path itself, not only its length. Weights differ, so we need Dijkstra, not BFS.
  2. A small example by hand. Use the graph of the picture, with \( n = 5 \). The distance to 5 is 11. Where did 11 come from? From vertex 4. Vertex 4 got its 8 from vertex 2. Vertex 2 got its 3 from vertex 3, and 3 got its 1 from vertex 1. Backwards: 5, 4, 2, 3, 1. So the path is 1 3 2 4 5.
  3. The idea. Each time a distance gets better, save where it came from in parent. At the end, walk back from n to 1. Then reverse the list.
  4. Why is it fast enough? Each edge can push one pair, and a queue step costs about \( \log n \approx 17 \). So about \( (n + m) \cdot 17 \approx 3.4 \cdot 10^6 \) steps. Far below \( 10^8 \). A path can be \( 10^5 \) edges of \( 10^6 \): that is \( 10^{11} \), so use long long.

#include <bits/stdc++.h>
using namespace std;

const long long INF = 1e18;                      // "not reached yet"

int main() {
    int n, m;
    cin >> n >> m;
    vector<vector<pair<int, long long>>> g(n + 1);   // {neighbour, weight}
    for (int i = 0; i < m; i++) {
        int a, b;
        long long w;
        cin >> a >> b >> w;
        g[a].push_back({b, w});
        g[b].push_back({a, w});
    }

    vector<long long> dist(n + 1, INF);
    vector<int> parent(n + 1, 0);
    priority_queue<pair<long long, int>, vector<pair<long long, int>>,
                   greater<pair<long long, int>>> pq;
    dist[1] = 0;
    pq.push({0, 1});
    while (!pq.empty()) {
        long long d = pq.top().first;
        int v = pq.top().second;
        pq.pop();
        if (d > dist[v]) continue;               // old pair: skip it
        for (auto edge : g[v]) {
            int to = edge.first;
            long long w = edge.second;
            if (dist[v] + w < dist[to]) {
                dist[to] = dist[v] + w;
                parent[to] = v;                  // we came to "to" from v
                pq.push({dist[to], to});
            }
        }
    }

    if (dist[n] == INF) {                        // n is not reachable
        cout << -1 << "\n";
        return 0;
    }
    vector<int> path;
    for (int v = n; v != 0; v = parent[v]) path.push_back(v);   // n, ..., 1
    reverse(path.begin(), path.end());
    for (int v : path) cout << v << " ";
    cout << "\n";
}

Speed: \( O((n + m) \log n) \). Fine for \( n \) and \( m \) up to a few \( 10^5 \).

Wrong ideas people get

  • You may think: BFS is enough, even with weights.

    The truth: BFS counts edges and ignores weights. It works only if every edge costs the same. See the first small picture.

  • You may think: Dijkstra works with any weights, even negative ones.

    The truth: With a negative weight, a "final" vertex can get shorter later. The idea of Dijkstra breaks.

  • You may think: A distance is final when the vertex first enters the queue.

    The truth: It is final only when the vertex first comes OUT of the queue. Before that it can still get better. In the picture, vertex 2 went from 4 to 3.

Common mistakes

  • dist is int. A path can be \( 10^5 \) edges of \( 10^9 \), that is \( 10^{14} \). Use long long and INF = 1e18.
  • No greater<…>. Then the queue gives the biggest distance first. The answer can still be right, but it is far too slow.
  • You forget if (d > dist[v]) continue;. Then old pairs do the work again: "Time limit exceeded" on big tests.

Not now

  • Negative weights (Bellman-Ford). Rare up to 1600. See After 1600.
  • Weights that are only 0 or 1 (0-1 BFS). Dijkstra already solves it. A faster trick exists: after 1600.
  • Distances between all pairs (Floyd-Warshall), for \( n \le 500 \). See After 1600.

Check yourself

  1. Every road has length 1. Do you use Dijkstra or BFS?
    Answer

    BFS. It gives the same answer, it is simpler, and it is faster: \( O(n + m) \).

  2. Why do we need the line if (d > dist[v]) continue;?
    Answer

    A vertex can have old pairs in the queue, like (4, 2) in the picture. Without the line, each old pair looks at all edges again. On big tests that is too slow.

  3. In the picture, what is the distance from 1 to 4, and what is the path?
    Answer

    8, by 1 → 3 → 2 → 4: \( 1 + 2 + 5 = 8 \). The direct way through 3 costs \( 1 + 8 = 9 \).
