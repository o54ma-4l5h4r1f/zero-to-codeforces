The shortest path when every edge has a length. Always fix the closest vertex that is not fixed yet.

Spot it

  • Roads have a length, a time or a price: each edge has a weight.
  • The statement asks for the minimum total cost or the shortest path from one vertex.
  • All weights are ≥ 0. (No negative numbers on edges.)
  • n and m are up to about 105 or 2 · 105.

Three ways to understand it

1 · Story — the GPS

A GPS knows the time of every road. At the start it knows one thing for sure: your own city is at distance 0.

Then it repeats one step. Take the closest city that is not fixed yet. Its distance is now final, because every other way to it goes through a city that is farther. Look at its roads: maybe they give a shorter way to its neighbours. If yes, write the smaller number.

3 · Code — distance and the path

This program solves the classic problem "Dijkstra?" (20C): print the shortest path from 1 to n, or −1. To print a path, remember for each vertex where you came from: parent[to] = v. At the end walk back from n to 1.


#include <bits/stdc++.h>
using namespace std;

const long long INF = 1e18;                      // "no path yet"

int main() {
    int n, m;
    cin >> n >> m;
    vector<vector<pair<int, long long>>> g(n + 1);   // {neighbour, weight}
    for (int i = 0; i < m; i++) {
        int a, b;
        long long w;
        cin >> a >> b >> w;
        g[a].push_back({b, w});
        g[b].push_back({a, w});
    }

    vector<long long> dist(n + 1, INF);
    vector<int> parent(n + 1, 0);
    // pairs {distance, vertex}; "greater" puts the SMALLEST distance on top
    priority_queue<pair<long long, int>, vector<pair<long long, int>>,
                   greater<pair<long long, int>>> pq;
    dist[1] = 0;
    pq.push({0, 1});
    while (!pq.empty()) {
        long long d = pq.top().first;
        int v = pq.top().second;
        pq.pop();
        if (d > dist[v]) continue;               // old pair: v has a better distance now
        for (auto edge : g[v]) {
            int to = edge.first;
            long long w = edge.second;
            if (dist[v] + w < dist[to]) {        // a shorter way to "to", through v
                dist[to] = dist[v] + w;
                parent[to] = v;
                pq.push({dist[to], to});
            }
        }
    }

    if (dist[n] == INF) {                        // n is not reachable
        cout << -1 << "\n";
        return 0;
    }
    vector<int> path;
    for (int v = n; v != 0; v = parent[v]) path.push_back(v);   // n, ..., 1
    reverse(path.begin(), path.end());
    for (int v : path) cout << v << " ";
    cout << "\n";
}

Why if (d > dist[v]) continue;? When a distance gets better, you push a new pair. The old pair stays in the queue. This line throws old pairs away. Without it the code can be very slow.

Which tool? No weights (every edge costs 1) → BFS, it is simpler and faster. Weights ≥ 0 → Dijkstra. Negative weights → Dijkstra is wrong; you need Bellman-Ford (see After 1600).

Speed: O((n + m) log n). Fine for n and m up to a few 10^5.

Common mistakes

  • dist is int. A path can be 105 edges × 109 = 1014. Use long long and INF = 1018.
  • No greater<…>. Then the queue gives the biggest distance first: the answer can still be right, but it is far too slow.
  • The pair is in the wrong order. Put the distance first: pairs are compared by the first number.
  • You forget the line if (d > dist[v]) continue; → time limit exceeded on big tests.
