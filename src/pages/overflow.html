An int holds only about 2·109. If a value, a sum or a product can be bigger, use long long.

Ask this on every problem

  • What is the biggest number my program can make? Not only the input: also every sum and every product.
  • Bigger than 2·109? Then that variable must be long long.
  • If it does not fit, you get overflow: no error, no warning, only a wrong number.

The types and their limits

Each type has a biggest value. Remember the "about" column.

TypeBiggest valueAboutUse it for
int2 147 483 647 (231 − 1)2·109n, indexes, small values
long long9 223 372 036 854 775 807 (263 − 1)9·1018sums, products, big answers
doublevery big, but not exact15–16 correct digitsonly answers with a decimal point

Negative numbers have the same limits with a minus sign.

Three ways to understand it

1 · Story — the car counter

An old car shows its kilometres with 6 digits. After 999 999 it shows 000 000 again. The car did not break. The counter just has no more room.

An int is the same. After 2 147 483 647 it jumps to a wrong number, often a negative one.

2 · Picture — where the product is made

C++ computes the right side first, then stores it. The type of the right side comes from the numbers in it, not from the variable on the left.

LineRight side is computed asResult for a = b = 100000
long long c = a * b;int × int → int1410065408 (wrong)
long long c = 1LL * a * b;long long × int → long long10000000000 (right)

1LL is the number 1 as a long long. Put it first, so everything after it is computed in long long.

3 · Code — see it yourself

Run this with the input 100000 100000.


#include <bits/stdc++.h>
using namespace std;

int main() {
    int a, b;
    cin >> a >> b;

    long long wrong = a * b;          // int * int: overflows BEFORE it is stored
    long long right = 1LL * a * b;    // long long * int: no overflow

    cout << "wrong: " << wrong << "\n";   // some garbage, often 1410065408
    cout << "right: " << right << "\n";   // 10000000000
}

The same fix for a sum: make the sum variable long long.


long long sum = 0;                        // not int!
for (int i = 0; i < n; i++) sum += a[i];  // a[i] can stay int

long long total = 1LL * n * (n + 1) / 2;  // 1 + 2 + ... + n

Not sure? Make it long long. It is almost never too slow. A wrong answer from overflow costs you much more.

double is not exact

A floating-point number keeps only 15–16 digits. A long long can have 19. So functions that work with double can give a slightly wrong result for big integers.

Do not writeWhyWrite
pow(a, b)returns a double, may be off by 1a loop that multiplies
ceil(a / b) with integersa / b is already rounded down(a + b - 1) / b
sqrt(x) for big xmay be off by 1check r * r and fix r by ±1
a / b == c with doublesnot exacta == b * c with integers

To round up a division of positive integers, stay in integers:


long long n, m, a;                     // problem 1A: n, m, a up to 10^9
cin >> n >> m >> a;
long long rows = (n + a - 1) / a;      // n / a rounded up
long long cols = (m + a - 1) / a;      // m / a rounded up
cout << rows * cols << "\n";           // up to 10^18: needs long long

Common mistakes

  • long long c = a * b; with int a, b. The left side does not help. Write 1LL * a * b.
  • You read a number up to 1012 into an int. Check the limits of the input too.
  • for (int i = 1; i * i <= n; i++) with big n: i * i overflows. Make i a long long.
  • long long also has a limit. 1018 × 10 does not fit. Three numbers up to 109 cannot be multiplied directly.
