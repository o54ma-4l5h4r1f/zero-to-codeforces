An int holds only about \( 2 \cdot 10^9 \). If a value, a sum or a product can be bigger, use long long.

Before this lesson

  • You can read limits like \( a_i \le 10^9 \) → How to read a problem
  • You know the template and its long long sum → Your C++ template

Ask this on every problem

  • What is the biggest number my program can make? Not only the input: also every sum and every product.
  • Bigger than \( 2 \cdot 10^9 \)? Then that variable must be long long.
  • If it does not fit, you get overflow: no error, no warning, only a wrong number.

Where int ends

Each type has a biggest value. Here is int on a line. One tick is one billion, \( 10^9 \).

TypeBiggest valueAboutUse it for
int2 147 483 647, that is \( 2^{31} - 1 \) \( 2 \cdot 10^9 \)\( n \), indexes, small values
long long9 223 372 036 854 775 807, that is \( 2^{63} - 1 \) \( 9 \cdot 10^{18} \)sums, products, big answers
doublevery big, but not exact15–16 correct digitsonly answers with a decimal point

The smallest values are the same with a minus sign. For int it is one more: −2 147 483 648.

See the wrap with real numbers

We ran these lines with int variables on a normal computer.

You compute in intThe true resultThe program printed
2147483647 + 12 147 483 648−2 147 483 648
100000 * 10000010 000 000 0001 410 065 408
46340 * 463412 147 441 9402 147 441 940 (fits)
46341 * 463422 147 534 622−2 147 432 674

The first row goes past the max and comes back at the min. Never trust the wrong number: C++ promises no result at all on overflow. You often see the wrapped value, but not always.

The last two rows show the exact edge for \( n \cdot (n + 1) \): it overflows int from \( n = 46341 \). So n * (n + 1) / 2 breaks already at \( n = 46341 \), long before \( n = 10^5 \).

Three ways to understand it

1 · Story — the car counter

An old car shows its kilometres with 6 digits. After 999 999 it shows 000 000 again. The car did not break. The counter has no more room.

An int is the same. After 2 147 483 647 it jumps to a wrong number, often a negative one.

2 · Picture — where the product is made

C++ computes the right side first, then stores it. The type of the right side comes from the numbers in it, not from the variable on the left.

LineRight side is computed asResult for a = b = 100000
long long c = a * b;int times int gives int1410065408 (wrong)
long long c = 1LL * a * b;long long times int gives long long10000000000 (right)

1LL is the number 1 as a long long. Put it first, so everything after it is computed in long long.

3 · Code — see it yourself

Run this with the input 100000 100000.


#include <bits/stdc++.h>
using namespace std;

int main() {
    int a, b;
    cin >> a >> b;

    long long wrong = a * b;          // int * int: overflows BEFORE it is stored
    long long right = 1LL * a * b;    // long long * int: no overflow

    cout << "wrong: " << wrong << "\n";   // some garbage, often 1410065408
    cout << "right: " << right << "\n";   // 10000000000
}

When to switch to long long: the rules

RuleExample from real limitsBiggest result
A sum of many numbers: the sum is long long.\( n \le 2 \cdot 10^5 \) numbers, each \( \le 10^9 \)\( 2 \cdot 10^{14} \)
A product that can pass \( 2 \cdot 10^9 \): write 1LL * first. Two numbers above 46 340 always do. So does \( 10^9 \cdot 3 \).\( a, b \le 10^5 \)\( 10^{10} \)
A count of pairs: n * (n - 1) / 2 in long long.\( n \le 2 \cdot 10^5 \)about \( 2 \cdot 10^{10} \)
An input above \( 2 \cdot 10^9 \): read it into long long.\( n \le 10^{12} \)\( 10^{12} \)
Two numbers up to \( 10^9 \) added: int is still fine.\( a, b \le 10^9 \)\( 2 \cdot 10^9 \), only just

Not sure? Use long long. It is almost never too slow. A wrong answer costs you much more. The cost of code is in How much does my code cost?

Solve one together

Problem. You get \( n \) numbers. Print the sum of their squares: \( a_1^2 + a_2^2 + \dots + a_n^2 \). Limits: \( 1 \le n \le 2 \cdot 10^5 \) and \( 1 \le a_i \le 10^5 \).

  1. What is asked? Square each number, then add all the squares.
  2. A small example by hand. Numbers 1, 2, 3: \( 1 + 4 + 9 = 14 \). No problem with small numbers.
  3. The biggest numbers. One square can be \( 10^5 \cdot 10^5 = 10^{10} \). That does not fit in int. So we write 1LL * a[i] * a[i], so the square is made in long long.
  4. The biggest sum. \( 2 \cdot 10^5 \) squares of \( 10^{10} \) give \( 2 \cdot 10^{15} \). The sum must be long long. It fits: \( 2 \cdot 10^{15} \) is far below \( 9 \cdot 10^{18} \).
  5. Test the edge. Input 1 and 100000 must print 10000000000. With plain a[i] * a[i] it prints 1410065408.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> a(n);                         // each a[i] fits in int
    for (int i = 0; i < n; i++) cin >> a[i];

    long long sum = 0;                        // up to 2 * 10^15: long long
    for (int i = 0; i < n; i++)
        sum += 1LL * a[i] * a[i];             // the square is made in long long
    cout << sum << "\n";
}

double is not exact

A floating-point number keeps only 15–16 digits. A long long can have 19. So functions that work with double can give a slightly wrong result for big integers.

Do not writeWhyWrite
pow(a, b)returns a double, may be off by 1 a loop that multiplies
ceil(a / b) with integersa / b already dropped the fraction (for positive numbers: rounded down)(a + b - 1) / b
sqrt(x) for big xmay be off by 1check r * r and fix r by 1
a / b == c with doublesnot exacta == b * c with integers

Some answers really have a decimal point, like an average. Then print it like this: cout << fixed << setprecision(9) << x;. Without it, cout may print a number like 1.33333e+06, and the answer is wrong. setprecision(9) prints 9 digits after the point.

To round up a division of positive integers, stay in integers:


long long n, m, a;                     // problem 1A: n, m, a up to 10^9
cin >> n >> m >> a;
long long rows = (n + a - 1) / a;      // n / a rounded up
long long cols = (m + a - 1) / a;      // m / a rounded up
cout << rows * cols << "\n";           // up to 10^18: needs long long

Wrong ideas people get

  • You may think: If the variable on the left is long long, nothing can overflow.

    The truth: The right side is computed first, in int. The overflow happens before it is stored. Write 1LL * a * b.

  • You may think: If there was an overflow, the program would show an error.

    The truth: There is no error and no warning. You get a wrong number in silence, then Wrong answer.

  • You may think: A long long holds any number.

    The truth: Its limit is about \( 9 \cdot 10^{18} \). A product of three numbers up to \( 10^9 \) does not fit.

Common mistakes

  • You read a number up to \( 10^{12} \) into an int. Check the limits of the input too.
  • for (int i = 1; i * i <= n; i++) with n up to \( 10^{12} \): i * i overflows. Make i a long long.
  • You write a * b * 1LL. Here a * b is made first, in int. Put 1LL first.

Not now

  • Answers "modulo \( 10^9 + 7 \)". Some problems have answers far above \( 10^{18} \). They ask for a remainder. You learn this in Mod and fast power.
  • unsigned types and __int128. You do not need them below 1600. long long is the one to use: After 1600.

Check yourself

  1. \( n \le 2 \cdot 10^5 \) numbers, each \( \le 10^9 \). Does their sum fit in an int?
    Answer

    No. The sum can reach \( 2 \cdot 10^{14} \). Make the sum long long.

  2. Both a and b are int and equal 50 000. Is long long c = a * b; right?
    Answer

    No. \( 50000 \cdot 50000 = 2.5 \cdot 10^9 \), above the int max. The product is made in int. Write 1LL * a * b.

  3. From which \( n \) does n * (n + 1) overflow an int?
    Answer

    From \( n = 46341 \). Then the product is 2 147 534 622, above 2 147 483 647.
