List the small cases first, then count with a rule: multiply for "and", add for "or", and use \( C(n, r) \) to choose r things from n.

  • You can try all options with loops → Brute force

  • You can take % MOD after each step and use power → Mod and fast power

Spot it

  • "How many ways…", "count the number of…", and the answer is huge.
  • "Print the answer modulo \( 10^9 + 7 \)" (or 998244353).
  • You choose some items from many, and the order of the chosen items does not matter.
  • You count pairs, subsets, orders, or paths in a grid.

Three ways to understand it

1 · Story — write them all down, then count

"Or" → add. You go to school by one of 3 buses or one of 2 trains. The list is B1, B2, B3, T1, T2. That is \( 3 + 2 = 5 \) ways.

"And" → multiply. You wear one of 3 shirts and one of 2 trousers. The tree in the picture below lists all 6 outfits: \( 3 \cdot 2 = 6 \).

Orders. Three friends A, B, C stand in a line. All orders: ABC, ACB, BAC, BCA, CAB, CBA. That is 6. Now four things A, B, C, D. These orders start with A:

ABCDABDCACBDACDBADBCADCB

Six start with A, six with B, six with C, six with D. So there are \( 4 \cdot 6 = 24 \) orders. There are 4 choices for the first place, then 3, then 2, then 1.

\[ 4! = 4 \cdot 3 \cdot 2 \cdot 1 = 24 \]

This is a factorial. \( n! \) is \( 1 \cdot 2 \cdot \dots \cdot n \), and \( 0! = 1 \).

Choose 2 of 4. A pizza has 2 of 4 toppings: Cheese, Olives, Mushrooms, Tomato. CO is the same pizza as OC. All choices:

COCMCTOMOTMT

That is 6. Why? With order there are \( 4 \cdot 3 = 12 \) pairs. Each choice is counted twice (CO and OC), so divide by 2. We write this count as \( C(n, r) \), read "n choose r". It counts the ways to choose r things from n when order does not matter:

\[ C(n, r) = \frac{n!}{r! \cdot (n - r)!} \]

Check: \( C(4, 2) = \frac{24}{2 \cdot 2} = 6 \).

2 · Picture — a tree of choices, and Pascal's triangle

Now put \( C(n, r) \) in a table: row n, column r. Each cell is the sum of two cells in the row above: the one above it and the one above-left.

The same table in code, for n up to 2000. It needs no division:


// before main:  const int MOD = 1e9 + 7;  long long C[2001][2001];
for (int n = 0; n <= 2000; n++) {
    C[n][0] = C[n][n] = 1;
    for (int r = 1; r < n; r++)
        C[n][r] = (C[n - 1][r - 1] + C[n - 1][r]) % MOD;
}

3 · Code — dividing under mod

For n up to \( 10^6 \) the table is too big. We need the formula with factorials. But the formula divides. Try it with \( C(5, 2) = 10 \) and mod 7. The right answer is \( 10 \bmod 7 = 3 \).

  • \( 5! = 120 \), and \( 120 \bmod 7 = 1 \).
  • \( 2! \cdot 3! = 12 \), and \( 12 \bmod 7 = 5 \).
  • Now 1 / 5 in C++ is 0. We get 0, not 3. Dividing after taking the mod gives a wrong number.

The fix: never divide. Multiply by the modular inverse. The inverse of 5 mod 7 is a number x with \( 5 \cdot x \bmod 7 = 1 \). Here \( x = 3 \), because \( 15 \bmod 7 = 1 \). Now \( 1 \cdot 3 \bmod 7 = 3 \). Correct.

The recipe (Fermat). If p is a prime and a is not a multiple of p, the inverse of a is \( a^{p-2} \bmod p \). Check: \( 5^{5} = 3125 \), and \( 3125 \bmod 7 = 3 \). This is a rule you may use without the proof for now. Both \( 10^9 + 7 \) and 998244353 are primes.


const long long MOD = 1e9 + 7;              // a prime

long long power(long long a, long long b) { // a^b mod MOD, fast
    long long res = 1;
    a %= MOD;
    while (b > 0) {
        if (b % 2 == 1) res = res * a % MOD;
        a = a * a % MOD;
        b /= 2;
    }
    return res;
}

long long inverse(long long a) {            // works only because MOD is prime
    return power(a, MOD - 2);
}

So \( C(n, r) \) = fact[n] * inverse(fact[r] * fact[n-r] % MOD) % MOD. The program in "Solve one together" makes this fast.

Paths in a grid. You walk from the bottom-left corner to the top-right one. You move only right or up. With 3 right moves and 2 up moves, a path is a word like RRURU.


long long paths = C(right + up, up);   // C(5, 2) = 10

Solve one together

Problem. You get \( q \) questions. Each question is two numbers n and r. Print \( C(n, r) \bmod (10^9 + 7) \). Limits: \( 1 \le q \le 10^5 \) and \( 0 \le r \le n \le 10^6 \).

  1. What is asked? \( C(n, r) \) many times, for n up to \( 10^6 \). The table needs \( 10^{12} \) cells: too big. So we use factorials.
  2. A small example by hand. "5 2" → \( \frac{120}{2 \cdot 6} = 10 \). "10 3" → \( \frac{3628800}{6 \cdot 5040} = 120 \). Small numbers can be divided. Big ones are taken mod, so we must multiply by inverses.
  3. The idea. Compute fact[i] \( = i! \bmod p \) once, for every i. Compute invfact[i], the inverse of \( i! \). Only one inverse comes from Fermat. The others come by going back with multiplication. \[ \frac{1}{(i-1)!} = \frac{1}{i!} \cdot i \]

    Then each answer is fact[n] * invfact[r] % MOD * invfact[n - r] % MOD.

  4. Why is it fast enough? The tables take \( 10^6 \) steps each. Fermat takes about 30 steps. Each question takes 2 multiplications. \[ 2 \cdot 10^6 + 2 \cdot 10^5 \text{ steps} \]

    That is far below \( 10^8 \).


#include <bits/stdc++.h>
using namespace std;

const long long MOD = 1e9 + 7;              // a prime
const int MAXN = 1000000;                   // the biggest n you need
long long fact[MAXN + 1], invfact[MAXN + 1];

long long power(long long a, long long b) { // a^b mod MOD, fast
    long long res = 1;
    a %= MOD;
    while (b > 0) {
        if (b % 2 == 1) res = res * a % MOD;
        a = a * a % MOD;
        b /= 2;
    }
    return res;
}

long long C(int n, int r) {                 // ways to choose r from n
    if (r < 0 || r > n) return 0;           // impossible choice: 0 ways
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD;
}

int main() {
    fact[0] = 1;
    for (int i = 1; i <= MAXN; i++) fact[i] = fact[i - 1] * i % MOD;
    invfact[MAXN] = power(fact[MAXN], MOD - 2);          // one inverse by Fermat
    for (int i = MAXN; i >= 1; i--)                      // 1/(i-1)! = 1/i! * i
        invfact[i - 1] = invfact[i] * i % MOD;

    int q;
    cin >> q;
    while (q--) {
        int n, r;
        cin >> n >> r;
        cout << C(n, r) << "\n";            // "5 2" -> 10,  "10 3" -> 120
    }
}

Speed: \( O(\text{MAXN}) \) once for the tables, then \( O(1) \) for each \( C(n, r) \). Pascal's table: \( O(n^2) \).

Wrong ideas people get

  • You may think: I can take the mod first and divide after.

    The truth: That gives a wrong number, as in the example \( C(5, 2) \) mod 7. Multiply by the inverse instead.

  • You may think: \( C(n, r) \) counts AB and BA as two different choices.

    The truth: In \( C(n, r) \) the order does not matter. If order matters, use \( P(n, r) \). Ask "is AB the same as BA?" before you choose.

  • You may think: For a small n like 70, \( C(n, r) \) fits in long long without a mod.

    The truth: \( C(67, 33) \) is already too big for long long. Use the mod, or Pascal's table if the problem has no mod and n is small.

Common mistakes

  • No % MOD after each multiplication. Three numbers below \( 10^9 \) multiplied together overflow long long.
  • No check for r < 0 or r > n. Then you read outside the array.
  • Pairs as n * (n - 1) / 2 in int. For \( n = 2 \cdot 10^5 \) the result is about \( 2 \cdot 10^{10} \): use long long.

Check yourself

  1. In how many ways can you choose 3 students out of 5, if the order does not matter?
    Answer

    \( C(5, 3) = \frac{120}{6 \cdot 2} = 10 \). It is also row 5, column 3 of Pascal's triangle.

  2. You have 4 shirts and 3 hats. You wear one shirt and one hat. How many ways?
    Answer

    "And" → multiply: \( 4 \cdot 3 = 12 \).

  3. What is the inverse of 3 mod 7? Check it with a multiplication.
    Answer

    5, because \( 3 \cdot 5 = 15 \) and \( 15 \bmod 7 = 1 \). Fermat gives the same: \( 3^{5} = 243 \), and \( 243 \bmod 7 = 5 \).
