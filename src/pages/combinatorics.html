Count the ways without listing them. Multiply for "and", add for "or", and use nCr to choose r things from n.

Spot it

  • "How many ways…", "count the number of…", and the answer is huge.
  • "Print the answer modulo 109+7" (or 998244353).
  • You choose some items from many, and the order of the chosen items does not matter.
  • You count pairs: n items give n·(n−1)/2 pairs.

Three ways to understand it

1 · Story — clothes and pizza

Rule of product ("and" → multiply). You have 3 shirts and 2 trousers. You wear one shirt and one pair of trousers: 3 × 2 = 6 ways.

Rule of sum ("or" → add). You go to school by one of 3 buses or one of 2 trains: 3 + 2 = 5 ways.

Factorial. 3 friends stand in a line: 3 choices for the first place, then 2, then 1. So 3 × 2 × 1 = 6 ways. This is 3!. In general n! = 1 × 2 × … × n, and 0! = 1.

nCr. A pizza shop has 4 toppings: Cheese, Olives, Mushrooms, Tomato. You choose 2. Order does not matter (CO is the same pizza as OC). List them: CO, CM, CT, OM, OT, MT → 6 ways.

This number is called C(n, r) or nCr, a combination: C(n, r) = n! / (r! · (n−r)!). Check: C(4, 2) = 24 / (2 · 2) = 6.

2 · Picture — Pascal's triangle

Row n, column r holds C(n, r). Each number is the sum of two numbers in the row above: the one above it and the one above-left.

C(n, r) = C(n−1, r−1) + C(n−1, r). Here C(4, 2) = 3 + 3 = 6.

Why? Look at the last item. Take it: choose r−1 more from the other n−1. Or leave it: choose all r from the other n−1. "Or" → add.

For n up to about 2000, fill this table. No division is needed:


// before main:  const int MOD = 1e9 + 7;  long long C[2001][2001];   (all zeros)
for (int n = 0; n <= 2000; n++) {
    C[n][0] = 1;                                         // choose nothing: 1 way
    for (int r = 1; r <= n; r++)
        C[n][r] = (C[n - 1][r - 1] + C[n - 1][r]) % MOD;
}

3 · Code — nCr mod p for big n

For n up to 105 or 106 the table is too big. Use the formula with factorials. But you cannot divide under mod. You multiply by the modular inverse.

When p is prime, the inverse of a is ap−2 mod p (Fermat). Compute it with fast power from Mod and fast power.

So precompute fact[i] = i! and invfact[i] = inverse of i!. Then C(n, r) = fact[n] · invfact[r] · invfact[n−r].


#include <bits/stdc++.h>
using namespace std;

const int MOD = 1e9 + 7;                    // a prime
const int MAXN = 200000;                    // the biggest n you need
long long fact[MAXN + 1], invfact[MAXN + 1];

long long power(long long a, long long b) { // a^b mod MOD, fast
    long long res = 1;
    a %= MOD;
    while (b > 0) {
        if (b % 2 == 1) res = res * a % MOD;
        a = a * a % MOD;
        b /= 2;
    }
    return res;
}

long long C(int n, int r) {                 // ways to choose r from n
    if (r < 0 || r > n) return 0;           // impossible choice: 0 ways
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD;
}

int main() {
    fact[0] = 1;
    for (int i = 1; i <= MAXN; i++) fact[i] = fact[i - 1] * i % MOD;
    invfact[MAXN] = power(fact[MAXN], MOD - 2);          // one inverse by Fermat
    for (int i = MAXN; i >= 1; i--)                      // 1/(i-1)! = 1/i! * i
        invfact[i - 1] = invfact[i] * i % MOD;

    int q;
    cin >> q;
    while (q--) {
        int n, r;
        cin >> n >> r;
        cout << C(n, r) << "\n";            // "5 2" -> 10,  "10 3" -> 120
    }
}

Three numbers to remember. Pairs from n items: n·(n−1)/2 (this is C(n, 2)). Subsets of n items: 2n (each item is in or out). Orders of n items: n!.

Speed: O(MAXN) once to precompute, then O(1) for each C(n, r). Pascal's table: O(n²).

Common mistakes

  • Dividing under mod: fact[n] / fact[r] % MOD is wrong. Multiply by the inverse.
  • Forgetting % MOD after each multiplication. Three numbers multiplied together overflow long long.
  • No check for r < 0 or r > n. Then you read outside the array.
  • Arrays too small, or n·(n−1)/2 in int. For n = 200 000 the number of pairs is 2·1010: use long long.
