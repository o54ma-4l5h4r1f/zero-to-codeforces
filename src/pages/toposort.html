Some tasks must come before others. Topological sort puts all tasks in one line so that every rule is respected.

Spot it

  • Rules like "a must be done before b": courses with a prerequisite, tasks that depend on other tasks.
  • You must print a correct order, or say that no order exists.
  • The graph is directed (edges are arrows) and you must check if it has a cycle.
  • You want a DP on a directed graph: longest path, number of paths. First you need a good order.

Three ways to understand it

1 · Story — getting dressed

Socks before shoes. Trousers before shoes and before the belt. Shirt before the belt and before the jacket. Belt before the jacket.

What can you put on first? Only a thing with no rule in front of it: socks, trousers or shirt. Put one on. Now cross out its rules. Maybe a new thing is free now. Repeat until you are dressed.

If the rules say "a before b" and also "b before a", then a and b are never free. Then no order exists.

2 · Picture — count the arrows that come in

Draw each rule "a before b" as an arrow a → b.

The in-degree of a vertex = how many arrows point to it = how many things must come before it. A vertex with in-degree 0 is free. Free vertices wait in a queue.

3 · Code — Kahn's algorithm

Input: n tasks, m rules. Each rule is "a b" = a must come before b.


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;
    vector<vector<int>> adj(n + 1);         // adj[a] = all b with an arrow a -> b
    vector<int> indeg(n + 1, 0);            // indeg[b] = arrows that point to b
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        adj[a].push_back(b);
        indeg[b]++;
    }
    queue<int> q;
    for (int v = 1; v <= n; v++)
        if (indeg[v] == 0) q.push(v);       // free at the start
    vector<int> order;
    while (!q.empty()) {
        int v = q.front(); q.pop();
        order.push_back(v);                 // do task v now
        for (int to : adj[v]) {             // remove the arrows that leave v
            indeg[to]--;
            if (indeg[to] == 0) q.push(to); // "to" is free now
        }
    }
    if ((int)order.size() < n) {            // some tasks never became free
        cout << "IMPOSSIBLE\n";             // -> there is a cycle
    } else {
        for (int v : order) cout << v << " ";
        cout << "\n";
    }
}

DP on the order: go through order from left to right. When you reach v, all vertices before v are finished. So best[to] = max(best[to], best[v] + 1) gives the longest path. Need the smallest order in the dictionary? Use a priority_queue<int, vector<int>, greater<int>> in place of the queue, and q.top() in place of q.front().

Speed: O(n + m). Every vertex enters the queue once, every arrow is removed once.

Common mistakes

  • The arrow in the wrong direction. "b needs a" means a → b. Read the statement twice.
  • No cycle check. Always compare order.size() with n before you print.
  • Using it on a graph without directions. Topological sort is only for directed graphs.
  • Thinking the order is unique. Often many orders are correct. If your output differs from the sample, it can still be right.
