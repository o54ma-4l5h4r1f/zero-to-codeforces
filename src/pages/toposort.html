Some tasks must come before others. Topological sort puts all tasks in one line, so that every rule is respected.

Optional at this level. You do not need topological sort below 1600. Read it when a problem needs it. Skipping it now will not block the lessons after it.

Before this lesson

  • You can store a graph in adj and run BFS with a queue → Graphs: BFS and DFS
  • You know priority_queue with greater → map, set, stack, queue
  • You can fill a DP array in a good order → Dynamic programming

Spot it

  • Rules like "a must be done before b": courses with a prerequisite, tasks that depend on other tasks.
  • You must print a correct order, or say that no order exists.
  • The graph is directed (edges are arrows), and you must check if it has a cycle.
  • You want a DP on a directed graph: the longest path, the number of paths. First you need a good order.

Three ways to understand it

1 · Story — getting dressed

Socks before shoes. Trousers before shoes and before the belt. Shirt before the belt and before the jacket. Belt before the jacket.

What can you put on first? Only a thing with no rule in front of it: socks, trousers or shirt. Put one on. Now cross out its rules. Maybe a new thing is free now. Repeat until you are dressed.

If the rules say "a before b" and also "b before a", then a and b are never free. Then no order exists.

2 · Picture — count the arrows that come in

Draw each rule "a before b" as an arrow a → b. Here 1 = socks, 2 = trousers, 3 = shoes, 4 = shirt, 5 = belt, 6 = jacket.

The in-degree of a vertex is the number of arrows that point to it. It counts the things that must come before it. A vertex with in-degree 0 is free, so it goes into the queue. This method is called Kahn's algorithm.

Now a graph with a cycle: 2 → 3 → 4 → 2.

3 · Code — Kahn's algorithm

adj[a] holds every b with an arrow a → b. indeg[b] counts the arrows into b. Vertices are 1 to n.


vector<int> topoOrder(int n, vector<vector<int>>& adj, vector<int> indeg) {
    queue<int> q;
    for (int v = 1; v <= n; v++)
        if (indeg[v] == 0) q.push(v);       // free at the start
    vector<int> order;
    while (!q.empty()) {
        int v = q.front(); q.pop();
        order.push_back(v);                 // do task v now
        for (int to : adj[v]) {             // remove the arrows that leave v
            indeg[to]--;
            if (indeg[to] == 0) q.push(to); // "to" is free now
        }
    }
    return order;                           // fewer than n vertices = a cycle
}

Change it to fit

The plain queue above is the DEFAULT. Use it unless the problem asks for one of these.

  • "Print IMPOSSIBLE if there is a cycle." Some vertices never became free. So the order is shorter than n. 
    
if ((int)order.size() < n) cout << "IMPOSSIBLE\n";
  • "Print the smallest order" (smallest first number, then smallest second…). Always take the smallest free vertex. Use a priority_queue with greater. A priority_queue has no q.front(), so write q.top(). 
    
priority_queue<int, vector<int>, greater<int>> q;   // was: queue<int> q;
int v = q.top(); q.pop();                              // was: q.front()
  • "The longest chain of tasks" (longest path). Go through order from left to right. When you reach v, all vertices before v are finished. best[v] = the most arrows on a path that ends at v. 
    
vector<int> best(n + 1, 0);
for (int v : order)
    for (int to : adj[v]) best[to] = max(best[to], best[v] + 1);

Solve one together

Problem. There are \( n \) courses and \( m \) rules. A rule "a b" means: course a must come before course b. Print an order of all courses, or IMPOSSIBLE if none exists. Limits: \( 1 \le n \le 10^5 \) and \( 1 \le m \le 2 \cdot 10^5 \).

  1. What is asked? One order that respects every rule. Rules "before" are arrows. So this is topological sort, with a cycle check.
  2. A small example by hand. Take \( n = 5 \) and the rules 1 2, 3 1, 4 5. The in-degrees of 1 … 5 are 1, 1, 0, 0, 1.
    takearrows removednow freequeue after
    start–3, 43, 4
    33 → 114, 1
    44 → 551, 5
    11 → 225, 2
    5none–2
    2none–empty

    The order is 3 4 1 5 2. It has 5 courses, so no cycle.

  3. The idea. Read the rules into adj and indeg. Call topoOrder. If the order is shorter than n, print IMPOSSIBLE. Otherwise print the order.
  4. Why is it fast enough? Every vertex enters the queue once. Every arrow is removed once. So the work is about \[ n + m = 3 \cdot 10^5 \text{ steps} \]

    That is far below \( 10^8 \).


#include <bits/stdc++.h>
using namespace std;

vector<int> topoOrder(int n, vector<vector<int>>& adj, vector<int> indeg) {
    queue<int> q;
    for (int v = 1; v <= n; v++)
        if (indeg[v] == 0) q.push(v);
    vector<int> order;
    while (!q.empty()) {
        int v = q.front(); q.pop();
        order.push_back(v);
        for (int to : adj[v]) {
            indeg[to]--;
            if (indeg[to] == 0) q.push(to);
        }
    }
    return order;
}

int main() {
    int n, m;
    cin >> n >> m;
    vector<vector<int>> adj(n + 1);         // adj[a] = all b with an arrow a -> b
    vector<int> indeg(n + 1, 0);            // indeg[b] = arrows that point to b
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;                      // a must come before b
        adj[a].push_back(b);
        indeg[b]++;
    }
    vector<int> order = topoOrder(n, adj, indeg);
    if ((int)order.size() < n) {            // some courses never became free
        cout << "IMPOSSIBLE\n";             // -> there is a cycle
    } else {
        for (int v : order) cout << v << " ";
        cout << "\n";
    }
}

Speed: \( O(n + m) \) for \( n \) vertices and \( m \) arrows. With a priority_queue: \( O(n \log n + m) \).

Wrong ideas people get

  • You may think: There is only one correct order, and my output must match the sample.

    The truth: Often many orders are correct. If your output differs from the sample, it can still be right. Only "print the smallest order" has one answer.

  • You may think: When the queue is empty, all vertices are done.

    The truth: With a cycle the queue empties early. Always compare order.size() with n.

  • You may think: Topological sort works on any graph.

    The truth: Only on directed graphs. And if there is a cycle, no order exists.

Common mistakes

  • The arrow in the wrong direction. "b needs a" means a → b. Read the statement twice.
  • q.front() on a priority_queue. It does not compile: write q.top().
  • Many test cases: adj and indeg are not cleared. Make them new inside the test loop.

Not now

  • Topological sort with DFS. It gives an order too, but it is a second way to do the same thing. Use Kahn's queue. The DFS way is in After 1600.
  • Groups of vertices that all reach each other (strongly connected components). A cycle becomes one vertex. It is rare below 1600: After 1600.

Check yourself

  1. The rules are 3 → 1 and 1 → 2. Write a correct order.
    Answer

    3 1 2. Here it is the only one: 3 must be first and 2 must be last.

  2. The arrows are 1 → 2, 1 → 3 and 2 → 3. What are the in-degrees? Which vertex enters the queue first?
    Answer

    Vertex 1 has 0, vertex 2 has 1, vertex 3 has 2. Only vertex 1 is free at the start.

  3. A graph has 6 vertices. At the end the order has only 4. What does that mean?
    Answer

    There is a cycle. Two vertices never reached in-degree 0, so no correct order exists.
