A graph is points joined by lines. DFS and BFS are two ways to walk over it and visit every point once.

Before this lesson

  • You can write a function that calls itself → Recursion and backtracking
  • You know queue and pair → map, set, stack, queue
  • You can count steps and compare with \( 10^8 \) → Limits → speed

Spot it

  • The statement has cities and roads, friends, or computers and cables: things and links between pairs.
  • "Can you reach B from A?" or "How many groups are there?" → DFS or BFS.
  • "The minimum number of moves" and every move costs the same → BFS.
  • A grid (maze) with walls where you move up, down, left, right. A grid is also a graph.

Three ways to understand it

1 · Story — a maze and a rumour

A graph has vertices (the points) and edges (the lines). Two vertices joined by an edge are neighbours.

DFS is one person in a maze. You walk forward as far as you can. You mark every room you enter. At a dead end you go back one room and try another door.

BFS is a rumour. Today you know it. Tomorrow all your friends know it. The next day their friends know it. It moves level by level, so it reaches each person by the shortest way.

2 · Picture — BFS, then DFS, on the same graph

BFS keeps a queue. Take the front vertex. Every neighbour with no distance yet gets dist + 1 and goes to the back of the queue.

DFS on the same graph. It goes deep first and comes back only at a dead end.

3 · Code — read, DFS, BFS

Store the graph as an adjacency list: g[v] is the list of neighbours of v. The program prints the number of connected components (groups), then the distances from vertex 1.


#include <bits/stdc++.h>
using namespace std;

int n, m;
vector<vector<int>> g;       // g[v] = neighbours of v
vector<bool> visited;

void dfs(int v) {
    visited[v] = true;                    // mark first, then go deeper
    for (int to : g[v])
        if (!visited[to]) dfs(to);
}

vector<int> bfs(int start) {
    vector<int> dist(n + 1, -1);          // -1 = not reached yet
    queue<int> q;
    dist[start] = 0;
    q.push(start);
    while (!q.empty()) {
        int v = q.front();
        q.pop();
        for (int to : g[v]) {
            if (dist[to] != -1) continue; // already seen
            dist[to] = dist[v] + 1;
            q.push(to);
        }
    }
    return dist;
}

int main() {
    cin >> n >> m;                        // n vertices (1..n), m edges
    g.assign(n + 1, vector<int>());
    visited.assign(n + 1, false);
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        g[a].push_back(b);
        g[b].push_back(a);                // the edge works in both directions
    }
    int components = 0;
    for (int v = 1; v <= n; v++)
        if (!visited[v]) {                // a vertex nobody reached: a new group
            components++;
            dfs(v);
        }
    cout << components << "\n";
    vector<int> dist = bfs(1);
    for (int v = 1; v <= n; v++) cout << dist[v] << " ";
    cout << "\n";
}

This is an undirected graph. If the statement says directed (one-way roads), write only g[a].push_back(b).

A DFS on a chain of \( 10^6 \) vertices goes \( 10^6 \) calls deep. On some judges this crashes. If you see a strange runtime error, use BFS.

A grid is also a graph

Each free cell is a vertex. Its neighbours are the 4 cells next to it. In a grid, x is the row and grows down. y is the column and grows to the right.

Do not build g. Use two small arrays for the 4 directions. Inside the BFS loop, for the cell (x, y) you took from the queue:


int dx[4] = {1, -1, 0, 0}, dy[4] = {0, 0, 1, -1};
for (int d = 0; d < 4; d++) {
    int nx = x + dx[d], ny = y + dy[d];
    if (nx < 0 || nx >= n || ny < 0 || ny >= m) continue;      // outside the grid
    if (grid[nx][ny] == '#' || dist[nx][ny] != -1) continue;  // wall, or seen
    dist[nx][ny] = dist[x][y] + 1;
    q.push({nx, ny});                                         // queue<pair<int,int>>
}

Solve one together

Problem. A maze is a grid with \( n \) rows and \( m \) columns. A dot is a free cell and # is a wall. You start in the top-left cell. You want to reach the bottom-right cell. One move goes up, down, left or right to a free cell. Print the smallest number of moves, or -1 if you cannot get there. Limits: \( 1 \le n, m \le 1000 \). Both corner cells are free.

  1. What is asked? The minimum number of moves. Every move costs the same. That is the signal for BFS.
  2. A small example by hand. Take a maze with 4 rows and 5 columns. Write 0 in the start cell. Write 1 in its free neighbours, then 2 in their new neighbours, and so on.
  3. The idea. Run BFS from the start cell. Keep dist[x][y], the number of moves to reach the cell. The value -1 means "not reached yet". So dist is also the visited mark. The answer is dist[n-1][m-1].
  4. Why is it fast enough? The biggest grid has \( 1000 \cdot 1000 = 10^6 \) cells. Each cell enters the queue once and looks at 4 neighbours. \[ 4 \cdot 10^6 \text{ steps} \]

    That is far below \( 10^8 \).


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;
    vector<string> grid(n);
    for (int i = 0; i < n; i++) cin >> grid[i];

    vector<vector<int>> dist(n, vector<int>(m, -1));   // -1 = not reached yet
    queue<pair<int, int>> q;
    dist[0][0] = 0;
    q.push({0, 0});
    int dx[4] = {1, -1, 0, 0}, dy[4] = {0, 0, 1, -1};
    while (!q.empty()) {
        int x = q.front().first, y = q.front().second;
        q.pop();
        for (int d = 0; d < 4; d++) {
            int nx = x + dx[d], ny = y + dy[d];
            if (nx < 0 || nx >= n || ny < 0 || ny >= m) continue;      // outside the grid
            if (grid[nx][ny] == '#' || dist[nx][ny] != -1) continue;  // wall, or seen
            dist[nx][ny] = dist[x][y] + 1;
            q.push({nx, ny});
        }
    }
    cout << dist[n - 1][m - 1] << "\n";              // still -1 if we never reached it
}

Speed: \( O(n + m) \) for both DFS and BFS, with \( n \) vertices and \( m \) edges. A grid: \( O(\text{rows} \cdot \text{columns}) \).

Wrong ideas people get

  • You may think: DFS also gives the shortest path.

    The truth: DFS finds some path, not the shortest one. For the minimum number of moves use BFS.

  • You may think: BFS gives the shortest path in any graph.

    The truth: Only if every edge costs the same. If the roads have different lengths, the BFS answer is wrong. The tool for that case comes later (see "Not now").

  • You may think: I mark a vertex as visited when I take it out of the queue.

    The truth: Mark it when you push it. If not, the same vertex enters the queue many times. In the code, dist[to] is set before q.push(to).

Common mistakes

  • No visited mark. In a graph with a cycle you then walk in a circle forever.
  • You add the edge in one direction only, or the size is g(n) while vertices are 1..n. Use n + 1.
  • Many test cases: you forget to clear g and visited before each one.

Not now

  • Roads with different lengths. BFS counts edges, not lengths. You learn the right tool in Shortest path (Dijkstra).
  • Trees. A tree is a connected graph with no cycle. It has its own tricks. You learn them in Trees.
  • An order where some tasks must come first. That is a question on a directed graph. You learn it in Topological sort.

Check yourself

  1. A graph has 5 vertices and the edges 1-2, 2-3 and 4-5. How many connected components does it have?
    Answer

    Two. One group is 1, 2, 3. The other group is 4, 5.

  2. You need the minimum number of moves in a maze. Do you use DFS or BFS? Why?
    Answer

    BFS. It moves level by level, so the first time it reaches a cell is the shortest way.

  3. A graph has \( 10^5 \) vertices and \( 2 \cdot 10^5 \) edges. About how many steps does BFS need?
    Answer

    About \( n + m = 3 \cdot 10^5 \) steps. Each vertex and each edge is used once.
