The judge does about 108 simple steps in one second. Read the limits, count your steps, and you know if your idea is fast enough.

Use it on every problem

  • Before you write code: look at the biggest n in the constraints.
  • Count the steps of your idea for that n.
  • About 108 or less → fine. 109 or more → too slow. Find a better idea.

The key table

O(…) is a short way to write "how many steps". It is called complexity. This table tells you which one the problem wants.

Biggest nSpeed that fitsUsual idea
n ≤ 10 – 11O(n!)Try every order.
n ≤ 20O(2n)Try every "take it or not".
n ≤ 500O(n3)Three loops.
n ≤ 5000O(n2)Two loops: all pairs.
n ≤ 2·105 (or 106)O(n log n) or O(n)Sort, one loop, binary search, map.
n ≤ 109 – 1012O(√n)Loop while i·i ≤ n.
n ≤ 109 – 1018O(log n) or O(1)A formula, or halving.

The row n ≤ 2·105 is the most common one. It means: two loops over n are too slow.

Three ways to understand it

1 · Story — walk or fly

You must travel 1000 km and you have one day. You can walk, drive or fly. You do not start walking and hope. You look at the distance first, then you choose.

The limits are the distance. The time limit is your one day. O(n2) is walking. O(n log n) is driving. O(log n) is flying.

For small n everything is fast. For n = 105 the n2 idea gets Time limit exceeded.

3 · Code — count the loops

O(n) — one loop:


long long sum = 0;
for (int i = 0; i < n; i++) sum += a[i];          // n steps

O(n2) — a nested loop:


int pairs = 0;
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)               // about n * n / 2 steps
        if (a[i] == a[j]) pairs++;

O(log n) — the number is cut in half each time:


int steps = 0;
while (n > 1) {                                   // 10^9 -> 1 in about 30 steps
    n /= 2;
    steps++;
}

sort is O(n log n). One map or set operation is O(log n).

Rule: put the biggest n into your O(…). Result ≤ about 108 → OK for 1 second.

With t test cases

If the statement says "the sum of n over all test cases ≤ 2·105", use that sum as your n. An O(n) solution for each test is fine.

If it does not say this, multiply: steps = t × (steps for one test).

Common mistakes

  • You write two loops for n = 2·105. That is 4·1010 steps.
  • A hidden loop: a.erase(a.begin()), count(...) or s.substr(...) inside a loop is O(n) each time.
  • You clear a big array of size 106 in every test case. With t = 104 this is 1010 steps.
  • You make a fast, hard solution when n ≤ 100. Small limits mean: the simple way is enough.
