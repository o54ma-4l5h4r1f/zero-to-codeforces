Do not change code and hope. Look at the verdict, follow a checklist in order, and test your code against a slow, simple solution.

First: read the verdict

The verdict tells you where to look. Each one has its own checklist below.

VerdictShortIt means
Wrong answerWAThe program ran, but printed something wrong.
Time limit exceededTLEThe program is too slow, or it never stops.
Runtime errorREThe program crashed.

Wrong answer: check in this order

  1. Read the statement again, slowly. Also read the output format. Most bugs are here.
  2. Test edge cases by hand: n = 1, all numbers equal, already sorted, the maximum values, an answer of 0.
  3. Overflow: can a sum or a product pass 2·109? Use long long. See int or long long?
  4. Array bounds: is every index from 0 to n − 1? Look at a[i + 1] and a[i - 1].
  5. Uninitialised variables: int sum; holds garbage. Write int sum = 0;
  6. Many test cases: do you reset every array and counter before each test case?
  7. Spelling: YES or Yes? A space or a new line between the numbers?

Explain your code line by line to a friend, or to an empty chair. When you must say what each line does, you often see the bug.

Time limit exceeded

  • Count the steps from the limits. More than about 108? You need a faster idea, not a faster keyboard. See Limits → speed.
  • endl is slow when you print many lines. Print "\n".
  • A vector passed by value is copied on every call. Write const vector<int> &a.
  • A loop that never ends: does the loop variable really change? Is it i++ in the inner loop, or j++?

Runtime error

  • Index out of range: an array that is too small, a[n], or a[-1].
  • Division by zero: x / 0 and x % 0 both crash.
  • Empty container: v.back(), s.top() or q.front() when nothing is inside.
  • Recursion that is too deep, or that never stops because the stop condition is missing.

Print what your program thinks

Print the variables inside the loop and compare them with your hand trace. Use cerr, not cout. The judge ignores cerr, so a forgotten line does not give Wrong answer.


for (int i = 0; i < n; i++) {
    sum += a[i];
    cerr << "i=" << i << " a[i]=" << a[i] << " sum=" << sum << "\n";   // debug line
}

Still delete these lines before you submit. Printing a lot to cerr takes time.

The strongest trick: stress testing

All samples pass, but the judge says Wrong answer on test 7. You cannot see test 7. So you make your own tests. This is stress testing.

1 · Story — two students

One student is fast but makes mistakes. The other is very slow but always right. Give both the same small questions. When their answers differ, you found a question where the fast student is wrong.

2 · Picture — the three parts

PartWhat it is
fast(...)Your real solution. Maybe it has a bug.
slow(...)A brute force: simple loops that are clearly correct. Speed does not matter.
generatorMakes small random inputs: n ≤ 6, values from −5 to 5.

Small inputs are the point. A wrong case with 4 numbers is easy to check by hand. A wrong case with 1000 numbers is useless.

3 · Code — everything in one file

Toy task: find the maximum sum of a subarray (at least one element).


#include <bits/stdc++.h>
using namespace std;

long long fast(const vector<int> &a) {     // the solution you want to submit: O(n)
    long long best = a[0], cur = 0;
    for (int x : a) {
        cur = max(cur + x, (long long)x);  // continue the old subarray, or start at x
        best = max(best, cur);
    }
    return best;
}

long long slow(const vector<int> &a) {     // try every subarray: O(n^2), clearly correct
    int n = a.size();
    long long best = a[0];
    for (int i = 0; i < n; i++) {
        long long sum = 0;
        for (int j = i; j < n; j++) {
            sum += a[j];                   // sum of a[i..j]
            best = max(best, sum);
        }
    }
    return best;
}

int main() {
    mt19937 rng(12345);                    // random generator; same tests on every run
    for (int test = 1; test <= 1000; test++) {
        int n = rng() % 6 + 1;             // n from 1 to 6
        vector<int> a(n);
        for (int &x : a) x = (int)(rng() % 11) - 5;   // values from -5 to 5
        long long f = fast(a), s = slow(a);
        if (f != s) {                      // the first input where they differ
            cout << "DIFFERENT on test " << test << "\n" << n << "\n";
            for (int x : a) cout << x << " ";
            cout << "\nfast = " << f << ", slow = " << s << "\n";
            return 0;
        }
    }
    cout << "all 1000 tests are equal\n";
}

Try it: change best = a[0] in fast to best = 0. The program now prints a small array with only negative numbers. That is the bug: the answer cannot be an empty subarray.

Common mistakes

  • You submit again and again with small random changes. Each wrong submit costs points in a contest.
  • You test only the samples. The samples are easy on purpose.
  • In a stress test you copy the same wrong idea into slow. Write slow in a different, simpler way.
  • Your random tests are big. Keep n small and the values small, so equal numbers and negative numbers appear often.
