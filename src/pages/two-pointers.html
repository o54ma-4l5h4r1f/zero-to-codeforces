Use two indexes that only move forward. Together they make at most 2n steps, so one pass replaces a slow double loop.

Spot it

  • "Find the longest (or shortest) subarray with …": sum ≤ S, at most k distinct values, max − min ≤ d.
  • The array is sorted (or you can sort it) and you look for a pair, for example with sum X.
  • You have two sorted lists and you walk through both at the same time.
  • n is up to 200 000, so trying every (l, r) is too slow.

Three ways to understand it

1 · Story — a window on the array

Put a window on the array. You see only the elements from l to r. This is a sliding window.

Move the right side one step: a new element comes in. If the window is now "too much", move the left side until it is fine again. The two sides never go back.

3 · Code — the sliding window

Task: n books, book i needs a[i] minutes. You have t minutes. You read books that stand next to each other. How many books can you read?


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    long long t;
    cin >> n >> t;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    long long sum = 0;                     // sum of the window a[l..r]
    int best = 0, l = 0;
    for (int r = 0; r < n; r++) {
        sum += a[r];                       // a[r] comes into the window
        while (sum > t) {                  // too much: make the window smaller
            sum -= a[l];
            l++;
        }
        best = max(best, r - l + 1);       // the window is fine now
    }
    cout << best << "\n";
}

Second form: two ends. In a sorted array, find two elements with sum x. Start at both ends and walk inward.


int i = 0, j = n - 1;                      // a is sorted, small -> big
while (i < j) {
    if (a[i] + a[j] == x) break;           // found the pair
    if (a[i] + a[j] < x) i++;              // sum too small: take a bigger left
    else j--;                              // sum too big: take a smaller right
}
// i < j here means: a[i] + a[j] == x.  i == j means: no such pair.

Third form: two lists. To merge two sorted lists, keep one pointer in each list. Take the smaller of the two front elements and move that pointer.

Speed: O(n). The inner while looks slow, but l moves at most n times in total. (Plus O(n log n) if you sort first.)

Common mistakes

  • Using it when a bigger window is not always "worse". With negative numbers the sum can go down again. The window idea then gives wrong answers.
  • Moving l back to 0 for every r. Then it is a double loop again, O(n2).
  • The two-ends form on an array that is not sorted.
  • You sort, but the task needs the old positions. Sort pairs (value, index), see Sorting.
