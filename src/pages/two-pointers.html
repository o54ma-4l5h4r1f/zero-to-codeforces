Use two indexes that only move forward. Together they make at most \( 2n \) steps, so one pass replaces a slow double loop.

Before this lesson

  • You can sort, and you saw the merge of two sorted lists → Sorting
  • You know what "the sum of a[l..r]" means → Prefix sums
  • You can count the steps of nested loops → Limits → speed

Spot it

  • "Find the longest (or shortest) subarray with …": sum at most \( S \), at most \( k \) distinct values, max − min at most \( d \).
  • The array is sorted, or you may sort it. You look for a pair, for example with sum \( x \).
  • \( n \) is up to \( 2 \cdot 10^5 \), so trying every pair \( (l, r) \) is too slow.

Three ways to understand it

1 · Story — a window on the array

Put a window on the array. You see only the elements from l to r. This is a sliding window.

Move the right side one step: a new element comes in. Is the window now "too much"? Move the left side until it is fine again. The two sides never go back.

2 · Picture — the longest subarray with sum at most 7

Why is it fast? The inner while looks like a second loop. But l never goes back, and it stops at the end. So l moves at most \( n \) times in the whole run, not \( n \) times for each r. Total: at most \( 2n \) moves, \( O(n) \).

When does it work? Only when a window always gets worse when it grows. With numbers that are not negative, a bigger window never has a smaller sum. So a window that is "too much" stays too much when it grows. Negative numbers break this:

3 · Code — the sliding window

Task: \( n \) books, book \( i \) needs a[i] minutes. You have t minutes. You read books that stand next to each other. How many books can you read?


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    long long t;
    cin >> n >> t;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    long long sum = 0;                     // sum of the window a[l..r]
    int best = 0, l = 0;
    for (int r = 0; r < n; r++) {
        sum += a[r];                       // a[r] comes into the window
        while (sum > t) {                  // too much: make the window smaller
            sum -= a[l];
            l++;
        }
        best = max(best, r - l + 1);       // the window is fine now
    }
    cout << best << "\n";
}

If one book alone needs more than t, l passes r. Then r - l + 1 is 0, and that is right: an empty window.

Change it to fit

The default form is the loop above: "r goes forward; while the window is bad, l goes forward". Here is how it changes.

1. Longest → shortest. "The shortest window with sum at least \( S \)." Now a good window is the one to shrink. Save the answer inside the while:


for (int r = 0; r < n; r++) {
    sum += a[r];
    while (sum >= S) {                     // good: save it, then try smaller
        best = min(best, r - l + 1);       // best starts at a big value, like n + 1
        sum -= a[l]; l++;
    }
}

2. Sum → at most \( k \) distinct values. The window keeps counts in a map instead of a sum.


cnt[a[r]]++;
if (cnt[a[r]] == 1) distinct++;            // a new value came in
while (distinct > k) {                     // too many: remove from the left
    cnt[a[l]]--;
    if (cnt[a[l]] == 0) distinct--;
    l++;
}

3. Two ends move inward. In a sorted array, find two elements with sum x. If the sum is too small, move the left end. If it is too big, move the right end.


int i = 0, j = n - 1;                      // a is sorted, small -> big
while (i < j) {
    if (a[i] + a[j] == x) break;           // found the pair
    if (a[i] + a[j] < x) i++;              // too small: a bigger left value
    else j--;                              // too big: a smaller right value
}
// i < j here means a[i] + a[j] == x.  i == j means: no such pair.

4. Two sorted arrays. One pointer in each array, both moving forward. This is the merge you saw in Sorting. It is two pointers too.

Solve one together

Problem. There are \( n \) students with skills \( a_i \). Choose the biggest team. In the team, any two skills may differ by at most 5. Limits: \( 1 \le n \le 2 \cdot 10^5 \) and \( 1 \le a_i \le 10^9 \).

  1. What is asked? The size of the biggest group with max − min at most 5.
  2. A small example by hand. Skills 1 10 17 12 15 2. Sorted: 1 2 10 12 15 17.
    group1 210 12 1512 15 1710 12 15 17
    max − min1557
    ok?yesyes, size 3yes, size 3no

    The answer is 3.

  3. The idea. The order of the students does not matter, so sort. Then a good team is a window of neighbours. When the window grows, max − min only grows or stays. So the sliding window works. The window is bad when a[r] - a[l] > 5.
  4. Why is it fast enough? The sort costs about \( 3.6 \cdot 10^6 \) steps. The window costs at most \( 2n = 4 \cdot 10^5 \) moves.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    for (auto &x : a) cin >> x;
    sort(a.begin(), a.end());                  // now max - min of a[l..r] is a[r] - a[l]
    int best = 0, l = 0;
    for (int r = 0; r < n; r++) {
        while (a[r] - a[l] > 5) l++;           // too wide: move the left side
        best = max(best, r - l + 1);
    }
    cout << best << "\n";
}

Speed: \( O(n) \) for the two pointers, because each one moves at most \( n \) times. Plus \( O(n \log n) \) if you sort first.

Wrong ideas people get

  • You may think: A while inside a for means \( O(n^2) \).

    The truth: Here l only moves forward. All its moves together are at most \( n \). Count them in the picture: 4 moves for \( n = 7 \).

  • You may think: The sliding window works on any array.

    The truth: Only if a bigger window is never better. With negative numbers it can give a wrong answer. See the 3 5 −6 2 picture.

  • You may think: The two-ends form works on any array.

    The truth: It needs a sorted array. Without sorting, moving an end does not make the sum bigger or smaller.

Common mistakes

  • Setting l = 0 again for every r. Then it is a double loop again, \( O(n^2) \).
  • Saving r - l + 1 before the while. Then you save a window that is still bad.
  • The window sum in an int. \( 2 \cdot 10^5 \) values of \( 10^9 \) need long long.

Not now

  • Binary search instead of the window. Some window problems can also use it, in \( O(n \log n) \). Learn it next: Binary search.
  • The max of every window of size \( k \) with a deque. Rare below 1600: After 1600.

Check yourself

  1. The array is 2 2 2 2 and \( S = 5 \). How long is the longest window with sum at most 5?
    Answer

    2. Two elements give 4. Three give 6, too much.

  2. With \( n = 10 \), at most how many times does l move in the whole run?
    Answer

    10. It only moves forward, from 0 to the end. Together with r: at most 20 moves.

  3. The array is 1 −1 1 −1 1. Do you use the sliding window for the longest part with sum at most 1?
    Answer

    No. There are negative numbers, so a bigger window can have a smaller sum.
