A tree is a connected graph with no cycle. One DFS from the root answers most tree questions.

Before this lesson

  • You can store a graph and run DFS and BFS → Graphs: BFS and DFS
  • You know that a call waits for the calls it makes → Recursion and backtracking

Spot it

  • "\( n \) vertices and \( n - 1 \) edges", and the graph is connected.
  • "There is exactly one path between every two vertices."
  • "The parent of vertex \( i \) is \( p_i \)", or a boss and workers, or folders inside folders.
  • Words like root, leaf, subtree.

Three ways to understand it

1 · Story — a company

A company has one director. This is the root. Every other person has exactly one boss: the parent. The people directly under you are your children. A person with no workers is a leaf.

Your depth is the number of bosses above you. Your subtree is you and everybody under you. A tree has no cycle: nobody is the boss of their own boss.

2 · Picture — depth goes down, size comes up

One DFS from the root 1. Each vertex gets two labels: d = depth, s = size of its subtree.

The depth is known on the way down. The size is known only on the way back up.

3 · Code — one DFS

The input comes in one of two forms. Here is the same tree in both:

vertex234567
its parent (parent form)112236
its line in the edge list1 21 32 42 53 66 7

Every vertex except the root has one parent, so there are \( n - 1 = 6 \) edges. The program below reads the edge list. The root is vertex 1. As in Graphs, g, depth and sz are global because dfs needs them; the assign lines reset them for each test.

You need no visited array. A tree has no cycle, so the only visited neighbour is the parent. Skip the parent, and you never come back:


#include <bits/stdc++.h>
using namespace std;

vector<vector<int>> g;
vector<int> depth, sz;

void dfs(int v, int parent) {
    sz[v] = 1;                           // v itself
    for (int to : g[v]) {
        if (to == parent) continue;      // do not go back up
        depth[to] = depth[v] + 1;        // going down: before the call
        dfs(to, v);
        sz[v] += sz[to];                 // coming up: after the call
    }
}

int main() {
    int n;
    cin >> n;
    g.assign(n + 1, vector<int>());
    depth.assign(n + 1, 0);
    sz.assign(n + 1, 0);
    for (int i = 0; i < n - 1; i++) {    // a tree has n - 1 edges
        int a, b;
        cin >> a >> b;
        g[a].push_back(b);
        g[b].push_back(a);
    }
    dfs(1, 0);                           // the root has no parent: use 0
    for (int v = 1; v <= n; v++)
        cout << v << ": depth " << depth[v] << ", size " << sz[v] << "\n";
}

Change it to fit

Default: the function dfs(v, parent) above. A "down" value goes before the call. An "up" value goes after it.

  • The input gives parents, not edges. Store children only. The same dfs still works: the parent is never in the list. 
    
for (int v = 2; v <= n; v++) {
    int p;
    cin >> p;                 // p is the parent of v
    g[p].push_back(v);        // g[p] = children of p
}
  • Count the leaves. A vertex is a leaf if its size is still 1 after the loop: it has no children. Add after the loop in dfs: 
    
if (sz[v] == 1) leaves++;
  • The sum of the values in each subtree. The same as size, with values in place of 1. Use long long: 
    
sum[v] = val[v];              // in place of sz[v] = 1
sum[v] += sum[to];            // in place of sz[v] += sz[to]
  • The height: the longest way down to a leaf. An "up" value with max. Start with h[v] = 0: 
    
h[v] = max(h[v], h[to] + 1);  // after dfs(to, v)

Solve one together

Problem. A tree has \( n \) vertices. Find the length of its longest path, counted in edges. This path is the diameter. Limits: \( 1 \le n \le 2 \cdot 10^5 \). (This is "Tree Diameter" on CSES.)

  1. What is asked? The biggest distance between any two vertices. Trying every pair is \( n^2 = 4 \cdot 10^{10} \) steps: too slow.
  2. A small example by hand. The same tree. Run BFS two times:
  3. The idea. The farthest vertex from any vertex is always one end of a longest path. This is a known fact about trees; we do not prove it here. So: BFS from 1, take the farthest vertex a. BFS from a. The biggest distance is the answer.
  4. Why is it fast enough? Two BFS runs, each \( O(n) \). That is about \( 4 \cdot 10^5 \) steps. Far below \( 10^8 \).

#include <bits/stdc++.h>
using namespace std;

int n;
vector<vector<int>> g;

vector<int> bfs(int start) {
    vector<int> dist(n + 1, -1);          // -1 = not reached yet
    queue<int> q;
    dist[start] = 0;
    q.push(start);
    while (!q.empty()) {
        int v = q.front();
        q.pop();
        for (int to : g[v]) {
            if (dist[to] != -1) continue;
            dist[to] = dist[v] + 1;
            q.push(to);
        }
    }
    return dist;
}

int main() {
    cin >> n;
    g.assign(n + 1, vector<int>());
    for (int i = 0; i < n - 1; i++) {
        int a, b;
        cin >> a >> b;
        g[a].push_back(b);
        g[b].push_back(a);
    }
    vector<int> d1 = bfs(1);
    int a = 1;
    for (int v = 1; v <= n; v++)
        if (d1[v] > d1[a]) a = v;            // a = farthest from 1
    vector<int> d2 = bfs(a);
    int best = 0;
    for (int v = 1; v <= n; v++) best = max(best, d2[v]);
    cout << best << "\n";                    // the diameter, in edges
}

Speed: \( O(n) \). The DFS (or the BFS) enters every vertex once and uses every edge twice.

Wrong ideas people get

  • You may think: I need a visited array for a DFS on a tree.

    The truth: No. With no cycle, the only visited neighbour is the parent. Skipping it is enough.

  • You may think: The line "a b" in the edge list means that a is the parent of b.

    The truth: An edge has no direction. You choose the root, and the DFS decides who is the parent. Read the statement: sometimes the root is given.

  • You may think: The size of a subtree is ready when I enter the vertex.

    The truth: It is ready only after all children return, so after the loop. In the picture, "s" appears on the way up.

Common mistakes

  • You read \( n \) edges. A tree has \( n - 1 \) edges.
  • You forget if (to == parent) continue;. Then the DFS jumps between two vertices forever.
  • A tree can be one long chain of \( 2 \cdot 10^5 \) vertices. The DFS then goes that many calls deep. On Codeforces the stack is big (256 MB), so even \( 10^6 \) calls deep is fine there. On your own computer the stack is often 8 MB, and such a chain can crash. That is the stack, not your code.

Not now

  • The distance between any two vertices, many times (LCA, binary lifting). Needed above 1600. See After 1600.
  • DP on trees (the best answer for every subtree). Learn Dynamic programming first, then come back after 1600.

Check yourself

  1. In the tree of the picture, what are the depth of vertex 6 and the size of its subtree?
    Answer

    Depth 2 (bosses 3 and 1). Size 2 (vertex 6 and vertex 7).

  2. A tree has 10 vertices. How many edges does it have?
    Answer

    9. Every vertex except the root has exactly one edge to its parent.

  3. Why do we add sz[to] after the call dfs(to, v), and not before it?
    Answer

    Before the call, sz[to] is still 0. The call fills it. Size is an "up" value.
