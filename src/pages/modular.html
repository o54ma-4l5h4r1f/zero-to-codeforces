When the answer is too big for any type, keep only its remainder. Take the remainder after every step, and the numbers stay small.

Spot it

  • "Print the answer modulo 109 + 7" (or 998244353).
  • You count the number of ways, and it grows very fast.
  • You need ab with a big b, like b = 1018 → fast power.
  • "The last digit of …" is the same thing: modulo 10.

Three ways to understand it

1 · Story — the clock

It is 10 o'clock. What time is it after 5 hours? Not 15. The clock says 3, because (10 + 5) % 12 = 3. A clock keeps only the remainder.

You can add hours one by one, or all together. The clock shows the same time. So you may take the remainder at any moment, and the final remainder does not change.

Why does the judge ask for it? The real answer can have thousands of digits. The remainder by 109 + 7 fits in an int, and it still shows that your method is right.

After each step b = b / 2. When b is 0 we stop. For b = 1018 that is only about 60 steps. In real code every multiplication is followed by % m.

3 · Code — power(a, b, m)


long long power(long long a, long long b, long long m) {   // a^b % m
    long long result = 1 % m;              // 1 % m, so it is also right for m = 1
    a %= m;                                // make a small first
    while (b > 0) {
        if (b % 2 == 1)                    // this power of a is needed
            result = result * a % m;
        a = a * a % m;                     // a, a^2, a^4, a^8, ...
        b /= 2;
    }
    return result;
}

A complete program: for each test print ab modulo 109 + 7.


#include <bits/stdc++.h>
using namespace std;

const long long MOD = 1000000007;          // 10^9 + 7, a prime

long long power(long long a, long long b, long long m) {
    long long result = 1 % m;
    a %= m;
    while (b > 0) {
        if (b % 2 == 1) result = result * a % m;
        a = a * a % m;
        b /= 2;
    }
    return result;
}

int main() {
    int t;
    cin >> t;
    while (t--) {
        long long a, b;
        cin >> a >> b;
        cout << power(a, b, MOD) << "\n";
    }
}

Division: you cannot write (a / b) % m. You multiply by the modular inverse of b. For a prime m it is power(b, m - 2, m). See Counting with nCr.

Speed: +, −, × with mod are O(1). Fast power is O(log b): about 60 steps for b = 10^18.

Common mistakes

  • Taking the mod only at the end. The number overflows long before. Take it after every + and ×.
  • Multiplying two int values: a * b % m overflows before the %. Use long long, or write 1LL * a * b % m.
  • A negative result after subtraction. Write ((a - b) % m + m) % m.
  • Comparing numbers after the mod. A bigger real number can have a smaller remainder. Never take min or max of remainders.
