You do not search for the best answer. You must build one answer that follows the rules. Find a simple pattern and print it.

Spot it

  • "If there are several answers, print any of them."
  • "Find an array / a permutation / a string such that …"
  • "… or print −1 (or NO) if it is impossible."
  • The limits are big, but the task has no real data to work on, often only one number n.

Three ways to understand it

1 · Story — tiling a floor

A worker covers a big floor with tiles. He does not think about each tile alone. He finds a small pattern that works, and he repeats it over the whole floor.

A constructive problem is the same. The judge accepts any valid answer, so choose the one that is the easiest to describe.

How to find the pattern:

  1. Solve the tiny cases by hand: n = 1, 2, 3, 4, 5, 6. Write the answers in a table.
  2. Try simple shapes first: sorted, reversed, shifted by one, alternating (small, big, small, big), all equal.
  3. Find when it is impossible. Look at parity and sums: something that never changes (an invariant).
  4. Test your pattern with a small checker before you submit (see the code below).

Example for step 3: "split the numbers 1..n into two groups with equal sums". The total is n · (n + 1) / 2. If the total is odd, no split exists. Print NO at once.

2 · Picture — a permutation where no number stays at home

Task: for a given n ≥ 2 print a permutation p of 1..n with p[i] ≠ i for every position i (positions from 1).

nan answer found by handwhat we see
22 1the only one
32 3 1everybody moves one step
42 3 4 1the same idea works
52 3 4 5 1again
62 3 4 5 6 1pattern: 2, 3, …, n, 1

Now check the pattern for every n, not only for the table. Position i (for i < n) holds i + 1, which is not i. Position n holds 1, which is not n because n ≥ 2. Every number is used once. So it is always valid.

This pattern is a shift by one. It is one of the most useful shapes in constructive problems.

3 · Code — print the pattern


#include <bits/stdc++.h>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        int n;
        cin >> n;                                  // n >= 2
        for (int i = 2; i <= n; i++) cout << i << " ";   // positions 1..n-1 get 2..n
        cout << 1 << "\n";                         // position n gets 1
    }
}

A checker. Write a small function that tests the rules of the statement. Run it on your own computer for every n from 2 to 50. If it says "false" for some n, you found a bug before the judge did. More about this in How to find your bug.


bool isValid(vector<int> p) {              // p[0] is position 1, p[1] is position 2, ...
    int n = p.size();
    vector<bool> seen(n + 1, false);
    for (int i = 0; i < n; i++) {
        if (p[i] < 1 || p[i] > n) return false;    // not a number from 1..n
        if (seen[p[i]]) return false;              // used twice: not a permutation
        seen[p[i]] = true;
        if (p[i] == i + 1) return false;           // this number stays at home
    }
    return true;
}

Speed: usually O(n), you only print the answer. The hard part is the idea, not the running time.

Common mistakes

  • Forgetting the small cases. A pattern that works for n ≥ 4 can fail for n = 1, 2 or 3. Check each edge case by hand.
  • Forgetting the impossible case, or printing −1 when an answer exists.
  • Thinking your output must be equal to the sample output. It does not. Any valid answer is accepted.
  • Looking for a clever method for too long. First write tiny cases on paper. The pattern often shows itself.
