You do not search for the best answer. You build one answer that follows the rules. Find a simple pattern and print it.

Spot it

  • "If there are several answers, print any of them."
  • "Find an array / a permutation / a string such that …"
  • "… or print −1 (or NO) if it is impossible."
  • The input is tiny, often only one number \( n \). The work is to invent the output.

Three ways to understand it

There is no single algorithm here. There are three ways to find a construction. We use all three on one task: split the numbers \( 1, 2, \dots, n \) into two groups with equal sums, or print NO.

1 · Tiny cases — solve n = 1 to 8 by hand, write a table

Look at the "yes" rows: 3, 4, 7, 8. It looks like "yes" when \( n \bmod 4 \) is 0 or 3. A table is only a guess. Ways 2 and 3 make it sure.

2 · What never changes — the total sum

However you split, the total stays \( 1 + 2 + \dots + n = \frac{n (n + 1)}{2} \). Each group must get half of it.

For \( n = 5 \) the total is 15. Half of 15 is not a whole number, so the answer is NO. For \( n = 6 \) the total is 21: also NO.

A thing that never changes, whatever you do, is an invariant. If the total is odd, no split exists. The total is even exactly when \( n \bmod 4 \) is 0 or 3. So the table was right.

3 · Simple shapes — blocks of four

Take four numbers in a row, like 1 2 3 4. The outer two have the same sum as the inner two: \( 1 + 4 = 2 + 3 \). So put the outer two in A and the inner two in B.


for (int s = start; s + 3 <= n; s += 4) {     // start = 1, or 4 after the 1 2 | 3 part
    A.push_back(s);     A.push_back(s + 3);    // the outer two
    B.push_back(s + 1); B.push_back(s + 2);    // the inner two
}

Solve one together

Problem. There are \( t \) tests. Each test gives \( n \) with \( 2 \le n \le 100 \). Print a permutation \( p \) of \( 1 \dots n \) with \( p_i \ne i \) for every position \( i \) (positions from 1). "Nobody stays at home."

  1. What is asked? Any order of 1 to \( n \) where no number stands at its own position.
  2. A small example by hand. For \( n = 2 \) the only answer is 2 1. For \( n = 3 \), 2 3 1 works.
  3. First try: reversed. For \( n = 4 \), 4 3 2 1 works. For \( n = 3 \) we get 3 2 1. But position 2 holds 2. For every odd \( n \) the middle number stays at home. This try fails.
  4. Second try: pairs swapped. For \( n = 4 \), 2 1 4 3 works. For \( n = 5 \) we get 2 1 4 3 5, and the 5 has no partner. It fails for odd \( n \) again.
  5. The idea. Both failures were at odd \( n \). Make a table of shifted by one:
    nshifted by onevalid?
    22 1yes
    32 3 1yes
    42 3 4 1yes
    52 3 4 5 1yes, odd too

    Why does it always work? Position \( i < n \) holds \( i + 1 \), which is not \( i \). Position \( n \) holds 1, which is not \( n \), because \( n \ge 2 \).

  6. Why is it fast enough? We print \( n \) numbers per test: \( O(n) \). The hard part was the idea, not the speed.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        int n;
        cin >> n;                                          // n >= 2
        for (int i = 2; i <= n; i++) cout << i << " ";     // positions 1..n-1 get 2..n
        cout << 1 << "\n";                                 // position n gets 1
    }
}

Test the pattern before you submit. Write a function that tests the rules of the statement. Run it for every \( n \) from 2 to 50. Put "reversed" into build and it prints wrong for n = 3 at once. More in How to find your bug.


#include <bits/stdc++.h>
using namespace std;

vector<int> build(int n) {                 // the pattern we want to test
    vector<int> p;
    for (int i = 2; i <= n; i++) p.push_back(i);
    p.push_back(1);
    return p;
}

bool isValid(vector<int> p) {              // p[0] is position 1, p[1] is position 2, ...
    int n = p.size();
    vector<bool> seen(n + 1, false);
    for (int i = 0; i < n; i++) {
        if (p[i] < 1 || p[i] > n) return false;    // not a number from 1..n
        if (seen[p[i]]) return false;              // used twice: not a permutation
        seen[p[i]] = true;
        if (p[i] == i + 1) return false;           // this number stays at home
    }
    return true;
}

int main() {
    for (int n = 2; n <= 50; n++)          // n starts at 2, as in the statement
        if (!isValid(build(n))) { cout << "wrong for n = " << n << "\n"; return 0; }
    cout << "all n from 2 to 50 are OK\n";
}

Speed: usually \( O(n) \), you only print the answer. The hard part is the idea, not the running time.

Wrong ideas people get

  • You may think: My output must be the same as the sample output.

    The truth: No. When the statement says "print any", the judge accepts every valid answer.

  • You may think: If my pattern works for \( n = 4 \), 6 and 8, it always works.

    The truth: Test odd \( n \) and the smallest \( n \) too. Run the checker on every \( n \). The reversed shape above works for 4, 6, 8 and fails for 3.

  • You may think: There is one clever method I must learn for these problems.

    The truth: There is no single algorithm. Use the three ways: tiny cases, what never changes, simple shapes.

Common mistakes

  • Forgetting the impossible case. Or printing −1 when an answer exists.
  • Not checking the smallest \( n \) allowed. A pattern for \( n \ge 4 \) can fail for \( n = 2 \) or 3. Check each edge case by hand.
  • Spending an hour on a clever idea. First write tiny cases on paper for 10 minutes.

Not now

  • Full proofs that a pattern works for every \( n \). At this level a short reason plus a checker is enough. Come back after the guide: After 1600.
  • Building graphs and trees ("print a tree with …"). You need graphs first: Graphs: BFS and DFS.

Check yourself

  1. For the "nobody stays at home" task with \( n = 5 \), is 2 1 4 3 5 valid?
    Answer

    No. Position 5 holds 5.

  2. Can you split 1 to 6 into two groups with equal sums?
    Answer

    No. The total is \( \frac{6 \cdot 7}{2} = 21 \), an odd number. It cannot be cut into two equal halves.

  3. You need an order that goes up, down, up, down. Which shape do you try first?
    Answer

    Small, big, small, big. For \( n = 6 \): 1 6 2 5 3 4 goes up, down, up, down, up. Then test it with a checker.
