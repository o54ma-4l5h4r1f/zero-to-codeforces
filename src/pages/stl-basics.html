C++ gives you ready tools: sort, max, sum, pairs. Learn their names and never write them by hand again.

Before this lesson

  • You know vector and that indexes go from 0 to \( n - 1 \) → Arrays and strings
  • You can read \( O(n \log n) \) and compare it with \( 10^8 \) → How much does my code cost?

Spot it

  • You need the numbers in order, or the \( k \) biggest, or the \( k \) smallest.
  • You need the biggest, the smallest or the sum of an array.
  • Two values belong together, like a score and the person who has it.
  • You are about to write 10 lines for something very common. Stop. There is a tool for it.

Three ways to understand it

1 · Story — the toolbox

A carpenter does not make a new hammer for every nail. He opens the toolbox and takes one.

The STL is the toolbox of C++. Its tools are fast and tested by millions of people. Your own sort will be slower and can have bugs.

2 · Picture — what a.begin(), a.end() means

Most tools take two places in the array: where to start and where to stop. a.begin() is the first box. But a.end() is not the last box. It is the place right after the last box.

This is a half-open range: the start is in, the stop is out. Math writes it \( [0, 5) \). Its good side: the number of boxes = stop − start. Here \( 5 - 0 = 5 \).

You can move both ends. Take a = {5, 2, 8, 1, 9, 4}. a.begin() + 1 is box 1. a.begin() + 4 is box 4. So sort(a.begin() + 1, a.begin() + 4) sorts boxes 1, 2, 3 only. That is \( 4 - 1 = 3 \) boxes.

Now the toolbox. Here a is a vector<int>.

The * is needed: max_element gives the place of the biggest value, and * reads the value there. 0LL makes the sum a long long. With plain 0 the sum is an int and can overflow.

How pairs sort. A pair is sorted by .first. If two firsts are equal, the smaller .second comes first.

before sort{5, 1}{2, 2}{5, 0}{1, 3}
after sort{1, 3}{2, 2}{5, 0}{5, 1}

So put the value you sort by in .first.

3 · Code — the tools in one program

Read \( n \) scores. Print the smallest, the biggest and the sum. Then print the people from the best score to the worst.


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    int smallest = *min_element(a.begin(), a.end());
    int biggest  = *max_element(a.begin(), a.end());
    long long sum = accumulate(a.begin(), a.end(), 0LL);
    cout << smallest << " " << biggest << " " << sum << "\n";

    vector<pair<int,int>> people;            // {score, number of the person}
    for (int i = 0; i < n; i++) people.push_back({a[i], i + 1});
    sort(people.begin(), people.end(), greater<pair<int,int>>());   // best first
    for (int i = 0; i < n; i++) cout << people[i].second << " ";
    cout << "\n";
}

Input 4 / 30 10 50 20 prints 10 50 110 and then 3 1 4 2. Sorting moves the scores, but each pair still remembers its person.

The size() trap

a.size() is unsigned: it can never be negative. So \( 0 - 1 \) does not give \( -1 \). It wraps around to a huge number. This is real output for an empty vector<int> a;:

this lineprints
cout << a.size() - 1;18446744073709551615
cout << (int)a.size() - 1;-1

Now for (int i = 0; i < a.size() - 1; i++) on an empty array runs and reads boxes that do not exist. The rule: turn the size into int before any minus: (int)a.size() - 1.

Solve one together

Problem (1360B, Honest Coach). There are \( n \) athletes with strengths \( s_1, \dots, s_n \). Split them into two teams A and B. Each team needs at least one athlete. Make \( |\max(A) - \min(B)| \) as small as possible. Here \( |x| \) is \( x \) without its minus sign. Limits: \( 2 \le n \le 50 \).

  1. What is asked? One number: the smallest possible difference.
  2. A small example by hand. Strengths 3 1 2 6 4. Sort them: 1 2 3 4 6. Now cut the sorted row in one place. The left part is A, the right part is B.
    cut between1 | 22 | 33 | 44 | 6
    max(A), min(B)1, 22, 33, 44, 6
    difference1112

    The answer is 1.

  3. The idea. After sorting, each cut gives the difference of two neighbours. The answer is the smallest neighbour difference. You cannot do better than that, and a cut always reaches it.
  4. Why is it fast enough? Sort is \( O(n \log n) \), then one loop is \( O(n) \). For \( n = 50 \) that is a few hundred steps.

#include <bits/stdc++.h>
using namespace std;

void solve() {
    int n;
    cin >> n;
    vector<int> s(n);
    for (int i = 0; i < n; i++) cin >> s[i];
    sort(s.begin(), s.end());                    // small -> big
    int best = s[1] - s[0];
    for (int i = 0; i + 1 < n; i++)               // every pair of neighbours
        best = min(best, s[i + 1] - s[i]);
    cout << best << "\n";
}

int main() {
    int t;
    cin >> t;
    while (t--) solve();
}

Speed: sort is \( O(n \log n) \), fine for \( n = 10^6 \). min_element, accumulate, count and reverse are \( O(n) \). push_back, back and pop_back are \( O(1) \).

Wrong ideas people get

  • You may think: The place a.end() is the last element.

    The truth: It is the place after the last element. Never read from it. The last element is a.back().

  • You may think: For an empty array, a.size() - 1 is −1.

    The truth: It is a huge number, because size() is unsigned. Write (int)a.size() - 1.

  • You may think: Sorting pairs looks only at .first.

    The truth: When the firsts are equal, it compares .second too. So {5, 0} comes before {5, 1}.

Common mistakes

  • accumulate(…, 0) adds in int. Write 0LL.
  • You forget the * before max_element. The code does not compile, with a long error.
  • a.back(), a.pop_back() or *max_element on an empty array. The program may crash or print garbage. Check !a.empty() first.

Not now

  • map, set, stack, queue. More boxes from the same toolbox. They come in map, set, stack, queue.
  • Sorting by your own rule, like "by length, then by name". You learn it in Sorting. Until then, put the key in .first.
  • lower_bound and other searches in a sorted array. They come in Binary search.

Check yourself

  1. Sort the pairs {2, 5}, {1, 9}, {2, 3}. What is the order?
    Answer

    {1, 9}, {2, 3}, {2, 5}. First by .first; the two 2s are ordered by .second.

  2. We have a = {4, 7, 1, 3}. What is it after sort(a.begin() + 1, a.begin() + 3)?
    Answer

    {4, 1, 7, 3}. Only boxes 1 and 2 are sorted. Box 3 is the stop place, so it is out.

  3. What happens to for (int i = 0; i < a.size() - 1; i++) when a is empty?
    Answer

    a.size() - 1 is a huge number, so the loop runs. It reads boxes that do not exist and may crash.
