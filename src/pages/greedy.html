At every step take the choice that looks best right now, and never go back. Very often this means: sort, then take.

Spot it

  • The statement asks for the minimum or maximum number of something: coins, moves, items.
  • You build the answer step by step, and one choice is clearly the best: the biggest, the smallest, the earliest.
  • n is big (up to 2·105), so you cannot try all possibilities. A sort and one loop must be enough.
  • Taking the best item now does not block a better answer later.

Three ways to understand it

1 · Story — one hour of homework

You have one hour and many tasks. Each task needs some minutes. You want to finish as many tasks as you can.

Do the shortest task first, then the next shortest, and so on. A short task never hurts: it leaves the most time for the others. This is a greedy rule: "smallest first".

2 · Picture — pay 125 with the fewest bills

Problem 996A: the bills are 100, 20, 10, 5 and 1. Take the biggest bill as many times as you can, then the next one.

Answer: 3 bills (100 + 20 + 5). "Left after" is just left % bill.

3 · Code — biggest first


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    int bills[5] = {100, 20, 10, 5, 1};    // from big to small
    int count = 0;
    for (int b : bills) {
        count += n / b;                    // take this bill as many times as we can
        n %= b;                            // what is still left to pay
    }
    cout << count << "\n";
}

Sort, then take. Problem 160A: take the fewest coins so that your sum is strictly more than the sum of the coins you leave. Big coins help the most, so sort in descending order and take from the front.


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> a(n);
    int total = 0;
    for (int &x : a) { cin >> x; total += x; }

    sort(a.begin(), a.end(), greater<int>());   // biggest coin first
    int mine = 0, taken = 0;
    for (int x : a) {
        if (mine > total - mine) break;         // I already have more than the rest
        mine += x;                              // take the biggest coin that is left
        taken++;
    }
    cout << taken << "\n";
}

Input 3 / 2 1 2 → output 2: you take 2 + 2 = 4, and 1 is left.

Speed: O(n log n) for the sort, then O(n) for one loop. Fast enough for n = 2·10^5.

Warning: greedy can be wrong

Coins are 1, 3 and 4. Pay 6 with the fewest coins.

WayCoinsHow many
Greedy (biggest first)4 + 1 + 13
Best3 + 32

With bills 100, 20, 10, 5, 1 greedy is right. With coins 1, 3, 4 it is wrong. The code is the same, so you must check the idea before you trust it.

How to trust a greedy

  • Try small cases by hand. Does your rule give the best answer for every one of them?
  • Try to break it. Look for a counterexample, like "1, 3, 4 and 6" above. One is enough to kill the idea.
  • The swap idea: take any answer and swap two neighbour choices into your order. If this never makes the answer worse, your order is the best.
  • Limits help. If n ≤ 20, the problem may want brute force. If n = 2·105 and a simple rule passes your small tests, greedy is likely.

Not sure? Write a brute force and compare it with your greedy on small random inputs. See "stress testing" in How to find your bug.

Common mistakes

  • You trust the first rule you think of and do not test it on small cases.
  • You forget to sort, or you sort in the wrong direction (small first when you need big first).
  • More or at least? In 160A the sum must be strictly more. > and >= give different answers.
  • The sum of many numbers is in an int. Use long long when it can pass 2·109.
