Do not start with code. Read the limits, ask what is wanted, then choose the tool.

Come back to this page before every problem, and when you are stuck. It is a checklist, not a lesson.

Every table row has a stage number. In Stage 1? Skip the rows with a bigger number. Stage 0 is "Start here", Stage 3 is the last stage of tools. Rows marked "optional" are the last three lessons of Stage 3: read them when a problem needs them.

The thinking routine

Run these 7 steps on every problem, in this order. Write the answer of each step on paper.

  1. Read the limits first. Ask: how big is \( n \)? How big are the values? Write: "\( n \le 2 \cdot 10^5 \), so \( O(n \log n) \) at most". The table is in Limits → speed.
  2. Say the task in one sentence. Ask: what do I get, and what do I print? Write that sentence in your own words. Help: How to read a problem.
  3. Do the samples by hand. Ask: do I get the same output as the statement? If not, you misread something. Read again.
  4. Name the kind of answer. Is it yes / no? A number: a count, a minimum or a maximum? Something you must build? Answers to many queries? Write the kind.
  5. Try the slowest correct idea first. This is brute force. Count its steps for the biggest test (How much does my code cost?). Below about \( 10^8 \) steps? Stop and code it. You need nothing more.
  6. Too slow? Find what is repeated. Ask: which work does the slow idea do again and again? Pick the tool that removes it. The same range sum again → prefix sums. The same search in one array again → sort, then binary search. The same smaller problem again → DP. Write: "I repeat X, so I use Y".
  7. Before you submit. Run the samples and the edge cases (Run and test your code): \( n = 1 \), all values equal, the biggest values. Ask: can a sum or a product pass \( 2 \cdot 10^9 \)? Then use long long (int or long long?).

5 · When your first idea fails

Stuck? Try these moves one by one. Each has a small example.

  • Read the limits again, as a hint. \( n \le 20 \) says "subsets". \( n \le 5000 \) says "pairs". \( n \le 2 \cdot 10^5 \) says "sort, prefix sums, two pointers, binary search or a map". See section 1.
  • Sort it. Ask: "what if the array were sorted? Does the order matter?" The smallest difference between two numbers? After sorting, check only neighbours.
  • Think backwards. Make \( x \) from 1 with "\( \times 2 \)" and "\( +1 \)"? Go back from \( x \): even → divide by 2, odd → subtract 1.
  • Fix one thing and loop over it. Count triples \( i < j < k \)? Fix the middle \( j \). Count good \( i \) on its left and good \( k \) on its right.
  • Solve tiny cases by hand. Write \( n = 1, 2, 3, 4, 5 \) in a table. Here you get 1, 3, 6, 10, 15. The pattern is \( \frac{n(n+1)}{2} \). Then check your guess against a brute force on many small inputs (How to find your bug).
  • Look for what never changes. Each move adds 2 to one element? Then the parity of the sum never changes. An odd sum can never reach 0. This is an invariant. Also look at the sum itself, and at how many times each value appears.
  • Guess that the answer is small. Very often it is 0, 1, 2, or -1 ("impossible"). Ask: when is it 0? When is it 1? Is it ever more than 2?
  • Turn "find the best" into "can I do X?" "The least time to finish" becomes "can I finish in time \( T \)?" If yes for \( T \), yes for every bigger \( T \): binary search on the answer.
  • Count the complement. Pairs with different values = all pairs − pairs with equal values. All pairs: \( \frac{n(n-1)}{2} \).
  • Think about one element's contribution. The sum over all subarrays of [4, 5, 6]? The middle 5 is in 4 subarrays: [5], [4, 5], [5, 6], [4, 5, 6]. So it adds \( 4 \cdot 5 = 20 \).
  • Swap the order of the loops. "For each number, find its divisors" is slow. "For each \( d \), visit its multiples \( d, 2d, 3d, \dots \)" costs about \( n \log n \).
  • Two players, "who wins?" Play tiny games by hand. Mark each small position as a win or a loss, and look for the pattern (often parity). The full theory is in After 1600.

6 · Then change the tool to fit

The form in the lesson is a starting point. In a real problem you change one line or one idea. Examples:

  • Binary search finds the first \( x \) that works. The problem wants the last one? Keep lo on a yes and hi on a no, and return lo (see Binary search).
  • BFS starts from one cell. The problem has many fires at the start? Put all of them in the queue first.
  • Prefix sums add values. The problem asks "how many good positions"? Write 1 on a good position, 0 on the others.

Many tool lessons have a section "Change it to fit", right after "Three ways". It shows such changes, with the changed line of code. See Sorting, Greedy, Prefix sums, Two pointers, Binary search, Recursion, Trees, DP and Dijkstra.

Which tool? Drills

For each problem: read it, decide the tool, and write why. Only then open the answer. You do not need to solve it now. The order is mixed on purpose.

  1. Beautiful Matrix 800
    A \( 5 \times 5 \) table has one 1. You may swap two neighbour rows or columns. Fewest moves to bring the 1 to the centre?
    Answer

    Tool: simulation with a small formula. Signal: a tiny fixed table and one thing to find. Idea: find the 1 at row \( r \), column \( c \); the answer is \( |r-3| + |c-3| \).

  2. Maximum Median 1400
    \( n \) is odd. You may add 1 to any element, \( k \) times in total. Make the median as big as possible.
    Answer

    Tool: sort, then binary search on the answer. Signal: "as big as possible", and a smaller median is always reachable too. Idea: for a guess \( x \), the cost is what the upper half needs to reach \( x \); check cost \( \le k \).

  3. Two Teams Composing 1100
    Students have skills. Team 1: all skills different. Team 2: all skills equal. Both teams have the same size. Biggest size?
    Answer

    Tool: counting. Signal: only how many times each skill appears matters. Idea: with \( d \) distinct skills and top frequency \( f \), the answer is \( \max(\min(d-1, f), \min(d, f-1)) \).

  4. The Lakes 1100
    A grid of depths. Cells with depth above 0 that touch by a side form one lake. Find the biggest total depth of a lake.
    Answer

    Tool: DFS / BFS on a grid. Signal: a grid, "touch by a side", groups of cells. Idea: from each unvisited water cell, run DFS and add up the depths.

  5. Petr and a Combination Lock 1200
    A lock gets \( n \le 15 \) turns. Each turn goes left or right. Can the pointer end at zero?
    Answer

    Tool: bits: try every subset with a mask. Signal: \( n \le 15 \) and two choices per item: \( 2^{15} = 32768 \) cases. Idea: for each mask add or subtract each angle; check the total modulo 360.

  6. Boredom 1500
    Pick a number \( x \) and get \( x \) points. Then every \( x-1 \) and \( x+1 \) is deleted. Most points?
    Answer

    Tool: counting + DP. Signal: a maximum, and one choice blocks its neighbours; "take the biggest" fails. Idea: for each value \( v \): skip it, or take all copies and skip \( v-1 \).

  7. Divisibility Problem 800
    Add 1 to \( a \) again and again until \( b \) divides it. How many moves? \( a, b \le 10^9 \).
    Answer

    Tool: basic math with mod. Signal: values up to \( 10^9 \) and many tests; a loop can run \( 10^9 \) times. Idea: 0 if \( a \bmod b = 0 \), else \( b - a \bmod b \).

  8. Books 1400
    Books in a row, each needs \( a_i \) minutes. Start at any book and read the next ones in order. Most books in \( t \) minutes?
    Answer

    Tool: two pointers. Signal: the longest block of neighbours with sum \( \le t \); times are positive. Idea: move r right; while the sum is above \( t \), move l right.

  9. Fox And Names 1600
    Find an order of the 26 letters so that a given list of names is sorted. Or say "Impossible".
    Answer

    Tool: topological sort. Signal: rules "letter a comes before letter b"; print an order or say none exists. Idea: two neighbour names give one rule at their first different letter. If there is no different letter and the first name is longer, print "Impossible".

  10. Twins 900
    Coins with values. Take the fewest coins so that your sum is strictly bigger than the sum you leave.
    Answer

    Tool: sorting + greedy. Signal: "fewest", and the order of the coins does not matter. Idea: sort from the biggest; take coins until your sum is bigger than the rest.

  11. Kuriyama Mirai's Stones 1200
    An array and many questions: the sum from \( l \) to \( r \) of the array, or of the sorted array.
    Answer

    Tool: prefix sums. Signal: many range-sum queries; the array never changes. Idea: one prefix array for the array, one for a sorted copy; use long long.

  12. Bear and Prime 100 1400
    A hidden number from 2 to 100. Ask at most 20 times "is \( d \) a divisor?". Then say prime or composite.
    Answer

    Tool: interactive + divisors. Signal: a hidden number and a query limit. Idea: ask the 15 primes up to 47 and also 4, 9, 25, 49; two "yes" answers mean composite.

  13. Balanced Array 800
    \( n \) is even. Build \( n \) different positive numbers: first half even, second half odd, equal sums. Or say NO.
    Answer

    Tool: constructive. Signal: "build an array", any answer, or NO. Idea: if \( n/2 \) is odd, the odd half has an odd sum: NO. Else write 2, 4, 6, … and 1, 3, 5, …, then fix the last odd number.

  14. Two Buttons 1400
    A screen shows \( n \). Red button: double it. Blue button: subtract 1. Fewest clicks to reach \( m \)? \( n, m \le 10^4 \).
    Answer

    Tool: BFS on numbers. Signal: "fewest clicks", every click costs 1, few possible values. Idea: each number is a vertex; BFS from \( n \). Thinking backwards from \( m \) also works.

  15. T-primes 1300
    A number is "T-prime" if it has exactly three divisors. Check up to \( 10^5 \) numbers, each up to \( 10^{12} \).
    Answer

    Tool: sieve. Signal: divisors, primes, and many numbers. Idea: only \( p^2 \) with a prime \( p \) has three divisors; sieve up to \( 10^6 \).

  16. Taxi 1100
    Groups of 1 to 4 children. A taxi takes at most 4 children, and a group rides together. Fewest taxis?
    Answer

    Tool: greedy with counts. Signal: "fewest", and the best match is clear. Idea: count groups by size; a 4 alone, a 3 with a 1, two 2s together, then the 1s.

  17. News Distribution 1400
    Users are in groups. News spreads between users who share a group. For each user: how many users get the news if this user starts?
    Answer

    Tool: DFS on components, or DSU (optional lesson). Signal: groups join and never split; the question is the size of a group. Idea: join every member of a group to its first member; print the size of each user's set.

  18. Dreamoon and WiFi 1300
    Commands + and − move you left and right. Some were lost; each lost one is + or − with chance 1/2. Chance to end at the right place?
    Answer

    Tool: brute force, or recursion: try every case. Signal: at most 10 lost commands, so at most \( 2^{10} = 1024 \) cases. Idea: count the cases that end right, then divide by the number of cases.

  19. Interesting drink 1100
    Shops sell a drink, each at its own price. On each of many days you have \( m \) coins. In how many shops can you buy?
    Answer

    Tool: sort, then binary search. Signal: many queries "how many are \( \le m \)", and the shop order does not matter. Idea: sort the prices; the answer is upper_bound of \( m \).

  20. Kefa and Park 1500
    A tree with root 1. Some vertices have cats. Count the leaves whose path from the root never has more than \( m \) cats in a row.
    Answer

    Tool: trees: DFS from the root. Signal: root, leaves, a path from the root. Idea: the DFS carries the current run of cats; stop when it is above \( m \).

  21. The World is a Theatre 1400
    \( n \) boys and \( m \) girls, both at most 30. Count the groups of exactly \( t \) people with at least 4 boys and at least 1 girl.
    Answer

    Tool: C(n, k), combinatorics. Signal: "count the groups", and the order inside a group does not matter. Idea: for each number of boys \( b \ge 4 \), add C(n, b) · C(m, t − b) with \( t - b \ge 1 \).

  22. Greg and Array 1400
    \( m \) operations "add \( d \) to positions \( l..r \)". Then \( k \) queries "apply operations \( x..y \)". Print the final array.
    Answer

    Tool: difference array, twice (prefix sums). Signal: many range additions; you read the array only at the end. Idea: one difference array counts how often each operation runs; a second one applies the operations.

  23. AND 0, Sum Big 1200
    Count arrays of \( n \) numbers from 0 to \( 2^k - 1 \): AND of all is 0, sum is as big as possible. Print it modulo \( 10^9+7 \).
    Answer

    Tool: bits + modular arithmetic. Signal: AND, \( 2^k \) and "modulo". Idea: each bit is 0 in exactly one element: \( n \) choices per bit, so \( n^k \bmod (10^9+7) \).

Pocket version

The short form of this page. Copy it on one card and keep it next to you.

Routine — every problem

  1. Limits → allowed cost (\( 10^8 \) steps per second).
  2. The task in one sentence.
  3. Samples by hand.
  4. Kind of answer: yes/no, count, min/max, build, queries.
  5. Brute force and its cost. Fits? Code it.
  6. Too slow? What is repeated? Remove it with a tool.
  7. Edge cases and long long, then submit.

12 strong signals

  • \( n \le 20 \) → try all subsets (mask).
  • \( n \le 5000 \) → \( O(n^2) \) is fine.
  • \( n \le 2 \cdot 10^5 \) → sort, one loop, \( O(n \log n) \).
  • Values up to \( 10^{12} \) → \( \sqrt{n} \) loop; up to \( 10^{18} \) → formula or \( \log \); long long.
  • Many "sum \( l..r \)" queries → prefix sums.
  • Longest window with sum \( \le S \) → two pointers.
  • "Min value that works", monotonic → binary search on the answer.
  • Only frequencies matter → counting.
  • Order does not matter → sort first.
  • "Modulo \( 10^9+7 \)", count ways → DP or C(n, k).
  • Fewest moves, equal cost → BFS; weights → Dijkstra.
  • "Print any" → constructive: solve tiny \( n \) by hand.
