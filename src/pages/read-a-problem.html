Most wrong answers come from reading too fast. Use the same reading steps for every problem.

The routine

  1. Read the limits first. Look at the constraints, the time limit and the memory limit. They tell you how fast your code must be.
  2. Read the story. Then say the task in one sentence, in your own words.
  3. Read the Input and Output parts. What do you read? What exactly do you print?
  4. Run the samples by hand. Use paper. Get the same answers as the statement.
  5. Read the Note. It is at the end. It often explains the samples.
  6. Look for trap words. See the table below.

Do not write code before step 4 works. If your hand answer is different, you did not understand the task yet.

Example: problem 4A

The task in short

Two friends have one watermelon. It weighs w kilos (1 ≤ w ≤ 100). They cut it into two parts. Each part must weigh an even number of kilos. The parts can be different. Print YES if this is possible, else NO.

StepWhat you find
Limitsw ≤ 100. Very small. Any solution is fast enough.
One sentence"Can I write w as even + even?"
Sample by handw = 8 → 2 + 6 → YES.
TrapEach part must be more than 0. So w = 2 is only 1 + 1 → NO.
OutputThe word YES or NO.

Now the answer is easy: YES when w is even and w > 2.

Trap words

WordMeaning
distinctAll different. No two are equal.
at least k / at most k≥ k / ≤ k. Not > and not <.
subarray, substringA part with no gaps: [3, 4, 5] inside [2, 3, 4, 5, 6].
subsequenceSame order, but gaps are allowed: [2, 4, 6] inside [2, 3, 4, 5, 6].
permutationThe numbers 1…n, each one time: [3, 1, 2].
"print any valid answer"Many answers are correct. Yours can differ from the sample.
1-indexedThe statement counts from 1. Your C++ array counts from 0.
non-negative / positive≥ 0 / > 0. Zero is not positive.

Many test cases

Many problems begin with a number t. It is the number of test cases in one input. You solve the task t times and print t answers.

Then you often see this line: "the sum of n over all test cases does not exceed 2·105".

It means: add the n of every test case. The total is at most 2·105. So all the tests together are like one test with n = 2·105. You do not multiply by t.

If this line is missing, the worst case is t × n. Count your steps with that number.

Common mistakes

  • You skip the limits. Then you write a solution that is too slow.
  • You print "Yes" when the statement asks for "YES". Copy the word from the statement.
  • You forget to read t, or you forget to clear your variables between test cases.
  • You see a different answer in the sample and think you are wrong. Check for "print any".
