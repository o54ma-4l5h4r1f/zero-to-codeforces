A few small formulas replace a long loop. Learn them once and many 800 problems become one line.

Spot it

  • The numbers go up to 109 or 1018. A loop is too slow, so there must be a formula.
  • The statement talks about even and odd, or divisible numbers, or digits.
  • "How many boxes / buses / steps do you need at least?" This is division that rounds up.
  • "Find the sum 1 + 2 + … + n" or "how many numbers from l to r are…".

Three ways to understand it

1 · Story — the buses

10 people go on a trip. One bus takes 4 people. In C++, 10 / 4 is 2: integer division throws away the rest (rounds down). But 2 buses leave 2 people on the street.

You need to round up: 3 buses. The trick is (10 + 4 - 1) / 4 = 13 / 4 = 3. In general: (a + b - 1) / b.

2 · Picture — take a number apart

x % 10 is the last digit. x / 10 removes the last digit. Repeat until nothing is left. Example: the sum of the digits of 4072.

The third sum is called an arithmetic progression. abs is the absolute value: the number without its minus sign.

3 · Code — small helpers


long long ceilDiv(long long a, long long b) {      // a / b rounded up (a >= 0, b > 0)
    return (a + b - 1) / b;
}

long long sumTo(long long n) {                     // 1 + 2 + ... + n
    return n * (n + 1) / 2;
}

long long multiples(long long l, long long r, long long k) {   // in [l..r], l >= 1
    return r / k - (l - 1) / k;
}

The digits loop from the picture, as a full program:


#include <bits/stdc++.h>
using namespace std;

int main() {
    long long x;
    cin >> x;                  // x >= 1
    int sum = 0, digits = 0;
    while (x > 0) {
        sum += x % 10;         // take the last digit
        digits++;
        x /= 10;               // remove the last digit
    }
    cout << sum << " " << digits << "\n";    // 4072 -> 13 4
}

Speed: a formula is O(1). The digits loop is O(number of digits): at most 19 turns for a long long.

Common mistakes

  • n * (n + 1) / 2 with int n can overflow: it overflows when n is above about 46 000. Use long long when n can pass 104.
  • % with a negative number gives a negative remainder: -7 % 2 is -1. Test odd with x % 2 != 0, not == 1.
  • You use double and ceil(a / b). With big numbers it loses digits. Stay with integers and (a + b - 1) / b.
  • The digits loop does nothing for x = 0. If 0 is a possible input, handle it alone.
