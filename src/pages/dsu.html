Keep items in groups. Each group has one leader. Two fast operations: "who is the leader of x?" and "join these two groups".

Optional at this level. You do not need DSU below 1600. It is one of the last three lessons of Stage 3. Read them in any order, when a problem needs one. To count groups, DFS from Graphs: BFS and DFS is enough.

Before this lesson

  • You know vertices, edges and connected components → Graphs: BFS and DFS
  • You can read a function that calls itself and returns a value → Recursion and backtracking

Spot it

  • Things are joined step by step: roads are built, friends are added. Nothing is ever removed.
  • The question is "are a and b in the same group?" or "how many groups are there now?"
  • You must print the number of groups, or the biggest group, after every new edge.
  • You must know if a new edge closes a cycle.

Three ways to understand it

1 · Story — teams with one leader

Each person has one boss. The top boss of a team is its leader. A leader is his own boss.

"Are Ali and Sara in the same team?" Ask Ali "who is your boss?", then ask that boss, and go up. Do the same for Sara. If you reach the same leader, they are in the same team.

Two teams join: the leader of the smaller team gets a boss, the leader of the bigger team.

2 · Picture — arrows to the boss

The array parent[x] holds the boss of x. In the picture it is an arrow from x to its boss. Only a leader has no arrow, and it shows the size of its group. find(x) follows the arrows up to the leader. unite(a, b) joins two groups.

Path compression keeps the arrows short. Without the size rule, a long chain can appear. Watch one find make it flat.

3 · Code — three small functions you can reuse

Items are numbered 1 to n. sz[x] is the size of the group, and it is correct only when x is a leader. The two arrays are global, as in Graphs. Call init(n) at the start of every test.


vector<int> parent, sz;                     // sz[leader] = size of its group

void init(int n) {
    parent.assign(n + 1, 0);
    sz.assign(n + 1, 1);
    for (int i = 0; i <= n; i++) parent[i] = i;   // everybody is alone
}

int find(int x) {                           // the leader of x
    if (parent[x] == x) return x;
    return parent[x] = find(parent[x]);     // path compression
}

bool unite(int a, int b) {                  // false = they were already together
    a = find(a);
    b = find(b);
    if (a == b) return false;
    if (sz[a] < sz[b]) swap(a, b);          // a is the bigger group
    parent[b] = a;                          // small group goes under the big one
    sz[a] += sz[b];
    return true;
}

The line return parent[x] = find(parent[x]); does two things. It stores the leader in parent[x], and it returns that leader.

Change it to fit

The three functions above are the DEFAULT. Never change them. Each problem changes only the few lines in main.

  • Count the groups. Start with groups = n. Every unite that returns true makes one group less. 
    
if (unite(a, b)) groups--;
  • The size of the group of x. Read the size at the leader only. 
    
int size = sz[find(x)];
  • Does the new edge close a cycle? If unite returns false, a and b were already connected. So the new edge closes a cycle. 
    
if (!unite(a, b)) cycle = true;
  • "Are a and b connected?" Compare the leaders. 
    
if (find(a) == find(b)) cout << "YES\n";
else cout << "NO\n";

Solve one together

Problem. There are \( n \) cities and no roads. Then \( m \) roads are built, one by one. After each road, print two numbers: the number of groups of connected cities, and the size of the biggest group. Limits: \( 1 \le n \le 10^5 \) and \( 1 \le m \le 2 \cdot 10^5 \).

  1. What is asked? Two numbers after every road. Roads are only added, never removed. That is the signal for DSU.
  2. A small example by hand. Take \( n = 5 \) and the roads 1-2, 1-3, 4-5, 2-3.
    roadgroupsgroups afterbiggest
    1-2{1,2} {3} {4} {5}42
    1-3{1,2,3} {4} {5}33
    4-5{1,2,3} {4,5}23
    2-3nothing changes: a cycle23
  3. The idea. Keep groups, starting at \( n \). When unite returns true, do groups--. Groups only grow, they never shrink. So the biggest size never goes down. After a real join, compare the new size with best.
  4. Why is it fast enough? Each road is one unite, which is almost one step. So the work is about \[ n + m = 3 \cdot 10^5 \text{ steps} \]

    That is far below \( 10^8 \). Running BFS again after every road would cost \( m \cdot (n + m) \approx 6 \cdot 10^{10} \) steps: too slow.


#include <bits/stdc++.h>
using namespace std;

vector<int> parent, sz;                     // the same functions as above

void init(int n) {
    parent.assign(n + 1, 0);
    sz.assign(n + 1, 1);
    for (int i = 0; i <= n; i++) parent[i] = i;
}

int find(int x) {
    if (parent[x] == x) return x;
    return parent[x] = find(parent[x]);
}

bool unite(int a, int b) {
    a = find(a);
    b = find(b);
    if (a == b) return false;
    if (sz[a] < sz[b]) swap(a, b);
    parent[b] = a;
    sz[a] += sz[b];
    return true;
}

int main() {
    int n, m;
    cin >> n >> m;
    init(n);
    int groups = n, best = 1;               // n cities, all alone
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        if (unite(a, b)) {                  // a real join: one group less
            groups--;
            best = max(best, sz[find(a)]);
        }
        cout << groups << " " << best << "\n";
    }
}

Speed: almost \( O(1) \) for each find and unite, on average over many calls. This is a safe estimate, not an exact law. The true cost grows, but so slowly that you can treat it as a small constant.

Wrong ideas people get

  • You may think: The value parent[x] is the leader of x.

    The truth: Not always. In the picture parent[4] is 3, but the leader is 1. Always compare find(a) == find(b).

  • You may think: DSU can remove an edge, or split a group in two.

    The truth: It cannot. After a join, the two groups stay joined for ever. If the problem removes edges, plain DSU does not fit (see "Not now").

  • You may think: The size rule and path compression are extras. The code is fast without them.

    The truth: Without them a chain of length n can appear. Then one find walks n steps. Keep both. They cost two lines.

Common mistakes

  • Writing parent[a] = b in unite. Join the leaders: first a = find(a); b = find(b);.
  • Reading sz[x] for any x. The size is correct only at the leader: sz[find(x)].
  • Items 1 to n but init(n - 1), or no init in a new test case. Call init(n) at the start of each test.

Not now

  • The cheapest roads that connect all cities (Kruskal, minimum spanning tree). It is sorting plus this DSU. It is rare below 1600: After 1600.
  • Removing edges (reading the operations from the end, or "DSU with rollback"). These are harder tricks: After 1600.

Check yourself

  1. The parent values of items 1 to 4 are 1, 1, 2, 3. What is find(4)? What is parent after it?
    Answer

    find(4) walks 4 → 3 → 2 → 1, so it returns 1. Path compression makes parent = 1, 1, 1, 1.

  2. You add the edges 1-2, then 2-3, then 3-1. Which edge closes a cycle? What does unite return for it?
    Answer

    The edge 3-1. Items 3 and 1 already have the same leader, so unite returns false.

  3. You have 10 items. Four unite calls returned true. How many groups are there now?
    Answer

    \( 10 - 4 = 6 \). Each real join makes one group less.
