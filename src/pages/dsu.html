Keep items in groups. Two fast operations: "which group is x in?" and "join these two groups into one".

Spot it

  • Things are joined step by step: roads are built, friends are added, groups merge. Nothing is ever removed.
  • The question is "are a and b in the same group?" or "how many groups are there now?"
  • You must count the connected components of a graph, or find the size of each one.
  • You must know if a new edge makes a cycle.

Three ways to understand it

1 · Story — companies and bosses

There are n small companies. Each company has one person, and this person is the boss. Sometimes two companies join. Then the boss of the smaller company gets a new boss: the boss of the bigger company.

"Are Ali and Sara in the same company?" Ask Ali: "who is your boss?" Then ask that boss, and go up until you reach the top boss. Do the same for Sara. Same top boss → same company. The top boss is the leader of the group.

find(x) = the top boss of x. unite(a, b) = join the two companies.

2 · Picture — the parent array for 5 items

parent[x] is the boss of x. A leader is its own boss: parent[x] == x. At the start everybody is alone.

unite(2, 4) does not join 2 and 4. It joins their leaders: 1 and 3. So leader 3 gets the boss 1.

Path compression: find(4) walks 4 → 3 → 1. On the way back it sets parent[4] = 1. Next time the walk is one step. This small trick makes DSU very fast.

3 · Code — a small struct you can reuse


struct DSU {
    vector<int> parent, sz;                 // sz[leader] = size of its group
    DSU(int n) : parent(n + 1), sz(n + 1, 1) {
        for (int i = 0; i <= n; i++) parent[i] = i;   // everybody is alone
    }
    int find(int x) {                       // the leader of x
        if (parent[x] == x) return x;
        return parent[x] = find(parent[x]); // path compression
    }
    bool unite(int a, int b) {              // false = they were already together
        a = find(a); b = find(b);
        if (a == b) return false;
        if (sz[a] < sz[b]) swap(a, b);      // a is the bigger group
        parent[b] = a;                      // small group goes under the big one
        sz[a] += sz[b];
        return true;
    }
};

A full program. Input: n cities, m roads, then q questions "can you go from a to b?".


#include <bits/stdc++.h>
using namespace std;

struct DSU {                                // the same struct as above
    vector<int> parent, sz;
    DSU(int n) : parent(n + 1), sz(n + 1, 1) {
        for (int i = 0; i <= n; i++) parent[i] = i;
    }
    int find(int x) { return parent[x] == x ? x : parent[x] = find(parent[x]); }
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;
        if (sz[a] < sz[b]) swap(a, b);
        parent[b] = a; sz[a] += sz[b];
        return true;
    }
};

int main() {
    int n, m;
    cin >> n >> m;
    DSU d(n);
    int groups = n;                         // n cities, all alone
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        if (d.unite(a, b)) groups--;        // a real merge: one group less
    }
    cout << groups << "\n";                 // number of connected components
    int q;
    cin >> q;
    while (q--) {
        int a, b;
        cin >> a >> b;
        cout << (d.find(a) == d.find(b) ? "YES" : "NO") << "\n";
    }
}

Cycle check: if unite(a, b) returns false, then a and b were already connected. So the new edge a–b closes a cycle. The size of the group of x is d.sz[d.find(x)].

Speed: almost O(1) for each find and unite. 106 operations are no problem.

Common mistakes

  • Comparing parent[a] == parent[b]. The parent is not always the leader. Compare find(a) == find(b).
  • Writing parent[a] = b in unite. You must join the leaders: parent[find(b)] = find(a).
  • Reading sz[x] for any x. The size is correct only at the leader: sz[find(x)].
  • Edges are removed in the problem. DSU cannot split a group. Try to read the operations from the end, so each removal becomes an add.
