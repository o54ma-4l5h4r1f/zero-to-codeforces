Solve the small problems first and write down their answers. Build each bigger answer from the answers you already have.

Spot it

  • The statement asks to count the ways (often "modulo 109+7"), or for the minimum / maximum over many choices.
  • You make choices one after another, and each choice changes what you can do next.
  • Greedy fails on a small example, and trying everything is too slow (n is 1000 or 105).
  • The answer for n is easy if you already know the answers for smaller n.

Three ways to understand it

1 · Story — climbing stairs

You climb stairs. Each move is 1 step or 2 steps up. In how many ways can you reach step n?

Think about your last move. You come to step n from step n−1 or from step n−2. So ways(n) = ways(n−1) + ways(n−2).

Now walk up and write the answer on every step with chalk. For a new step you only read the two numbers below it. You never count again. This is dynamic programming (DP).

2 · Picture — fill the table from left to right

Stairs: dp[i] = number of ways to reach step i. Each cell = the sum of the two cells before it.

i0123456
dp[i]11235813

dp[6] = dp[5] + dp[4] = 8 + 5 = 13. dp[0] = 1: there is one way to stay on the floor (do nothing).

Min coins: coins are 1, 3 and 4. dp[x] = the smallest number of coins with sum x. Try each coin as the last coin: dp[x] = 1 + min(dp[x−1], dp[x−3], dp[x−4]).

x0123456
dp[x]0121122

dp[6] = 1 + min(dp[5], dp[3], dp[2]) = 1 + min(2, 1, 2) = 2, that is 3 + 3. Greedy takes 4 first and gets 4 + 1 + 1 = 3 coins. DP checks every last coin, so it is never wrong.

3 · Code — stairs

The answer grows very fast, so problems ask for it modulo 109+7.


#include <bits/stdc++.h>
using namespace std;

const int MOD = 1000000007;

int main() {
    int n;
    cin >> n;
    vector<long long> dp(n + 2);
    dp[0] = 1;                                   // base cases
    dp[1] = 1;
    for (int i = 2; i <= n; i++)
        dp[i] = (dp[i - 1] + dp[i - 2]) % MOD;   // last move: 1 step or 2 steps
    cout << dp[n] << "\n";                       // the answer is on step n
}

The recipe: 4 questions

Answer these on paper before you write code. Every DP problem is these four answers.

QuestionStairsMin coins
1. What does dp[i] mean, in words? (the state)ways to reach step ifewest coins with sum x
2. The formula from smaller answers? (the transition)dp[i] = dp[i−1] + dp[i−2]dp[x] = 1 + min(dp[x−c])
3. The base cases?dp[0] = dp[1] = 1dp[0] = 0, others = ∞
4. The order of filling? Where is the answer?i from 2 up; answer dp[n]x from 1 up; answer dp[sum]

Stuck on question 2? Ask: "What was the last choice?" Last move, last coin, last item. Each possible last choice gives one smaller subproblem.

Second example — 0/1 knapsack

n items, item i has weight w and value v. The bag holds weight W. Each item is used at most once. Find the best total value. This is the knapsack problem.

dp[c] = the best value with total weight ≤ c, using the items seen so far. For a new item: skip it (dp[c] stays) or take it (dp[c − w] + v).


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, W;
    cin >> n >> W;
    vector<long long> dp(W + 1, 0);          // no items yet: value 0
    for (int i = 0; i < n; i++) {
        int w;
        long long v;
        cin >> w >> v;
        for (int c = W; c >= w; c--)          // backwards: use each item once
            dp[c] = max(dp[c], dp[c - w] + v);
    }
    cout << dp[W] << "\n";
}

Why backwards? Going down, dp[c − w] is still the old value, without this item. Going up, you can take the same item two times.

Classic patterns

Patterndp meansFormula
Count ways (stairs)dp[i] = ways to reach idp[i] = dp[i−1] + dp[i−2]
Min coinsdp[x] = fewest coins for sum xdp[x] = 1 + min(dp[x−c]) over coins c
Take or skip (no two adjacent)dp[i] = best sum in the first i itemsdp[i] = max(dp[i−1], dp[i−2] + a[i])
Paths in a grid (right / down)dp[i][j] = ways to reach cell (i, j)dp[i][j] = dp[i−1][j] + dp[i][j−1]
Knapsackdp[c] = best value with weight ≤ cdp[c] = max(dp[c], dp[c−w] + v), c backwards
LIS, O(n²) (longest increasing subsequence)dp[i] = longest one that ends at idp[i] = 1 + max(dp[j]) for j < i, a[j] < a[i]
LCS (longest common subsequence)dp[i][j] = answer for first i of s, first j of tsame letters: dp[i−1][j−1] + 1; else max(dp[i−1][j], dp[i][j−1])

Two styles. Bottom-up: fill the table with loops, small to big, like the code above. Top-down: write the recursion and store each answer the first time you compute it (memoisation). Both give the same answer; use the one that is easier for you.

Speed: (number of states) × (work for one state). Stairs O(n). Min coins O(sum × coins). Knapsack O(n × W). LIS O(n²).

Common mistakes

  • You start coding before you can say in words what dp[i] means. Write that sentence first.
  • Wrong or missing base case, or reading outside the array: dp[i − 2] when i = 1.
  • Wrong order: you use a cell that is not filled yet. In 0/1 knapsack the weight loop must go backwards.
  • Forgetting % MOD or using int for big sums. For "minimum", start with a big value, not 0.
