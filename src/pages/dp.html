Solve the small problems first and write down their answers. Build each bigger answer from the answers you already have.

Before this lesson

  • You can solve a problem with a smaller copy of itself → Recursion and backtracking
  • You saw that greedy can fail on a small example → Greedy
  • You can print an answer "modulo \( 10^9 + 7 \)" → Mod and fast power

Spot it

  • The statement asks to count the ways, often "modulo \( 10^9 + 7 \)".
  • It asks for the minimum or maximum over many choices made one after another.
  • Greedy fails on a small example, and trying everything is too slow. Here \( n \) is 1000 or \( 10^5 \), not 20.
  • The answer for \( n \) is easy if you already know the answers for smaller \( n \).

Three ways to understand it

1 · Story — climbing stairs

You climb stairs. Each move goes 1 step or 2 steps up. In how many ways can you reach step 6?

Think about your last move. You come to step 6 from step 5 or from step 4. So the ways to 6 = the ways to 5 + the ways to 4.

Walk up and write the answer on every step with chalk. For a new step you read only the two numbers below it. You never count again. This is dynamic programming (DP).

2 · Picture — fill the table from left to right

dp[i] = the number of ways to reach step i. Each cell reads the two cells before it.

Minimum coins, the same way. Coins are 1, 3 and 4. dp[x] = the fewest coins with sum x. Try each coin as the last coin. For \( x = 6 \): \( 1 + \min(dp_5, dp_3, dp_2) = 1 + \min(2, 1, 2) = 2 \), that is 3 + 3.

3 · Code — four questions, then the loop

Answer these on paper before you write code. Every DP is these four answers.

QuestionStairs
1. What does dp[i] mean, in words? This is the state.ways to reach step i
2. How is it built from smaller answers? This is the transition.dp[i] = dp[i-1] + dp[i-2]
3. The base cases?dp[0] = 1, dp[1] = 1
4. The order of filling? Where is the answer?i from 2 up; answer dp[n]

Stuck on question 2? Ask: "What was the last choice?" The last move, the last coin, the last item. Each possible last choice gives one smaller subproblem.


#include <bits/stdc++.h>
using namespace std;

const int MOD = 1000000007;

int main() {
    int n;
    cin >> n;
    vector<long long> dp(n + 2);             // 1. dp[i] = ways to reach step i
    dp[0] = 1;                               // 3. base cases
    dp[1] = 1;
    for (int i = 2; i <= n; i++)             // 4. small to big
        dp[i] = (dp[i - 1] + dp[i - 2]) % MOD;   // 2. last move: 1 step or 2 steps
    cout << dp[n] << "\n";                   // 4. the answer is on step n
}

The number of ways grows very fast, so the problem asks for it modulo \( 10^9 + 7 \).

Change it to fit

Default: fill the table with loops, from small to big, as above. The four questions stay. Only their answers change.

Count ways → minimum → maximum

Now every step i has a price cost[i] or a gift gain[i]. One line changes: the + becomes min or max. The base case changes with it.


dp[i] = dp[i - 1] + dp[i - 2];                  // count ways:    dp[0] = 1
dp[i] = min(dp[i - 1], dp[i - 2]) + cost[i];    // cheapest way:  dp[0] = 0
dp[i] = max(dp[i - 1], dp[i - 2]) + gain[i];    // richest way:   dp[0] = 0

For "minimum", a cell you cannot reach must start big (like 1e9), not 0. For "maximum", it starts very small.

One number → two numbers in the state (a grid)

You walk in a grid from the top-left cell. Each move goes right or down. dp[i][j] = the number of paths to cell (i, j). The last move came from above or from the left.

A wall in a cell? Write if (grid[i][j] == '#') dp[i][j] = 0; No path goes through it.

Take or skip each item (0/1 knapsack)

There are \( n \) items. Item i has a weight and a value. The bag holds weight W. Each item is used at most once. Find the best total value. This is the knapsack problem.

dp[c] = the best value with total weight at most c, using the items read so far. A new item: skip it (dp[c] stays) or take it (dp[c - w] + v).

Why does the weight loop go down? Look at one item with weight 2 and value 3, and a bag of 4.


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, W;
    cin >> n >> W;
    vector<long long> dp(W + 1, 0);          // no items yet: value 0
    for (int i = 0; i < n; i++) {
        int w;
        long long v;
        cin >> w >> v;
        for (int c = W; c >= w; c--)          // DOWN: each item at most once
            dp[c] = max(dp[c], dp[c - w] + v);   // skip it, or take it
    }
    cout << dp[W] << "\n";
}

The classic patterns

Here \( dp_i \) means dp[i] and \( dp_{i,j} \) means dp[i][j].

PatternThe state meansTransition
Count ways (stairs)ways to reach step \( i \)\( dp_i = dp_{i-1} + dp_{i-2} \)

Which one do I use: loops or recursion?

Use loops (bottom-up), as on this page. You can also write the recursion and store each answer the first time you get it. That is top-down, or memoisation. Both give the same table. Use top-down only when the order of filling is hard to see.

Solve one together

Problem. There are \( n \) stones in a row with heights \( h_1, \dots, h_n \). A frog starts on stone 1. It jumps to the next stone or over one stone. A jump from height 10 to height 30 costs \( |10 - 30| = 20 \): the bars mean "without the minus sign". Find the smallest total cost to reach stone \( n \). Limits: \( 2 \le n \le 10^5 \), \( 1 \le h_i \le 10^4 \).

  1. What is asked? A minimum over many choices of jumps. Greedy "take the cheaper next jump" can fail. So we use DP. We answer the four questions on paper first. In the code, stones are numbered from 0.
  2. Question 1, the state. dp[i] = the smallest cost to reach stone i.
  3. Question 2, the transition. The last jump came from stone i-1 or from stone i-2. Take the cheaper one: \[ dp_i = \min(dp_{i-1} + |h_i - h_{i-1}|,\ dp_{i-2} + |h_i - h_{i-2}|) \]
  4. Questions 3 and 4. Base: dp[0] = 0, and dp[1] = |h[1] - h[0]| (only one way). Order: i from 2 up. The answer is dp[n-1].
  5. A small example by hand. Heights 10, 30, 40, 20.
    stone0123
    height10304020
    dp020\( \min(20 + 10, 0 + 30) = 30 \)\( \min(30 + 20, 20 + 10) = 30 \)

    The answer is 30: stone 0 → 1 → 3 costs \( 20 + 10 \).

  6. Why is it fast enough? There are \( n \) cells, and each one reads 2 cells. That is about \( 2 \cdot 10^5 \) steps. Far below \( 10^8 \).

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<int> h(n);
    for (int i = 0; i < n; i++) cin >> h[i];
    vector<long long> dp(n);                  // dp[i] = cheapest cost to reach stone i
    dp[0] = 0;                                // base cases
    dp[1] = abs(h[1] - h[0]);
    for (int i = 2; i < n; i++)               // small to big
        dp[i] = min(dp[i - 1] + abs(h[i] - h[i - 1]),    // last jump: 1 stone
                    dp[i - 2] + abs(h[i] - h[i - 2]));   // last jump: 2 stones
    cout << dp[n - 1] << "\n";
}

Speed: (number of cells) \( \times \) (work for one cell). Stairs and the frog \( O(n) \). Min coins \( O(\text{sum} \cdot \text{coins}) \). Knapsack \( O(n \cdot W) \).

Wrong ideas people get

  • You may think: DP is a list of formulas to learn by heart.

    The truth: DP is four answers you find for each new problem: state, transition, base case, order. The patterns table shows examples, not rules.

  • You may think: dp[i] is always the answer for the i-th element.

    The truth: dp[i] is whatever YOU define in question 1. In min coins, x is a sum, not the number of an element.

  • You may think: Greedy is a kind of DP.

    The truth: Greedy takes one choice and never looks back. DP tries every last choice. With coins 1, 3, 4 and sum 6, greedy uses 3 coins and DP uses 2.

Common mistakes

  • You read outside the array: dp[i - 2] when i = 1. Fill the base cases first and start the loop after them.
  • For a minimum, the table starts with 0. Then 0 always wins. Start with a big value like 1e9.
  • You forget % MOD, or you use int for big sums. Use long long.

Not now

  • Bitmask DP (the state is a set of items, \( n \le 20 \)). It needs this page to feel easy first. Come back after 1600.
  • DP on trees (an answer for every subtree). Same idea, harder order. See After 1600.
  • Making a DP faster (less memory, fewer cells). Most problems up to 1600 do not need it. See After 1600.

Check yourself

  1. Stairs where a move goes 1, 2 or 3 steps up. What is dp[4]?
    Answer

    7. The table is 1, 1, 2, 4, 7. Each cell is the sum of the three cells before it: \( 4 + 2 + 1 = 7 \).

  2. Coins 1, 5, 6 and sum 10. How many coins does greedy use? How many does DP use?
    Answer

    Greedy: 6 + 1 + 1 + 1 + 1, so 5 coins. DP: 5 + 5, so 2 coins.

  3. In 0/1 knapsack, what goes wrong if the weight loop goes up, from w to W?
    Answer

    A cell can read a cell that already holds the same item. So one item can be taken two or more times.
