Cut the search area in half again and again. You find the answer in about 30 steps, even inside a billion numbers.

Spot it

  • The array is sorted and you must find a value or a position.
  • The statement asks for the minimum or maximum value that still works.
  • If a value x works, then every bigger value also works (or every smaller one). This is called monotonic.
  • The answer can be up to 109 or 1018, so you cannot try every value.

Three ways to understand it

1 · Story — the guessing game

I think of a number from 1 to 100. After each guess I say "too small" or "too big".

A bad player says 1, 2, 3, 4… A good player says 50. "Too big." Now only 1–49 is left. Then 25. Each guess throws away half of the numbers. 100 → 50 → 25 → 12 → 6 → 3 → 1. Only 7 guesses.

2 · Picture — find the first number ≥ 7

Ask one yes/no question for every position: "is a[i] ≥ 7?" In a sorted array the answers look like no no no yes yes yes. We look for the first yes.

3 · Code — one template for everything

Write a function ok(x) that answers the yes/no question. The loop never changes.


bool ok(long long x);          // you write this: no no no YES YES YES

long long firstYes(long long lo, long long hi) {
    // lo = a value where ok is false (or one step before the range)
    // hi = a value where ok is true  (or one step after the range)
    while (hi - lo > 1) {
        long long mid = lo + (hi - lo) / 2;   // the middle, safe from overflow
        if (ok(mid)) hi = mid;                // mid is a yes -> answer is mid or left of it
        else         lo = mid;                // mid is a no  -> answer is right of it
    }
    return hi;                                // the first yes
}

For a sorted vector, C++ already has it:


int i = lower_bound(a.begin(), a.end(), x) - a.begin();  // first index with a[i] >= x
int j = upper_bound(a.begin(), a.end(), x) - a.begin();  // first index with a[i] >  x
// j - i = how many times x is in the array

Binary search on the answer

This is the trick that solves many 1200–1600 problems. You do not search in an array. You search in the answers.

Example — n machines, machine i makes one item every t[i] seconds. What is the smallest time to make k items?

Hard question: "what is the best time?" Easy question: "is time T enough?" Just count: in time T machine i makes T / t[i] items.

If T is enough, then T+1 is also enough → no no no yes yes yes → find the first yes.


#include <bits/stdc++.h>
using namespace std;

int n; long long k;
vector<long long> t;

bool ok(long long T) {                 // can we make k items in T seconds?
    long long made = 0;
    for (int i = 0; i < n; i++) {
        made += T / t[i];
        if (made >= k) return true;    // stop early, so "made" never overflows
    }
    return false;
}

int main() {
    cin >> n >> k;
    t.resize(n);
    for (auto &x : t) cin >> x;
    long long lo = 0;                                     // 0 seconds: not enough
    long long hi = *min_element(t.begin(), t.end()) * k;  // fastest machine alone: enough
    while (hi - lo > 1) {
        long long mid = lo + (hi - lo) / 2;
        if (ok(mid)) hi = mid; else lo = mid;
    }
    cout << hi << "\n";
}

Looking for the last yes (pattern yes yes yes no no no)? Keep lo on a yes and hi on a no, swap the two lines inside the if, and return lo.

Speed: O(log n) steps. For answers up to 10^18 that is about 60 steps. Total = 60 × (cost of ok).

Common mistakes

  • The array is not sorted. Binary search on an unsorted array gives a wrong answer.
  • ok is not monotonic. Check it: can a "yes" come before a "no"? Then this tool does not fit.
  • (lo + hi) / 2 can overflow. Write lo + (hi - lo) / 2 and use long long.
  • Wrong start: lo must really be a "no" and hi must really be a "yes". If you are not sure, make hi bigger.
