Cut the search area in half again and again. About 30 steps are enough for a billion numbers.

Spot it

  • The array is sorted. You must find a value or a position in it.
  • The statement asks for the minimum or maximum value that still works.
  • If a value x works, then every bigger value also works (or every smaller one). This is called monotonic.
  • The answer can be as big as \( 10^9 \) or \( 10^{18} \). You cannot try every value.

Three ways to understand it

1 · Story — the guessing game

I think of a number from 1 to 100. After each guess I say "too small" or "too big".

A bad player says 1, 2, 3, 4… A good player says 50. I say "too big". Now only 1 to 49 is left.

Each guess throws away half of the numbers. 100 → 50 → 25 → 12 → 6 → 3 → 1. Only 7 guesses.

2 · Picture — find the first number that is 7 or more

Ask one yes/no question for every position: "is a[i] >= 7?"

i0123456
a[i]13478912
a[i] >= 7 ?nononoyesyesyesyes

In a sorted array all the "no" answers come first, then all the "yes" answers. We look for the first yes.

Keep two positions. lo always stands on a "no". hi always stands on a "yes". Look at the middle and move one of them.

Why start at -1 and 7? They are one step outside the array. We pretend that -1 is a "no" and 7 is a "yes". The code never reads a[-1] or a[7], because mid is always between them.

3 · Code — one template for everything

You write a function ok(x). It answers the yes/no question for one value. The loop never changes.


bool ok(long long x);          // only says that ok exists; you write its body

long long firstYes(long long lo, long long hi) {
    // lo = a value where ok is false (or one step before the range)
    // hi = a value where ok is true  (or one step after the range)
    while (hi - lo > 1) {
        long long mid = lo + (hi - lo) / 2;   // the middle, safe from overflow
        if (ok(mid)) hi = mid;                // mid is a yes -> answer is mid or left of it
        else         lo = mid;                // mid is a no  -> answer is right of it
    }
    return hi;                                // the first yes
}

For "find a value in a sorted vector", C++ already has this loop:


int i = lower_bound(a.begin(), a.end(), x) - a.begin();  // first index with a[i] >= x
int j = upper_bound(a.begin(), a.end(), x) - a.begin();  // first index with a[i] >  x
// j - i = how many times x is in the array

lower_bound gives a place (an iterator), not a number. - a.begin() turns the place into an index. If every value is smaller than x, it returns a.end(), so i == n. Check i < n before you read a[i]. More: C++ reference, part "Iterators".

Which one do I use? Searching for a value in a sorted vector: use lower_bound. Everything else: use the template with ok.

Binary search on the answer

This idea solves many 1200–1600 problems. You do not search in an array. You search among the possible answers.

The hard question is "what is the smallest value that works?" The easy question is "does this one value work?" Are the easy answers no no no yes yes yes? Then the template finds the first yes.

Do you need the last yes (yes yes yes no no no)? Keep lo on a yes and hi on a no. Swap the two lines inside the if. Return lo.

Solve one together

Problem. There are \( n \) machines. Machine \( i \) makes one item every \( t_i \) seconds. All machines work at the same time. What is the smallest time to make \( k \) items? Limits: \( 1 \le n \le 2 \cdot 10^5 \) and \( 1 \le k, t_i \le 10^9 \).

  1. What is asked? The smallest time \( T \). In \( T \) seconds, all machines together must make at least \( k \) items.
  2. A small example by hand. Take times 3, 2, 5 and \( k = 7 \). In 8 seconds the first machine makes 2 items, because \( 8 / 3 = 2.66 \) and we round down. We write "round down" as \( \lfloor 8 / 3 \rfloor = 2 \).
    T56789
    items made1+2+1 = 42+3+1 = 62+3+1 = 62+4+1 = 73+4+1 = 8
    at least 7 ?nononoyesyes

    The answer is 8.

  3. The idea. More time never makes fewer items. So the answers are no no no yes yes yes. We search for the first yes. ok(T) adds the items of all machines and checks: \[ \lfloor T / t_1 \rfloor + \lfloor T / t_2 \rfloor + \dots + \lfloor T / t_n \rfloor \ge k \]

    Start: lo = 0 is a "no", because 0 seconds make 0 items. For hi, let the fastest machine work alone. It needs \( k \cdot \min(t_i) \) seconds. That is a "yes".

    Watch the search on the small example: times 3, 2, 5 and \( k = 7 \). Here hi starts at \( 7 \cdot 2 = 14 \).

    In the code, n, k and t are global, so ok can read them. With many test cases, fill them again in every test.

  4. Why is it fast enough? The biggest hi is \( 10^9 \cdot 10^9 = 10^{18} \). It fits in long long. Cutting \( 10^{18} \) in half takes about 60 steps. Each step runs ok, which is one loop over \( n \) machines. \[ 60 \cdot 2 \cdot 10^5 = 1.2 \cdot 10^7 \text{ steps} \]

    That is far below \( 10^8 \).


#include <bits/stdc++.h>
using namespace std;

int n; long long k;                    // global, so ok() can read them
vector<long long> t;

bool ok(long long T) {                 // can we make k items in T seconds?
    long long made = 0;
    for (int i = 0; i < n; i++) {
        made += T / t[i];              // drops the fraction: 8 / 3 is 2
        if (made >= k) return true;    // stop early, so "made" never overflows
    }
    return false;
}

int main() {
    cin >> n >> k;
    t.resize(n);                       // now t has n boxes
    for (auto &x : t) cin >> x;
    long long lo = 0;                                     // 0 seconds: not enough
    long long hi = *min_element(t.begin(), t.end()) * k;  // fastest machine alone: enough
    while (hi - lo > 1) {
        long long mid = lo + (hi - lo) / 2;
        if (ok(mid)) hi = mid; else lo = mid;
    }
    cout << hi << "\n";
}

Speed: \( O(\log n) \) steps for a range of size \( n \). For answers up to \( 10^{18} \): about 60 steps. Total = 60 \( \times \) (cost of ok).

Wrong ideas people get

  • You may think: Binary search is only for finding a value in an array.

    The truth: It works for any yes/no question. The rule: all the "no" answers come before all the "yes" answers. In contests you search on the answer more often than in an array.

  • You may think: It works on any array.

    The truth: The array must be sorted. On an unsorted array it gives a wrong answer, with no error message.

  • You may think: Some values work and some do not, so I can binary search.

    The truth: Only if a "yes" never comes before a "no". Test a small example by hand first. If yes and no are mixed, this tool does not fit.

Common mistakes

  • Wrong start. lo must really be a "no" and hi must really be a "yes". Not sure? Make hi bigger.
  • (lo + hi) / 2 can overflow when both are big. Write lo + (hi - lo) / 2 and use long long.
  • You return the wrong end. For the first yes return hi. For the last yes return lo.

Check yourself

  1. The sorted array is 2 4 4 7 9. Which index does lower_bound give for 4? And upper_bound?
    Answer

    lower_bound gives 1, the first 4. upper_bound gives 3, the 7. So 4 is there \( 3 - 1 = 2 \) times.

  2. For x = 1, 2, 3, 4 your ok gives yes, no, yes, yes. Can you use binary search?
    Answer

    No. A "yes" comes before a "no", so ok is not monotonic.

  3. The answer is between 1 and \( 10^9 \). One call of ok costs \( 10^5 \) steps. About how many steps in total?
    Answer

    Cutting \( 10^9 \) in half takes about 30 steps. \( 30 \cdot 10^5 = 3 \cdot 10^6 \) steps. That is fast.
