A function that calls itself on a smaller problem. With it you can try every choice: take or skip, this order or that order.

Before this lesson

  • You know the idea "try every case and check it" → Brute force
  • You can compare a number of steps with \( 10^8 \) → Limits → speed
  • You can try every subset with a mask → Bits

Spot it

  • \( n \) is very small. \( n \le 20 \) means "try all subsets": \( 2^{20} \approx 10^6 \).
  • \( n \le 10 \) means "try all orders": \( 10! \approx 3.6 \cdot 10^6 \). Here \( 10! = 10 \cdot 9 \cdot \dots \cdot 1 \).
  • For every item you make a choice: take it or skip it, group A or group B, plus or minus.
  • The statement says "print all …" or "count all ways …", and the numbers are tiny.

Three ways to understand it

1 · Story — the line of people

You stand in a long line. You want your position, but you cannot see the front. You ask the person in front of you. He does not know, so he asks the next person.

The first person says "I am 1". She asks nobody. This is the base case. Then the answers come back: 2, 3, 4 … Each person adds 1 to the answer he gets.

Every recursion has two parts: a base case that stops, and a step that asks a smaller question.

2 · Picture — a function waits for the call it made

The smallest recursion: \( \text{sum}(3) = 3 + 2 + 1 = 6 \). Read the rule as "sum of 1..n is n plus the sum of 1..n-1". The base case comes first: the sum of nothing is 0.

This function returns its answer with return. The call that asked uses that value. So sum(3) waits for sum(2) to return 3, then returns \( 3 + 3 \).

For a sum, a loop is better. Recursion is worth it when every step has a choice, as in the next box.

3 · Code — take or skip: all subsets of {1, 2, 3}

For each number choose: take it or skip it. go(i) means "numbers before index i are decided". The vector chosen holds the taken numbers.

This is backtracking: do (add the number), recurse, then undo (remove it) before the next choice.


#include <bits/stdc++.h>
using namespace std;

int n;
vector<int> a, chosen;

void print(const vector<int>& v) {
    cout << "{";
    for (int k = 0; k < (int)v.size(); k++) {
        if (k > 0) cout << ",";
        cout << v[k];
    }
    cout << "}\n";
}

void go(int i) {
    if (i == n) {                  // base case FIRST: every number is decided
        print(chosen);
        return;
    }
    chosen.push_back(a[i]);        // do: take a[i]
    go(i + 1);                     // recurse
    chosen.pop_back();             // undo
    go(i + 1);                     // skip a[i]
}

int main() {
    cin >> n;
    a.resize(n);
    for (int& x : a) cin >> x;
    go(0);
}

Input 3 and 1 2 3 prints the 8 subsets in the order of the picture.

n, a and chosen are global, because go needs them. That is fine for a function like this. With many test cases, reset them at the start of every test. In print, const vector<int>& v means "use the real vector, do not copy it, and do not change it" (C++ reference, "References").

Change it to fit

Default: for plain "all subsets", the mask loop from Bits is shorter. Use the take-or-skip function in three cases: you must stop early, an item has more than 2 choices, or you build something step by step. For "all orders", use next_permutation instead of your own recursion.

  • Count, do not print. Example: count the subsets with sum target. Pass the sum as a parameter. Then there is nothing to undo. 
    
void go(int i, long long sum) {
    if (i == n) { if (sum == target) ways++; return; }
    go(i + 1, sum + a[i]);         // take
    go(i + 1, sum);                // skip
}
  • Only subsets of size k. Change the base case. You can also stop early: with more than k numbers chosen, no answer is left below. 
    
if ((int)chosen.size() > k) return;              // stop early
if (i == n) { if ((int)chosen.size() == k) print(chosen); return; }
  • All orders (permutations). Sort first. next_permutation changes p to the next order and returns false after the last one. A do { … } while (…); loop runs its body first and tests after, so the sorted start is used too. For 1 2 3 you get 6 orders: 123, 132, 213, 231, 312, 321. 
    
sort(p.begin(), p.end());                        // start from the smallest order
do {
    // use the order p here
} while (next_permutation(p.begin(), p.end()));
  • All strings of length n over the letters a, b, c. Each position has 3 choices, not 2. Loop over the choices. There are \( 3^n \) strings. 
    
void go(int i) {                                 // s is a global string
    if (i == n) { cout << s << "\n"; return; }
    for (char c : {'a', 'b', 'c'}) {
        s.push_back(c);  go(i + 1);  s.pop_back();   // do, recurse, undo
    }
}

Solve one together

Problem. There are \( n \) apples with weights \( p_1, \dots, p_n \). Split them into two groups, A and B. Make the difference of the two total weights as small as possible. Print that difference. Limits: \( 1 \le n \le 20 \), \( 1 \le p_i \le 10^9 \). (This is "Apple Division" on CSES.)

  1. What is asked? The smallest value of \( |\text{sumA} - \text{sumB}| \). The bars mean "without the minus sign": \( |8 - 9| = 1 \).
  2. A small example by hand. Weights 3, 2, 7, 4, 1. The total is 17. Put 3, 4, 1 in A: \( \text{sumA} = 8 \). Then \( \text{sumB} = 17 - 8 = 9 \). The difference is 1. It cannot be 0, because 17 is odd. So the answer is 1.
  3. The idea. Every apple has two choices: A or B. That is take or skip. Pass sumA as a parameter. In the base case, sumB = total - sumA. Keep the best difference.
  4. Why is it fast enough? Count the bottom calls for a few \( n \):
    \( n \)3102030
    \( 2^n \)81024\( \approx 10^6 \)\( \approx 10^9 \)

    For \( n = 20 \) that is about \( 2 \cdot 10^6 \) calls in all. Far below \( 10^8 \). For \( n = 30 \) it would be too slow.


#include <bits/stdc++.h>
using namespace std;

int n;
vector<long long> p;
long long total = 0, best;

void go(int i, long long sumA) {
    if (i == n) {                            // base case: every apple has a group
        long long sumB = total - sumA;
        best = min(best, abs(sumA - sumB));
        return;
    }
    go(i + 1, sumA + p[i]);                  // apple i goes to A
    go(i + 1, sumA);                         // apple i goes to B
}

int main() {
    cin >> n;
    p.resize(n);
    for (long long& x : p) {
        cin >> x;
        total += x;                          // up to 2 * 10^10: long long
    }
    best = total;                            // the worst split: all in one group
    go(0, 0);
    cout << best << "\n";
}

Speed: all subsets \( O(2^n) \), fine for \( n \le 20 \). All orders \( O(n!) \), fine for \( n \le 10 \). Check \( n \) before you start.

Wrong ideas people get

  • You may think: Recursion is magic. I cannot follow what happens.

    The truth: Each call is a normal function call with its own copy of the variables. Trace \( n = 2 \) on paper, like the picture with sum(3).

  • You may think: When a function calls itself, it restarts and forgets what it was doing.

    The truth: The function waits. When the inner call returns, it goes on from the next line, with its own n.

  • You may think: The base case is a small detail. I add it at the end.

    The truth: Without a base case the calls never stop. The program crashes or runs for ever. Write it first. On Codeforces you get "Runtime error" or "Time limit exceeded".

  • You may think: Recursion is always slow.

    The truth: The cost is the number of calls. sum(n) makes only \( n + 1 \) calls, like a loop. Take or skip is slow only because it makes \( 2^n \) calls.

Common mistakes

  • The next call is not smaller: you write go(i) and not go(i + 1). It never reaches the base case.
  • You forget to undo. After push_back and the call, write pop_back.
  • You call next_permutation on an array that is not sorted. Then you miss the orders that come "before" it.

Not now

  • The same call runs many times. Storing each answer once makes it fast. That is Dynamic programming.
  • Recursion on a graph. Walking from a point to its neighbours is the same idea. You learn it next, in Graphs: BFS and DFS.
  • \( n \) up to 40 (meet in the middle) and bitmask DP. Rare below 1600. Come back after 1600.

Check yourself

  1. What does sum(4) return? How many calls wait when sum(0) starts?
    Answer

    It returns \( 4 + 3 + 2 + 1 = 10 \). Four calls wait: sum(4), sum(3), sum(2), sum(1).

  2. In the take-or-skip code, what goes wrong if you delete chosen.pop_back()?
    Answer

    Numbers you skipped stay inside chosen. For {1, 2, 3} the second line prints {1,2,3} again, not {1,2}.

  3. \( n \le 15 \) and you must try every order. Is that fast enough?
    Answer

    No. \( 15! \approx 1.3 \cdot 10^{12} \), far above \( 10^8 \). All orders are fine only up to about \( n = 10 \).
