Do not write your own sorting algorithm. Call sort(), then change the order rule to fit your problem.

Before this lesson

  • You can call sort and use a pair → STL basics
  • You can read \( O(n \log n) \) and \( O(n^2) \) → Limits → speed
  • You know "take the smallest first" ideas → Greedy

Spot it

  • The order of the input does not matter. You choose a group, pairs, or "any \( k \) elements".
  • The statement asks for the smallest difference, or for equal elements.
  • A greedy idea: "serve the shortest first", "take the biggest first".
  • The output must be "in order of score", "by name", and so on.

Three ways to understand it

1 · Story — students in a line

Find the two students with the closest heights. In a random crowd, you compare every student with every other one. That is slow.

Now they stand in a line by height. The two closest students are now adjacent. You look only at neighbours.

2 · Picture — what sorting buys you, and how it is so fast

before819413
after sort148913
gap to the left neighbour–3414

Before sorting there are 10 pairs to check. After sorting, only 4 neighbours. Now take \( n = 2 \cdot 10^5 \) values. All pairs: about \( 2 \cdot 10^{10} \) checks, far too slow. Sort plus one loop: about \( n \log_2 n \approx 3.6 \cdot 10^6 \) steps.

Why is sorting so fast? One idea inside it is the merge. To merge two sorted lists, compare their two front values and take the smaller one. Repeat.

A sort can use merging like this. Take 8 values. Merge them in pairs of 1 + 1, then 2 + 2, then 4 + 4. Each round costs 8 steps. The size doubles each round, so there are 3 rounds: \( 8 \cdot 3 = 24 \) steps. For \( n \) values: \( n \log_2 n \) steps, written \( O(n \log n) \).

This method is called merge sort. C++ sort uses another method inside, but its cost is also \( O(n \log n) \).

3 · Code — sort, then one easy loop


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;                               // n >= 2
    vector<int> a(n);
    for (auto &x : a) cin >> x;
    sort(a.begin(), a.end());               // small -> big
    int best = a[1] - a[0];
    for (int i = 1; i < n; i++)             // look only at neighbours
        best = min(best, a[i] - a[i - 1]);
    cout << best << "\n";
}

After sorting, equal values are neighbours. "Are two elements equal?" becomes: is a[i] == a[i - 1] for some i?

Change it to fit

This is the real skill. You never change how sort works. You change what you sort, or the rule that compares two values.

1. Big → small. Use this one form:


sort(a.rbegin(), a.rend());                // 13 9 8 4 1

2. Your own order. Give sort a small function, a lambda. It returns true only when x must come before y. Here: by the last digit.


sort(a.begin(), a.end(), [](int x, int y) {
    return x % 10 < y % 10;                // 13 5 21 44 -> 21 13 44 5
});

Always use < or > here, never <=. For two equal values the function must return false. With <= the program can crash.

3. By one key, then by another. Score big → small. Equal scores: name a → z.


vector<pair<int, string>> v;              // (score, name)
sort(v.begin(), v.end(), [](const auto &x, const auto &y) {
    if (x.first != y.first) return x.first > y.first;   // first key: bigger score first
    return x.second < y.second;                          // equal score: name a -> z
});

4. Keep the old position. Build the pairs (value, index) first. Then sort the pairs. Each value carries its old index with it.


vector<pair<int, int>> p(n);
for (int i = 0; i < n; i++) p[i] = {a[i], i};  // BEFORE sorting
sort(p.begin(), p.end());                      // by value; equal value: by index
// p[0].second = the old index of the smallest value

5. Only a part. sort(a.begin() + l, a.begin() + r + 1) sorts a[l] … a[r]. The second place is one step after the last value. An array filled from index 1: sort(a.begin() + 1, a.end()).

6. Small values: count them. Values from 0 to 100 only? Count each value, then write them out. That is \( n + 101 \) steps.


vector<int> cnt(101, 0);                   // cnt[v] = how many times v appears
for (int x : a) cnt[x]++;
a.clear();
for (int v = 0; v <= 100; v++)
    for (int k = 0; k < cnt[v]; k++) a.push_back(v);

Use it only when a problem needs \( O(n) \). The default is sort.

Sort first, then think. Many tools need sorted input. You saw greedy. Two pointers and binary search come next, and both start with a sort.

Solve one together

Problem. \( n \) people wait at one desk. Person \( i \) needs \( t_i \) minutes. The desk serves one person at a time. A person waits until their own turn starts. Choose the order with the smallest total waiting time. Print that total and the order of person numbers. Limits: \( 1 \le n \le 2 \cdot 10^5 \) and \( 1 \le t_i \le 10^4 \).

  1. What is asked? An order of the people, and its total waiting time.
  2. A small example by hand. Three people need 3, 1 and 2 minutes.
    ordereach one waitstotal
    1, 2, 30, 3, 3 + 1 = 47
    3, 2, 10, 2, 2 + 1 = 35
    2, 3, 10, 1, 1 + 2 = 34
  3. The idea. Everyone after a person waits for that person's time. So the shortest one goes first. Sort by time. The answer is person numbers, so use idea 4: pairs (time, number) built before the sort.
  4. Why is it fast enough? The sort costs about \( 2 \cdot 10^5 \cdot 18 \approx 3.6 \cdot 10^6 \) steps. The total wait is at most \( 2 \cdot 10^5 \cdot 2 \cdot 10^5 \cdot 10^4 = 4 \cdot 10^{14} \). That needs long long.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<pair<int, int>> p(n);             // (time, person number)
    for (int i = 0; i < n; i++) {
        cin >> p[i].first;
        p[i].second = i + 1;                   // remember the number BEFORE sorting
    }
    sort(p.begin(), p.end());                  // shortest time first
    long long now = 0, total = 0;              // now = when the next person starts
    for (auto [t, id] : p) {
        total += now;                          // this person waited "now" minutes
        now += t;
    }
    cout << total << "\n";
    for (auto [t, id] : p) cout << id << " ";
    cout << "\n";
}

Speed: sort is \( O(n \log n) \). For \( n = 2 \cdot 10^5 \): about \( 3.6 \cdot 10^6 \) steps, very fast.

Wrong ideas people get

  • You may think: Sorting never hurts. I can sort any array first.

    The truth: Sorting destroys the old positions. If the problem is about positions or a subarray, that information is gone. Example: in 30 10 20 the smallest is at index 1. After the sort, it is at index 0. Keep pairs (idea 4).

  • You may think: A rule with <= gives the same order, so it is fine too.

    The truth: The rule must be strict. With <= the program can crash or give a wrong order.

  • You may think: I must learn many sorting algorithms to get good.

    The truth: On Codeforces you call sort(). The skill is to change the order to fit the problem. Only the merge idea comes back later.

Common mistakes

  • You sort a and then build the pairs (value, index). The indexes are now the new ones. Build the pairs first.
  • An array filled from index 1, sorted with sort(a.begin(), a.end()). The empty a[0] is sorted in too. Write sort(a.begin() + 1, a.end()).
  • A rule that forgets the second key. Equal scores then come in any order, and your output differs from the expected one.

Not now

  • Bubble, insertion, selection, quick and heap sort. They are for university exams and interviews. You do not need them to solve Codeforces problems below 1600: After 1600.
  • Writing merge sort yourself, and counting "inversions" with it. It needs a function that calls itself: Recursion.
  • The count array in full. Idea 6 is the main tool of the next lesson: Counting.

Check yourself

  1. Your rule is return x <= y;. What is wrong?
    Answer

    It is not strict. For two equal values it returns true, and it must return false. Write x < y.

  2. You sort the pairs (3, 0), (1, 1), (3, 2), (2, 3). What is the order?
    Answer

    (1, 1), (2, 3), (3, 0), (3, 2). By the first value; the two 3s by the second value.

  3. You want to sort only a[2] to a[5]. What do you write?
    Answer

    sort(a.begin() + 2, a.begin() + 6). The second place is one step after a[5].
