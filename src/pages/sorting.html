Put the values in order first. In a sorted array, close values stand next to each other, and many problems become easy.

Spot it

  • The order of the input does not matter: you choose a group, or pairs, or "any k elements".
  • The statement asks for the smallest difference, or for equal elements.
  • A greedy idea: "take the smallest first" or "take the biggest first".
  • You want to use binary search or two pointers. Both need a sorted array.

Three ways to understand it

1 · Story — students in a line

Find the two students with the closest heights. If they stand in a random order, you must compare every student with every other student. That is slow.

Now ask them to stand in a line by height. The two closest students are now adjacent. You only look at neighbours.

2 · Picture — smallest difference between two elements

before819413
after sort148913
neighbours1, 44, 88, 99, 13
difference3414

Before sorting: 10 pairs to check. After sorting: only 4 neighbours. For n = 200 000 that is 2·1010 pairs against 200 000 neighbours.

3 · Code — sort, then one easy loop


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;                               // n >= 2
    vector<int> a(n);
    for (auto &x : a) cin >> x;
    sort(a.begin(), a.end());               // small -> big
    int best = a[1] - a[0];
    for (int i = 1; i < n; i++)             // look only at neighbours
        best = min(best, a[i] - a[i - 1]);
    cout << best << "\n";
}

Other orders. A pair is sorted by first, then by second. Use it to remember the old position.


sort(a.begin(), a.end(), greater<int>());      // big -> small
vector<pair<int, int>> p(n);
for (int i = 0; i < n; i++) p[i] = {a[i], i};  // (value, old index)
sort(p.begin(), p.end());                      // by value; same value: by index
// p[0].second = where the smallest value was in a

Your own order: write a comparator. It returns true when x must come before y.


struct Student { string name; int score; };

bool before(const Student &x, const Student &y) {
    if (x.score != y.score) return x.score > y.score;  // bigger score first
    return x.name < y.name;                            // same score: by name
}
// in main:  sort(v.begin(), v.end(), before);

The same thing as a short lambda, written inside sort:


// sort numbers by their last digit; same last digit: smaller number first
sort(a.begin(), a.end(), [](int x, int y) {
    if (x % 10 != y % 10) return x % 10 < y % 10;
    return x < y;
});

After sorting, equal values are neighbours. So "are there two equal elements?" is just: is a[i] == a[i - 1] for some i?

Speed: sort is O(n log n). For n = 200 000 that is about 4 million steps: very fast.

Common mistakes

  • A comparator with <= or >=. It must be strict: < or >. For two equal elements it must return false. If not, the program can crash.
  • Sorting loses the old positions. If the answer needs them, sort pairs (value, index).
  • Sorting when the order matters. If the problem talks about a subarray or "the next element", you usually cannot sort.
  • An array that starts from index 1: write sort(a + 1, a + n + 1), not sort(a, a + n).
