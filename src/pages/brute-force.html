When the limits are small, do not look for a clever idea. Try every possibility and check each one.

Before this lesson

  • You can count the steps of two nested loops: \( O(n^2) \) → How much does my code cost?
  • You can loop over an array and compare boxes → Arrays and strings

Spot it

  • The limits are small: \( n \le 100 \), \( n \le 1000 \), or the answer is at most a few thousand.
  • You can list every possibility: every element, every pair, every value of the answer.
  • Checking one possibility is easy: one if or one short loop.
  • The number of possibilities times the cost of one check is below about \( 10^8 \).

Three ways to understand it

1 · Story — the key ring

You have 10 keys and one door. You do not know which key is right. You do not study the keys. You try key 1, key 2, key 3… until the door opens.

With 10 keys this is the fastest way. With a million keys it is not. So always count the keys first. This way of solving is called brute force.

2 · Picture — all pairs for \( n = 5 \)

Task: how many pairs of positions \( i < j \) have a[i] + a[j] == 7? Here a = {2, 5, 3, 4, 1}.

First, which pairs do we check? Draw every \( (i, j) \) as a grid: row \( i \), column \( j \).

With \( n \) elements there are \( \frac{n (n - 1)}{2} \) pairs. For \( n = 5 \): \( \frac{5 \cdot 4}{2} = 10 \). Starting j at i + 1 visits exactly the checked half. Now watch the loops walk over it.

3 · Code — two loops over all pairs


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, target;
    cin >> n >> target;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    int count = 0;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)        // j > i: each pair once
            if (a[i] + a[j] == target) count++;
    cout << count << "\n";
}

Change it to fit

The same tool fits many problems. Change only what you try. Then count the cost and compare it with \( 10^8 \). The DEFAULT is the pairs loop above.

For "every value of the answer", go from small to big. The first value that works is the smallest answer, so stop there with break. The next part solves one problem this way.

A fourth form, "all subsets", tries every group of elements. It needs a new tool; see "Not now" below.

Solve one together

Problem (732A, Buy a Shovel). One shovel costs \( k \). You have many 10-coins and one coin of value \( r \), with \( 1 \le r \le 9 \). Buy the fewest shovels (at least one) so that you pay with no change. Limits: \( 1 \le k \le 1000 \).

  1. What is asked? The smallest number of shovels. You can pay when the total ends in 0 (only 10-coins) or ends in \( r \) (10-coins and the \( r \)-coin).
  2. A small example by hand. \( k = 117 \), \( r = 3 \). Only the last digit of the total matters.
    shovels123…89
    total117234351…9361053
    last digit741…63

    The answer is 9.

  3. The idea. Try every number of shovels from 1 upward. 10 shovels always work, because \( 10 \cdot k \) ends in 0. So trying up to 10 is enough.
  4. Why is it fast enough? At most 10 tries, each one is a multiplication. That is \( O(1) \) in practice.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int k, r;
    cin >> k >> r;
    for (int cnt = 1; cnt <= 10; cnt++) {      // 10 shovels always work: 10 * k ends in 0
        int last = cnt * k % 10;               // last digit of the total price
        if (last == 0 || last == r) {
            cout << cnt << "\n";               // the first cnt that works is the smallest
            break;
        }
    }
}

Speed: (number of possibilities) \( \times \) (cost of one check). One loop is \( O(n) \), all pairs \( O(n^2) \), all triples \( O(n^3) \). Keep it below about \( 10^8 \).

Brute force has a second job. When you write a faster solution, a slow brute force tells you if it is correct. See "stress testing" in How to find your bug.

Wrong ideas people get

  • You may think: Brute force is a beginner's trick. The real solution is always more clever.

    The truth: If the steps stay below \( 10^8 \), it is the best answer. It is fast to write and hard to get wrong.

  • You may think: Two nested loops are fine, because each step is tiny.

    The truth: With \( n = 2 \cdot 10^5 \) there are about \( 2 \cdot 10^{10} \) pairs: about 200 seconds. Count before you write.

  • You may think: Small limits mean there is a hidden formula I must find.

    The truth: Small limits are a message from the author: you may try everything.

Common mistakes

  • The inner loop starts at j = 0. Then you count each pair twice, and also pair an element with itself.
  • The loop over answers stops too early. Be sure of the biggest answer that can happen, or make the limit bigger.
  • The count of pairs is stored in int. For \( n = 10^5 \) there are about \( 5 \cdot 10^9 \) pairs: use long long.

Not now

  • All subsets ("choose any group of items"). With \( n \le 20 \) there are \( 2^{20} \approx 10^6 \) groups. You list them with bits in Bits.
  • All orders and all ways to build something step by step. You learn it in Recursion and backtracking.

Check yourself

  1. How many pairs \( i < j \) are there for \( n = 6 \)?
    Answer

    \( \frac{6 \cdot 5}{2} = 15 \).

  2. \( n \le 3000 \) and you check all pairs. Is it fast enough? And for \( n \le 10^5 \)?
    Answer

    For 3000: about \( 4.5 \cdot 10^6 \) pairs, fast. For \( 10^5 \): about \( 5 \cdot 10^9 \), too slow.

  3. \( n \le 100 \) and you need all triples. Are three loops fast enough?
    Answer

    Yes. About \( \frac{100^3}{6} \approx 1.7 \cdot 10^5 \) triples, far below \( 10^8 \).
