When the limits are small, do not look for a clever idea. Try every possibility and check each one.

Spot it

  • The limits are small: n ≤ 100, n ≤ 1000, or the answer is at most a few thousand.
  • You can list every possibility: every element, every pair, every value of the answer.
  • Checking one possibility is easy: one if or one short loop.
  • The number of possibilities × the cost of one check is below about 108.

Three ways to understand it

1 · Story — the key ring

You have 10 keys and one door. You do not know which key is right. You do not study the keys. You try key 1, key 2, key 3… until the door opens.

With 10 keys this is the fastest way. With a million keys it is not. So always count the keys first. This way of solving is called brute force.

2 · Picture — all pairs for n = 4

Task: how many pairs of positions i < j have a[i] + a[j] = 7? Here a = [2, 5, 3, 4].

4 elements give 6 pairs. In general n elements give n × (n − 1) / 2 pairs. j starts at i + 1, so each pair is seen once and no element is paired with itself.

3 · Code — the three shapes

Shape 1: one loop. Look at every element and count or keep the best. You know this from the earlier pages.

Shape 2: two loops over all pairs. This is the table above.


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, target;
    cin >> n >> target;
    vector<int> a(n);
    for (int &x : a) cin >> x;

    int count = 0;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)        // j > i: each pair once
            if (a[i] + a[j] == target) count++;
    cout << count << "\n";
}

Shape 3: try every answer. Loop over each candidate answer from small to big. Stop at the first one that works.

Example (problem 732A): one shovel costs k. You have many 10-coins and one coin of value r. Find the smallest number of shovels you can pay for with no change. The total must end in 0 or in r.


#include <bits/stdc++.h>
using namespace std;

int main() {
    int k, r;
    cin >> k >> r;
    for (int cnt = 1; cnt <= 10; cnt++) {      // 10 shovels always work: 10 * k ends in 0
        int last = cnt * k % 10;               // last digit of the total price
        if (last == 0 || last == r) {
            cout << cnt << "\n";               // the first cnt that works is the smallest
            break;
        }
    }
}

Input 117 3 → output 9, because 9 × 117 = 1053 ends in 3.

Speed: (number of possibilities) × (cost of one check). One loop is O(n), all pairs are O(n^2). Keep it below about 10^8.

Brute force has a second job. When you write a faster solution, a slow brute force tells you if it is correct. See "stress testing" in How to find your bug.

Common mistakes

  • You do not count the steps first. Two loops with n = 2·105 are 2·1010 steps: Time limit exceeded.
  • The inner loop starts at j = 0. Then you count each pair twice, and also pair an element with itself.
  • The loop over answers stops too early. Be sure of the biggest answer that can happen, or make the limit bigger.
  • You look for a formula for 30 minutes when n ≤ 100. Small limits are a gift: use them.
