No trick, no formula. Read the rules, then make your program follow them step by step.

Before this lesson

  • You can read numbers with cin and write a for loop → Your C++ template
  • You can count the steps of a loop, like \( O(n) \) → How much does my code cost?

Spot it

  • The statement describes a process: "first…, then…, after each step…".
  • The limits are small, like \( n \le 100 \) or \( n \le 1000 \). Doing every step is fast enough.
  • After one reading you know what to do. The only work is to write it carefully.
  • Codeforces puts the tag implementation on these problems. Another name is simulation.

Three ways to understand it

1 · Story — cooking from a recipe

A recipe says: "Put 2 eggs. Add sugar. Mix. Repeat 3 times." You do not invent anything. You do each line in the same order.

The statement is your recipe. Each number in it becomes a variable. Each "repeat" becomes a loop. Each "if" stays an if.

2 · Picture — the tram

A tram is empty at the start. There are 4 stops. At each stop a people exit, then b people enter. How many seats does the tram need?

We need the biggest number of people inside at any moment. The stops are (0, 3), (2, 5), (4, 2) and (4, 0). Press Next and watch the variables.

The skill: trace by hand

The stepper did a trace: it wrote every variable after every line. You can do the same on paper.

  1. Draw one column for each variable.
  2. Write one row for each turn of the loop.
  3. Read your code line by line. Change only what the line changes.
  4. Compare the last row with the expected output. The first difference shows you the bug.

Trace the code you wrote, not the code you wanted to write.

3 · Code — the trace becomes a loop

Use the same names as the statement: n, a, b. Then you can compare your code with the text line by line.


#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;                    // number of stops
    cin >> n;
    int inside = 0;           // people in the tram now
    int best = 0;             // the biggest "inside" we saw
    for (int i = 0; i < n; i++) {
        int a, b;             // a people exit, b people enter
        cin >> a >> b;
        inside -= a;          // first they exit
        inside += b;          // then they enter
        best = max(best, inside);   // max(x, y) = the bigger of the two
    }
    cout << best << "\n";
}

Many problems have t test cases in one input. Put the solution of one case in a function. Then every case starts with fresh variables.


#include <bits/stdc++.h>
using namespace std;

void solve() {                // solves ONE test case
    int n;
    cin >> n;
    long long sum = 0;        // made new for every test case
    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;
        sum += x;
    }
    cout << sum << "\n";      // one answer per line
}

int main() {
    int t;
    cin >> t;
    while (t--) solve();
}

Solve one together

Problem (266B, Queue at the School). \( n \) children stand in a queue. The string s shows them: B is a boy, G is a girl. Each second, every boy who stands right before a girl swaps places with her. All swaps of one second happen at the same time. Print the queue after \( t \) seconds. Limits: \( 1 \le n, t \le 50 \).

  1. What is asked? The string after \( t \) seconds. Nothing is counted, so no clever idea is needed.
  2. A small example by hand. s = BGGBG and \( t = 2 \). Look at each pair of neighbours from the left.
    secondwhat happensqueue after
    0–BGGBG
    1positions 0, 1 swap; positions 3, 4 swapGBGGB
    2positions 1, 2 swapGGBGB
  3. The trap. After a swap at positions 0, 1 the boy stands at position 1. If the loop now checks positions 1, 2, it swaps him again. Then the boy moves two places in one second, and that is not allowed. A trace of this wrong code gives GGBGB after second 1, not GBGGB. The trace shows the bug before you submit.
  4. The idea. Repeat \( t \) times: walk over the string. If you find BG, swap them and skip the next position.
  5. Why is it fast enough? Each second looks at about \( n \) pairs. In total \( t \cdot n = 50 \cdot 50 = 2500 \) steps. That is far below \( 10^8 \).

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, t;
    string s;
    cin >> n >> t >> s;
    for (int sec = 0; sec < t; sec++) {
        for (int i = 0; i + 1 < n; i++) {
            if (s[i] == 'B' && s[i + 1] == 'G') {
                swap(s[i], s[i + 1]);
                i++;                  // skip: this boy already moved this second
            }
        }
    }
    cout << s << "\n";
}

Speed: \( O(\text{number of steps}) \). Here \( O(t \cdot n) \). Before you write, check that the steps stay below about \( 10^8 \).

Wrong ideas people get

  • You may think: There must be a clever trick. Simulation is too easy to be the answer.

    The truth: Many A and B problems are only careful simulation. If the limits are small, do the steps.

  • You may think: If the samples pass, my code is correct.

    The truth: The samples are few and small. Trace one more small case by hand, like \( n = 1 \).

  • You may think: The order of the steps inside one turn does not matter.

    The truth: The order often changes the answer. Follow the order of the statement exactly. In the tram, people exit before others enter.

Common mistakes

  • Wrong output format. YES is not Yes when the statement asks for exact letters. Do not print extra text like "Answer:".
  • A variable keeps its old value in the next test case. Create it inside solve().
  • You forget the smallest input, the edge case. Try \( n = 1 \) by hand.

Not now

  • Too many steps. Sometimes the process runs \( 10^{18} \) times. Then you cannot do every step; you need a formula. Start with Basic math.
  • A real queue of people, where the first one leaves and new ones join at the end. C++ has a tool for it: Stack, queue, map, set.

Check yourself

  1. The tram stops are (0, 4), (3, 1), (2, 6). What does the program print?
    Answer

    6. Inside: 4, then \( 4 - 3 + 1 = 2 \), then \( 2 - 2 + 6 = 6 \). The biggest is 6.

  2. In Queue at the School, why do we write i++ after a swap?
    Answer

    The boy now stands at i + 1. Without the skip he can swap again in the same second.

  3. You have \( t \le 100 \) seconds and \( n \le 1000 \) children. Is a full simulation fast enough?
    Answer

    Yes. \( 100 \cdot 1000 = 10^5 \) steps, far below \( 10^8 \).
