Count how many steps your code does when the input is big. \( O(\dots) \) is the short name for how that count grows.

First, count with real numbers

A step is one small action: add two numbers, compare two numbers, read one array cell. The cost of a code is how many steps it does.

This loop adds up an array of 10 numbers. The line sum += a[i] runs 10 times: 10 steps.


long long sum = 0;
for (int i = 0; i < n; i++) sum += a[i];        // runs n times

Now put a loop inside a loop. For every i, the inner loop runs over all j.


int same = 0;
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)                  // runs n times for EACH i
        if (a[i] == a[j]) same++;

Now the short name: \( O(\dots) \)

The letter \( n \) is the size of the input: how many numbers in the array, or how long the string is.

One loop does \( n \) steps. We write \( O(n) \). The loop inside a loop does \( n \cdot n = n^2 \) steps. We write \( O(n^2) \). Say it "big O of n squared".

\( O(\dots) \) is not the exact number of steps. It says how the steps grow when \( n \) grows. This is the complexity of the code.

A problem can have two sizes. Example: a grid with \( n \) rows and \( m \) columns. Reading it takes \( n \cdot m \) steps: \( O(n \cdot m) \). For \( n = 1000 \) and \( m = 2000 \) that is \( 2 \cdot 10^6 \).

Read the cost from the code

Each rule below has a tiny code, its count for one \( n \), and its \( O(\dots) \).

1. One loop → \( O(n) \)


for (int i = 0; i < n; i++) cnt += (a[i] % 2 == 0);   // n = 1000: 1000 steps

2. A loop inside a loop → multiply → \( O(n^2) \)


for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) total += a[i] * a[j];  // n = 1000: 1000 * 1000 = 10^6

Two different sizes multiply the same way: an outer loop to \( n \) and an inner loop to \( m \) give \( O(n \cdot m) \).

3. Loops one after another → add → keep the bigger


for (int i = 0; i < n; i++) cin >> a[i];             // n steps
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) total += a[i] * a[j];  // n * n steps

For \( n = 1000 \): \( 1000 + 10^6 \) = 1 001 000. The small part changes almost nothing, so keep only the bigger part: \( O(n^2) \).

4. The inner loop stops at i → about half → still \( O(n^2) \)


for (int i = 0; i < n; i++)
    for (int j = 0; j < i; j++) pairs += (a[j] == a[i]);  // 0 + 1 + 2 + ... + (n-1)
\( n \)101001000
steps454950499 500
\( n^2 / 2 \)505000500 000

It is about \( n^2 / 2 \). Half of \( n^2 \) still grows like \( n^2 \): \( O(n^2) \).

5. Halve or double each round → \( O(\log n) \)


int rounds = 0;
for (int i = n; i > 1; i /= 2) rounds++;      // i: n, n/2, n/4, ... down to 1
\( n \)101001000\( 10^6 \)\( 10^9 \)
rounds3691929

\( n \) grows a million times, but the rounds grow by only about 20. The number of halvings from \( n \) down to 1 is called the logarithm, \( \log n \). Example: \( \log 8 = 3 \), because 8 → 4 → 2 → 1.

Doubling is the same count from the other side. for (int i = 1; i < n; i *= 2) runs 30 times for \( n = 10^9 \).

6. Loop while i * i <= n → \( O(\sqrt{n}) \)


for (long long i = 1; i * i <= n; i++) cnt++;   // n = 10^12: 10^6 rounds

The loop stops when \( i \) passes the square root of \( n \). For \( n = 100 \) it runs 10 times, because \( \sqrt{100} = 10 \). For \( n = 10^{12} \) it runs \( 10^6 \) times.

7. A loop over \( n \) with a halving loop inside → \( O(n \log n) \)


for (int i = 0; i < n; i++)
    for (int j = n; j > 1; j /= 2) cnt++;      // n = 1000: 1000 * 9 = 9000 steps

Multiply again: \( n \) rounds outside, \( \log n \) rounds inside.

8. A function that calls itself two times → \( O(2^n) \)


long long f(int n) {
    if (n == 0) return 1;
    return f(n - 1) + f(n - 1);   // two calls, each with n - 1
}

Count the calls: f(10) makes 2047 calls. f(20) makes 2 097 151. f(30) makes 2 147 483 647. Every \( +1 \) on \( n \) doubles the work. Only the idea here. Functions that call themselves come in a later lesson.

9. No loop → \( O(1) \)


long long total = n * (n + 1) / 2;    // n is long long: 1 step for any n
cout << a[0] + a[n - 1] << "\n";   // 1 step, for n = 10 or n = 10^9

\( O(1) \) means the steps do not grow with \( n \).

Some lines look like one step. Inside, they hide a loop. Here \( n \) is the size of the vector or string. Some of these tools come in later lessons. Learn their cost now.

Printing \( 10^6 \) lines took 1.3 seconds with endl and 0.05 seconds with "\n". s.find(t) with a longer string t of length \( m \) can cost up to \( n \cdot m \).

An \( O(n) \) line inside a loop of \( n \) rounds gives \( O(n^2) \), even if the code is two lines.

Why we drop the small parts

Take a code that does \( n^2 + 100 n \) steps. Look at both parts:

\( n \)\( n^2 \)\( 100 n \)Share of \( 100 n \)
10100100091%
1000\( 10^6 \)\( 10^5 \)9%
\( 10^5 \)\( 10^{10} \)\( 10^7 \)0.1%

For small \( n \) the small part matters. But the judge tests the biggest \( n \). There the biggest part is almost everything. So \( n^2 + 100 n \) is \( O(n^2) \).

Numbers in front are dropped too. \( 3 n \) and \( n \) are both \( O(n) \). This is a safe estimate, not an exact law: two \( O(n) \) codes can differ 10 times in time.

From cost to verdict

The judge does about \( 10^8 \) simple steps in one second. This is a safe estimate, not an exact law.

  1. Find the biggest \( n \) in the limits.
  2. Put it into your \( O(\dots) \).
  3. About \( 10^8 \) or less per second of time limit: it passes. \( 10^9 \) or more: too slow.

Example. \( n \le 10^5 \) and the time limit is 1 second.

  • Your code is \( O(n \log n) \): \( 10^5 \cdot 17 \approx 1.7 \cdot 10^6 \). Far below \( 10^8 \). It passes.
  • Your code is \( O(n^2) \): \( 10^{10} \) steps, about 100 seconds. "Time limit exceeded".

Here \( \log 10^5 \approx 17 \): you halve \( 10^5 \) about 17 times to reach 1. The next lesson turns this around: from the limits to the speed you need.

Many test cases

With \( t \) test cases, the cost of solve() is paid once per test. Add the costs of all tests.

The statement says "the sum of \( n \) over all test cases is at most \( 2 \cdot 10^5 \)". Put that sum into your \( O(\dots) \). An \( O(n) \) solve() then does about \( 2 \cdot 10^5 \) steps in total.

The classic trap: work that does not depend on \( n \) runs in every test.


// inside solve(): the numbers are at most 10^6
vector<int> cnt(1000001, 0);     // 10^6 steps in EVERY test

With \( t = 10^4 \) tests that is \( 10^4 \cdot 10^6 = 10^{10} \) steps, even if every \( n \) is tiny. The fix: make the work of each test depend on its \( n \) only. If the numbers are at most \( n \), write vector<int> cnt(n + 1, 0);. The same trap is a big global array cleared fully in each test.

Solve one together

Problem. A friend wrote the code below. It reads \( n \) numbers and a number \( k \). It counts the pairs of numbers that differ by at most \( k \). Limits: \( 1 \le n \le 5000 \), numbers and \( k \) from 0 to \( 10^9 \), time limit 1 second. Will it pass?

  1. What is asked? The cost of this code for the biggest \( n \), and a verdict. sort puts the numbers in order, from small to big. 
    
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];   // part 1

    sort(a.begin(), a.end());                  // part 2

    long long pairs = 0;
    for (int i = 0; i < n; i++)                // part 3
        for (int j = i + 1; j < n; j++) {
            if (a[j] - a[i] > k) break;        // the next ones are even bigger
            pairs++;
        }
    cout << pairs << "\n";
}
  2. A small example by hand. Input 4 1 / 3 1 10 2. After sort: 1 2 3 10. Count the checks of part 3:
    icheckswhy it stops
    0 (value 1)2\( 3 - 1 = 2 > 1 \): break
    1 (value 2)2\( 10 - 2 > 1 \): break
    2 (value 3)1\( 10 - 3 > 1 \): break
    The answer is 2 pairs: (1, 2) and (2, 3).
  3. The idea. Cost each part, then add.
    • Part 1: one loop, \( O(n) \).
    • Part 2: sort, \( O(n \log n) \).
    • Part 3: the break can stop early. But in the worst case, all numbers are equal and the break never happens. Then it checks every pair: about \( n^2 / 2 \), so \( O(n^2) \).
    Keep the bigger part: the whole code is \( O(n^2) \).
  4. Why is it fast enough? Put in \( n = 5000 \): \[ 5000 + 5000 \cdot 12 + \frac{5000 \cdot 4999}{2} \approx 1.3 \cdot 10^7 \] Here \( \log 5000 \approx 12 \). The total is below \( 10^8 \). It passes. With \( n \le 2 \cdot 10^5 \) part 3 alone is \( 2 \cdot 10^{10} \) steps: "Time limit exceeded".

Rule: nested loops multiply, loops in a row add. Keep the biggest part. Then put in the biggest \( n \).

Practice: what does this code cost?

For each code: count the steps for a big \( n \), then write its \( O(\dots) \). They go from easy to tricky.

  1. 
for (int i = 0; i < n; i++) cin >> a[i];
for (int i = 0; i < n; i++) sum += a[i];
    Cost

    \( O(n) \). Loops one after another add: \( n + n = 2n \).

  2. 
for (int i = 0; i < n; i++)
    for (int j = 0; j < 5; j++) total += a[i] * j;
    Cost

    \( O(n) \). The inner loop always runs 5 times, for any \( n \). That is \( 5n \) steps.

  3. 
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        if (a[i] + a[j] == x) found = true;
    Cost

    \( O(n^2) \). For \( n = 1000 \): \( 10^6 \) steps.

  4. 
for (int i = 0; i < n; i++)
    for (int j = 0; j < i; j++)
        if (a[j] > a[i]) bigger++;
    Cost

    \( O(n^2) \). About \( n^2 / 2 \) steps: 499 500 for \( n = 1000 \).

  5. 
int cnt = 0;
for (int i = 1; i < n; i *= 2) cnt++;
    Cost

    \( O(\log n) \). i doubles each round. For \( n = 10^9 \): 30 rounds.

  6. 
for (int i = 0; i < n; i++)
    for (int j = 0; j < m; j++) cin >> g[i][j];
    Cost

    \( O(n \cdot m) \), not \( O(n^2) \). For \( n = 1000 \), \( m = 2000 \): \( 2 \cdot 10^6 \) steps.

  7. 
int pos = -1;
for (int i = 0; i < n; i++)
    if (a[i] == x) { pos = i; break; }
    Cost

    \( O(n) \). The break can stop early. In the worst case x is not there, and the loop does all \( n \) rounds.

  8. 
int cnt = 0;                          // s has length n
for (int i = 0; i < n; i++)
    if (s.substr(i) == t) cnt++;
    Cost

    \( O(n^2) \). s.substr(i) copies \( n - i \) letters each round. For \( n = 10^5 \): about \( 5 \cdot 10^9 \) steps.

  9. 
for (int q = 0; q < n; q++) {
    sort(a.begin(), a.end());         // a has n numbers
    cout << a[q] << "\n";
}
    Cost

    \( O(n \cdot n \log n) \). A sort of \( n \log n \) steps runs \( n \) times. Sort once, before the loop: then it is \( O(n \log n) \).

Wrong ideas people get

  • You may think: More lines of code means a slower program.

    The truth: What matters is how many times each line runs, not how many lines there are. Three lines with a hidden substr can be slower than 30 lines with no loop.

  • You may think: Two loops always mean \( n^2 \).

    The truth: Two loops one after another add: \( n + n \). Nested loops over two different sizes give \( n \cdot m \), not \( n \cdot n \).

  • You may think: An \( O(n) \) solution is always fast enough.

    The truth: Not when \( n \) can be \( 10^{12} \). Not when the \( O(n) \) work runs again for each of \( q \) questions. That is \( O(n \cdot q) \).

  • You may think: Big-O tells me the exact running time.

    The truth: It drops the numbers in front, so two \( O(n) \) codes can differ 10 times. Near \( 10^8 \) steps, be careful. Far from it, Big-O decides.

Check yourself

  1. \( n \le 10^6 \) and your code is \( O(n \log n) \). Does it pass in 1 second?
    Answer

    Yes. \( \log 10^6 \approx 20 \), so about \( 2 \cdot 10^7 \) steps. That is below \( 10^8 \).

  2. There are \( t \le 10^4 \) tests and the sum of \( n \) is at most \( 2 \cdot 10^5 \). Each test makes a vector of size \( 10^6 \). About how many steps?
    Answer

    About \( 10^4 \cdot 10^6 = 10^{10} \). Too slow. Make the work of each test depend on its \( n \). If the values are at most \( n \), use a vector of size \( n + 1 \). If not, keep one global array and clear only the cells this test used.

  3. Does int a[20000][20000] fit in a memory limit of 256 MB?
    Answer

    No. \( 4 \cdot 10^8 \) values of 4 bytes are \( 1.6 \cdot 10^9 \) bytes: about 1600 MB.
