== safety | s0 | Overflow and other traps
-- overflow | Quick size check before you choose a type: multiply or add the biggest values from the limits.
$$of_1: 10^5 \cdot 10^5 = 10^{10}$$ → {{: long long}}
$$of_2: 2 \cdot 10^5 \cdot 10^9 = 2 \cdot 10^{14}$$ → {{: long long}}
$$of_3: 10^9 \cdot 10^9 = 10^{18}$$ → {{: long long}}, it fits
$$of_4: 10^9 \cdot 10^9 \cdot 10^9$$ → too big, use % or divide
-- overflow | Two ints are multiplied as int, and the result is already broken before it is stored. Put 1LL first so the product is computed as long long.
wrong: {{of_bad: long long p = a * b}}
right: {{of_good: long long p = 1LL * a * b}}
in a loop test: {{of_loop: 1LL * i * i <= n}}
-- overflow | Compare a product with a limit when the product itself can overflow: divide the limit. For a >= 0, b > 0, c >= 0.
{{: a * b > c}} → {{cmp_gt: a > c / b}}
{{: a * b <= c}} → {{cmp_le: a <= c / b}}
{{: a * b >= c}} → {{cmp_ge: a >= c / b + (c % b != 0)}}
-- overflow | Will a + b pass the long long maximum? Test it with a subtraction, which cannot overflow. For b >= 0.
a + b is too big: {{add_of: a > LLONG_MAX - b}}
-- overflow | The biggest and smallest values of int and long long, as ready names.
{{c_intmax: INT_MAX}} = {{: 2147483647}}
{{c_intmin: INT_MIN}} = {{: -2147483648}}
{{c_llmax: LLONG_MAX}} = {{: 9223372036854775807}}
{{c_llmin: LLONG_MIN}}
-- overflow | A value that means infinity. Do not use INT_MAX or LLONG_MAX for it: adding anything to them overflows. These two leave room for one addition.
for int: {{inf_int: const int INF = 1e9}}
for long long: {{inf_ll: const long long INF = 1e18}}
-- debugging | size() has no sign. For an empty vector, a.size() - 1 is not -1 but a huge number, and the loop runs into memory it must not touch. Cast to int first.
wrong: {{sz_bad: a.size() - 1}}
right: {{sz_good: (int)a.size() - 1}}
loop: {{sz_loop: for (int i = 0; i + 1 < (int)a.size(); i++)}}
-- binary-search | The middle of lo and hi. For 0 <= lo <= hi the first form never overflows. The second overflows when lo + hi is too big.
safe: {{mid_safe: lo + (hi - lo) / 2}}
can overflow: {{mid_bad: (lo + hi) / 2}}
-- overflow | A double holds every integer exactly only up to 2^53, about 9·10^15. Above that, digits are lost. Keep big integers in long long.
$$dbl_53: 2^{53} \approx 9 \cdot 10^{15}$$
$$: x = 10^{18}$$: {{dbl_lost: (double)(x + 1) == (double)x}} is {{: true}}
-- bits | A shift of the int 1 breaks at k = 31. Make the 1 a long long.
wrong for $$: k \ge 31$$: {{: 1 << k}}
right for $$: k \le 62$$: {{sh_good: 1LL << k}}

not an element: {{: a[n]}}
